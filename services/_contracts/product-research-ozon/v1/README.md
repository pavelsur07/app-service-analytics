# product-research-ozon v1

Symfony → Python, Bearer направления PHP → Python, только internal сеть.
Обратный токен зарезервирован для Python → PHP и не принимается здесь.
MPStats-токен никогда не участвует в контракте. Вход пользователя только PHP;
синхронных вызовов из пользовательского HTTP нет (ADR-050).

Корень `/internal/v1/companies/{company_id}`. UUID — канонические UUIDv7.
Вложенные схемы в schema.json — единственный источник форматов; examples.json
содержит общий corpus положительных и отрицательных примеров PHP/Python.
Валидируется выбранный `$defs`, а не случайная другая ветка корневого oneOf.

| HTTP | Суффикс | Запрос/ответ ($defs) |
|---|---|---|
| GET | /categories?limit=1..100&cursor=opaque | categories_request / categories_response |
| POST | /runs | run_request / run_accepted (202 после commit) |
| GET | /runs/{run_id} | run_progress |
| GET | /snapshots/{snapshot_id} | snapshot_metadata |

Каталог читается страницами по стабильному snapshot revision; cursor привязан
к компании/ревизии и не является URL или S3-ключом. Протухший cursor — conflict,
следует начать синхронизацию заново. Пустая items допустима только после
получения каталога; до этого not_available. Keyset и механизм подписания cursor
реализуются вместе с каталогом в этапе 3.

company_id обязателен в пути и данных; в POST обязан совпадать. FBS только true,
RUB, до 24 уникальных календарных месяцев. Семантические правила (согласование
дат, days, future/current months и дедупликация) проверяет приложение; одной
JSON Schema для них недостаточно. Полные месяцы не режутся. Сроки фиксирует PHP
до отправки. Реальная обработка периодов — этапы 2/4.

(company_id, run_id) — ключ идемпотентности, повтор другого тела — conflict.
revision монотонна внутри запуска. row_count null означает «ещё не известно»,
а ноль — проверенный пустой результат. ready допускается только после
проверки снимка. Метаданные не включают сырые строки, суммы и объектные ключи.
Сверка известных запусков делает GET каждого run_id ограниченными пачками;
межарендаторного списка и неограниченной выгрузки нет.

Ошибки: `error`, без подробностей запроса. unauthorized=401,
contract_violation=422, payload_too_large=413 (максимум 65536 байт),
request_timeout=408 (5 секунд на чтение тела), not_ready/not_available=503, not_found=404, method_not_allowed=405, conflict=409, internal_error=500.
Неизвестные поля запрещены. Внутренние запросы сначала авторизуются, затем
разбираются. Каждому HTTP-ответу добавляется новый X-Trace-Id UUIDv7; внешний
идентификатор не копируется в журнал.

**Этап 1:** операции существуют как защищённые точки контракта и отвечают
not_available вместо фиктивных успешных данных. Ни run_accepted, ни готовые
снимки пока не выдаются. /ready проверяет инфраструктуру, collection_enabled=false.
Нормативные успешные форматы зафиксированы для независимой реализации сторон
в следующих этапах. Не меняем опубликованный v1 без новой версии.
