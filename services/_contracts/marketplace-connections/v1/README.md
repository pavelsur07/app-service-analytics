# marketplace-connections v1

Ответ внутреннего endpoint'а PHP `GET /api/internal/marketplace-connections`
(сервисный контур, CLAUDE.md §1, ADR-043 п. 4). Сервисы `services/` опрашивают
его и работают автономно (`services/AGENTS.md` §2). Schema:
[schema.json](schema.json), эталонная страница: [example.json](example.json),
история: [CHANGELOG.md](CHANGELOG.md).

Статус: **проект** до реализации endpoint'а в PHP (этап 4 плана
`docs/plan/ozon-fetcher.md`). Изменения v1 допустимы до первого потребителя
на проде; после — только через v2.

## Запрос

`GET /api/internal/marketplace-connections?provider=ozon&limit=200&cursor=<курсор>`,
заголовок `Authorization: Bearer <токен «сервис → PHP»>`.

- `provider` — только `ozon`; другой — 422.
- `limit` — по умолчанию 50, максимум 200, больше — 422 (CLAUDE.md §5).
- `cursor` — `next_cursor` предыдущей страницы; без него — первая страница.
- 401 — нет токена или токен другого направления. Снаружи endpoint
  недоступен: публичные vhost отвечают 404 на `/api/internal/`.

## Семантика

- Отдаются только **активные** подключения Ozon; keyset-пагинация по
  `marketplace_account_id`, порядок страницы — по нему же.
- `next_cursor` — непрозрачная строка; `null` — страница последняя.
  Сервис собирает все страницы и заменяет кэш только целиком собранным
  списком; сбой любой страницы, курсор, который не продвинулся, или страница
  больше лимита — отказ всего обхода, кэш не меняется.
- **Подключение, которого нет в успешно собранной выдаче, теряет ключи**
  у сервиса: так отзыв и перевод в `broken` доходят до сервиса за один
  интервал опроса.
- Ключи сгруппированы по типу, не по ресурсу:
  - `seller` — Client-Id + Api-Key (`api-seller.ozon.ru`);
  - `performance` — client_id + client_secret → OAuth-токен
    (`api-performance.ozon.ru`).
  Тип равен `null` — ключа нет, задачи на его ресурсы не ставятся.
  Подключение без пригодных ключей в выдачу не попадает.
- `resource_types` — выводимое поле (ресурсы, доступные с имеющимися
  ключами), не источник истины.
- `updated_at` — последнее изменение подключения или ключей: после 401
  Ozon сервис ждёт нового значения, а не повторяет запросы со старым ключом.
- Ключи у сервиса живут только в памяти: не попадают в его БД, журнал,
  трекер и фикстуры. В журнале PHP — строка аудита без ключей и тела ответа.
