# ozon-fetcher — правила сервиса

Загрузка raw Ozon Seller API и Performance API по активным подключениям
Conwix: raw — в бакет сырья Conwix под префиксом `conwix/svc/ozon-fetcher/v1/`
(ADR-044), журнал загрузок — в свою БД (ADR-043).
План работ — `docs/plan/ozon-fetcher.md`. Общие правила — `services/AGENTS.md`
и `services/go.md`; этот файл их уточняет для каталога и не отменяет.

## Стек

- Go 1.27 (пин в `go.mod`); раскладка, паттерны, принятые зависимости
  и гейты — `services/go.md`.
- `cmd/ozon-fetcher/` — только wiring; логика — в `internal/`.
- Гейты: `make ozon-fetcher-lint`, `make ozon-fetcher-vet`,
  `make ozon-fetcher-test`, `make ozon-fetcher-vulncheck`.

## Границы ответственности

Делает: получает активные подключения и ключи из PHP
(`marketplace-connections` v1), ходит в Ozon по нескольким подключениям
параллельно с лимитом на каждое, обходит страницы по курсору, повторяет
на 429 с backoff, пишет raw без перезаписи, ведёт журнал и догружает пропуски.

Не делает (`services/AGENTS.md` §1): не пишет в БД и очереди PHP, не
нормализует данные в факты, не решает об идемпотентности по состоянию БД PHP.

## Подключение и изоляция

- Подключение — пара `company_id` + `marketplace_account_id` (`internal/account`,
  `account.Ref`). Функции, работающие с данными подключения, принимают его
  первым параметром после `ctx`; ключи таблиц и ключ объекта начинаются
  с компании (`services/AGENTS.md` §4).
- Межарендаторно работают только операционные функции `store`, и это видно
  из имени (`…AcrossConnections`, `…AllConnections`): выдача задач
  диспетчеру, постановка задач планировщиком, сборщик просроченных lease,
  остановка снятого ресурса, загрузка лимитов при старте, отчёты
  `/internal/fetch-status` и `/internal/coverage`. У каждой —
  ссылка на CLAUDE.md §1 в докблоке; новая такая функция — только с тем же
  именем и ссылкой.

## Хранение

- Своя БД `ozon_fetcher` (роль `svc_ozon_fetcher`) — только техническое
  состояние. Одна стартовая миграция с рабочим `down`; новые идентификаторы —
  UUIDv7 (`internal/uuidv7`).
- Raw immutable — новый объект на каждую загрузку, sha256 и размер
  в `raw_object`.

## Специфика Ozon

- Ресурсы, формы запросов, классы ответов и стартовые лимиты —
  `docs/ozon-api.md`.
- Лимит — на пару (подключение, endpoint): старт из дефолтов, ручное
  значение в `connection_limit`, адаптация на 429 (`Retry-After`).
- Ключи подключений — только в памяти; в коде, журнале, БД и фикстурах —
  никогда. В песочнице сервис ходит в мок (`test/stand/mock`), реального
  кабинета не касается.

## Тесты

- Table-driven + `testify`; фикстуры — по `services/AGENTS.md` §9.
- Конкурентность (лимитер, захват задач, диспетчер) — с `-race`.
- Контракт выдачи подключений проверяется по `schema.json` в тесте.
