# services/go.md — правила Go-сервисов

Распространяется на все `.go`-файлы под `services/` (`services/**/*.go`). Иерархия: `CLAUDE.md` и корневой
`AGENTS.md` → `services/AGENTS.md` → этот файл → `services/<name>/AGENTS.md`.
Перенесено из ВашФинДир с адаптацией к правилам Conwix.

## Тулчейн

- Go **1.27**, пин в `go.mod` (`go 1.27`). Версия зафиксирована явно,
  как всё в проекте; подъём — плановая задача после выхода из поддержки
  прежней (endoflife.date/go), не автоматический.
- Дев-инструменты — директива `tool` в `go.mod`, не глобальные установки.
- Всё запускается через цели Makefile в контейнерах, не на хосте.

## Раскладка

```text
services/<name>/
├── cmd/<name>/main.go      только wiring: config → клиенты → воркеры/сервер; graceful shutdown
├── internal/
│   ├── config/             env + валидация, отказ при старте
│   ├── <provider>/         клиент внешнего API: auth, лимит, курсор, классы ошибок
│   ├── store/              БД сервиса, миграции (embed)
│   ├── rawstore/           объектное хранилище
│   └── observability/      slog, Sentry
├── test/                   интеграционные вне internal
├── .golangci.yml
├── go.mod / go.sum
└── docker/Dockerfile
```

Начинать плоско; новый пакет — когда у него появились своя граница и свои
инварианты. `pkg/` не создавать: сервисы — не библиотеки. Golden-файлы —
рядом с тестами в `testdata/`. Каталоги с `_` и `.` go tool игнорирует:
в `_contracts/` Go-кода нет.

## Пакеты и зависимости между ними

- Однонаправленно, `main` → всё. Пакет не импортирует соседей через один.
- Интерфейсы — у потребителя, на границах подмены (HTTP-клиент, часы,
  генератор идентификаторов); моки — ручные фейки в тестах.
- DI — вручную в `cmd/<name>/main.go`. `wire`, `fx` не используются.

## Внешние зависимости

**Новая зависимость — пункт согласования плана** (CLAUDE.md «Единственная
точка согласования»), как на бэкенде и фронтенде. stdlib-first: внешний
модуль — когда он осмысленно лучше 30–50 строк своего кода.

**Принятый стек** — прямые зависимости `go.mod` на коммите-источнике
(ADR-043), перечисленные здесь поимённо. Модуль не из этой таблицы —
пункт согласования, даже если он лежит в `go.mod` источника:

| Задача | Модуль |
|---|---|
| PostgreSQL | `jackc/pgx/v5` (pgxpool, 2–5 соединений, `statement_timeout`, `lock_timeout`) |
| Миграции | `pressly/goose/v3` с `embed.FS` |
| S3 | `aws-sdk-go-v2` (S3-совместимые провайдеры, endpoint и region из env) |
| Лимитер | `golang.org/x/time/rate` |
| Трекер | `getsentry/sentry-go` (GlitchTip) |
| Тесты | `stretchr/testify`, `go.uber.org/goleak` |
| Проверка контракта по JSON Schema — только в тестах | `santhosh-tekuri/jsonschema/v6` (согласовано 24.10.2026, этап 1) |

`aws/smithy-go` — прямая зависимость из семейства `aws-sdk-go-v2`
(типы ошибок S3), отдельным выбором не является.

Транзитивные модули источника (`golang.org/x/sync` и другие) прямыми
зависимостями не становятся без согласования; `errgroup` — после него.
UUIDv7 — свой код (`internal/uuidv7`, RFC 9562), без модуля: решение
владельца 24.10.2026. В рабочем коде ответ выдачи подключений проверяется
строгим разбором, валидатор схемы в бинарник не попадает.

`go.sum` коммитится; версии зафиксированы, обновление — плановая задача.

**Чего не берём:** ORM (`gorm`, `ent`) — SQL пишется явно, как DBAL
в PHP; `shopspring/decimal` — деньги сервис не вычисляет
(`services/AGENTS.md` §6); `viper` — env читается stdlib; DI-фреймворки.

## Паттерны

- `context` — первым аргументом на всю глубину; дедлайн на каждый внешний
  вызов; отмена по сигналу — в `main`.
- Fan-out — ограниченный пул горутин (`errgroup` — после согласования,
  см. «Внешние зависимости»); утечек горутин нет
  (`goleak` в тестах).
- Ошибки: `%w` с префиксом пакета; sentinel + `errors.Is/As`;
  `errors.Join` для агрегации. Без `log.Fatal` и `panic` вне `main`.
- **Долгое ожидание не держит слот:** неготовый отчёт и пауза кабинета
  по `Retry-After` — перенос задачи на `next_run_at`. Короткое ожидание
  лимитера между запросами одного кабинета допустимо: оно идёт в горутине
  этого кабинета и другие кабинеты не задерживает.
- Повтор — экспоненциальный backoff с jitter; класс ошибки определяет
  реакцию (`services/AGENTS.md`, README сервиса).
- Часы и генераторы идентификаторов — параметры, не `time.Now()` в глубине:
  повтор и тесты детерминированы.
- Graceful shutdown: `signal.NotifyContext` + `http.Server.Shutdown`.
- HTTP: stdlib `http.ServeMux` с паттернами; middleware — замыкания.
- Сравнение токенов — `crypto/subtle.ConstantTimeCompare`.

## Деньги и числа

Денег в первой волне нет (`services/AGENTS.md` §6), денежного пакета
тоже. `float64` допустим для нерасчётных величин — скорость лимитера
в запросах в секунду. Появится денежный код — `float32`/`float64` в нём
запрещается линтером (`forbidigo` по пакету) в том же изменении.

## Конфиг и секреты

- Только env, проверка при старте: отсутствие обязательного — отказ
  запуска, не умолчание.
- Имена переменных — в README сервиса; значения — никогда в git и журнале.

## Тесты

- Table-driven + `testify`; фикстуры — `services/AGENTS.md` §9.
- Нативный fuzzing для разбора курсоров и сборки ключей хранилища.
- `-race` обязателен. Порог покрытия в CI — стартово 70%, только растёт.
- Интеграционные — против dev-БД и SeaweedFS песочницы; без переменной
  окружения с адресом тест пропускается явно, CI переменные задаёт.

## Гейты (make и CI)

Порядок: fmt → vet → lint → test; красный гейт останавливает конвейер
и блокирует merge (CLAUDE.md «Проверки CI»).

- `make <name>-lint` — golangci-lint v2, `.golangci.yml`, проверка
  форматирования.
- `make <name>-vet` — `go vet ./...`.
- `make <name>-test` — `go test -race ./...`. `-race` требует cgo:
  контейнер тестов — `golang:1.27` (debian), `CGO_ENABLED=1`.
- CI дополнительно: `govulncheck` (пин версии), `go build -trimpath`.

## Docker

- Multi-stage: сборка в `golang:1.27-alpine` → рантайм `distroless/static`
  или `alpine`, non-root; `-trimpath -ldflags="-s -w"`. Базовые образы —
  с точным тегом.
- `.dockerignore` в контексте сервиса; healthcheck — `GET /health`.

## Монорепо

- Свой `go.mod` у каждого сервиса. Общего Go-модуля нет, пока сервис один;
  появится второй и общий код — решение отдельной задачей.
