# Правила Python-сервисов Conwix

Основание — ADR-050. Общие инварианты CLAUDE.md и services/AGENTS.md обязательны.
Это правила Python для product-research-ozon; исключения Go сюда не переносятся.

- CPython 3.14.10, Linux x86_64. Образ закреплён digest в
  `product-research-ozon/stage0/python-image.txt`; полный граф пакетов с hashes —
  `stage0/requirements.lock`. Другую платформу проверять и закреплять отдельно.
- Установка, Python, pip, тесты и анализ запускаются в контейнере через Make.
  Host Python стандартной библиотеки допустим для утилит процесса разработки.
- Типы strict: mypy --strict; явный Any не используется. Dynamic JSON только
  на внешней границе, затем проверенные DTO. Cast сам по себе не валидатор
  входа. Ruff check/format обязательны, исключения ради зелёного результата нет.
- Чистая логика не импортирует FastAPI/HTTP/БД. Контроллеры — тонкие,
  jobs оркестрирует, collection работает с MPStats, snapshots — с публикацией
  снимков; технические реализации — infrastructure. Нет общего context-dict.
- SQL явный, Psycopg binary; runtime ORM нет. SQLAlchemy Core только в Alembic.
  Company-scoped методы принимают company_id первым параметром; фоновые
  межарендаторные диспетчеры названы явно. Доступа к БД монолита нет.
- Списки ограничены; растущие журналы — keyset. Нет запросов в цикле и COUNT
  по фактам. UUIDv7 генерируется приложением, хранится нативным uuid.
- Денежные JSON-числа читаются через Decimal, деньги — целые минорные единицы
  с валютой. Float в денежных промежуточных вычислениях запрещён. Для исходных
  байтов сырья числовое представление не меняется.
- datetime событий — aware UTC; календарь проекта — Europe/Moscow. Это политика
  Conwix, не доказанная timezone внутренних расчётов провайдера.
- DB uniqueness, аренда и fencing защищают повтор/конкуренцию. Фиксируются
  параметры запуска, next_attempt_at и deadline. Уникальность не заменяется
  предварительным SELECT. API-запросы имеют timeout/ограничение объёма.
- Alembic-миграции включены в образ, запуск явной Make-командой, не при старте.
  Одна итоговая на задачу; down либо описанное восстановление. Проверка текущей
  ревизии и rebuild с чистой локальной БД обязательны до выкладки схемы.
- Unit без инфраструктуры, integration с PostgreSQL/S3, contract на обеих
  сторонах PHP/Python. В автоматических тестах нет live MPStats. Фикстуры —
  по CLAUDE.md §9, checksum и provenance обязательны; архивы читаются без
  произвольного extractall. Нельзя заменять несовпадение значений округлением.
- Логи — идентификаторы, статусы, счётчики, trace_id, длительность. Без секретов,
  сумм, тел MPStats, ПДн. Токен только в заголовке, не URL. Нет публичного route.

Этап 0: `make product-research-ozon-stage0-check` устанавливает hash-lock,
проверяет imports/pip check/audit, затем с отключённой сетью запускает
Ruff, mypy strict и офлайн-тесты эталонов. Результаты — в var, не исходники.

Этап 1 добавляет отдельные lint/vet/architecture/test/audit/migrate/
migrations-check цели, CI и настоящие integration-тесты. Этап 0
не считается доказательством готовности worker, HTTP API или БД сервиса.
