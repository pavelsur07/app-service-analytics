# services/AGENTS.md — правила сервисов вне монолита

Распространяется на всё дерево `services/`. Иерархия: `CLAUDE.md` и корневой
`AGENTS.md` → этот файл → `services/go.md` → `services/<name>/AGENTS.md`.
Ближайший к файлу уточняет, но не отменяет: **инварианты** `CLAUDE.md`
(изоляция, идентификаторы, деньги, идемпотентность, лимиты списков,
миграции, фикстуры, обязательное покрытие) действуют в сервисах полностью.
**Механизмы монолита** — Deptrac, PHPStan, Doctrine ORM и DBAL,
`QueryBuilder`, readonly DTO, Builder, Messenger, `symfony/uid` — в сервисах
не применяются; этот файл говорит, чем каждый инвариант исполняется там.
Инвариант без названной здесь замены — пробел правил, а не разрешение.

Основание — ADR-043. Модель и код перенесены из ВашФинДир
(`app-service-finance`, `services/`); где правила ВашФинДир расходятся
с Conwix, действуют правила Conwix, и расхождения перечислены в §11.

| Документ | Что содержит | Когда читать |
|---|---|---|
| `services/go.md` | Go: раскладка, паттерны, зависимости, гейты, Docker | код в `services/*/*.go` |
| `services/<name>/AGENTS.md` | специфика сервиса: провайдер, ресурсы, запуск | работа внутри сервиса |
| `services/_contracts/` | контракты между сервисом и PHP | любой обмен данными с PHP |
| ADR-043 | границы сервиса, сервисный контур, первая волна | новый сервис, изменение границ |

## 1. Границы

Сервис ingestion в первой волне ADR-043:

- **не читает и не пишет БД Conwix** — ни таблиц, ни представлений;
- не разбирает ответы площадки в факты, не пишет факт-таблицы, не ставит
  отметку загрузки дня, не меняет состояние подключения
  (`active`/`broken`/`revoked` — правило ADR-007 остаётся в PHP);
- не вычисляет деньги (§6);
- не отдаёт UI и не публикуется наружу: фронтенд говорит только с PHP API.

Расширение границ — новый ADR, не правка этого файла.

## 2. Взаимодействие с PHP

- **Конфигурация и ключи** — поллинг `GET /api/internal/marketplace-connections`
  (контракт `marketplace-connections` v1, сервисный контур, CLAUDE.md §1),
  постранично; кэш только в памяти и заменяется только целиком собранным
  списком. Значения ключей никогда не попадают в БД сервиса, логи, трекер,
  фикстуры.
- **Отзыв доходит до сервиса** (ADR-043 п. 4): подключение, которого нет
  в успешно собранной выдаче, сразу теряет ключи и задачи. Кэш без
  подтверждения живёт не дольше `CONNECTIONS_MAX_STALE` (30 минут), затем
  все задачи останавливаются до успешной выдачи. 401 площадки — одно
  обновление и один повтор, затем пауза кабинета до новых ключей.
- **Токены — по направлению:** «сервис → PHP» и «PHP → сервис» разные,
  не короче 32 символов, только из секретов окружения. Ротация — одной
  выкладкой.
- **Сеть:** только docker-сеть `internal`, к площадке — `egress`.
  Роутера Traefik у сервиса нет.
- **Стандартные endpoint'ы сервиса:** `GET /health`, `GET /ready`
  (БД, хранилище), `/internal/*` под токеном «PHP → сервис». Ответы
  `/internal/*` содержат идентификаторы, статусы и счётчики — не ключи,
  не тела ответов площадки, не суммы.
- Синхронного вызова сервиса из пользовательского запроса PHP нет.

## 3. Контракты

- Единственный источник — `services/_contracts/<имя>/v<N>/` со `schema.json`
  и `CHANGELOG.md`.
- Опубликованная версия неизменна: изменение полей или семантики — новая
  версия; производитель и потребитель переходят независимо.
- Обе стороны проверяют сообщения по схеме **тестом**: PHP — свой ответ,
  Go — разбор эталонного ответа. Ручное расхождение с контрактом — дефект.
- Ответ, не прошедший схему, — ошибка `contract_violation`, а не тихо
  принятые данные.

## 4. Изоляция арендаторов в сервисе

Сервис по природе межарендаторный: он обслуживает подключения всех
компаний (операционная задача, CLAUDE.md §1, обоснование — ADR-043).
Deptrac этого не видит, поэтому правило исполняется так:

- **ключ объекта хранилища начинается с компании**:
  `{provider}/{company_id}/{marketplace_account_id}/…`. `company_id`
  и подключение берутся из одной записи выдачи подключений, сегменты
  проверяются при сборке ключа; ключ не принимается готовым извне;
- каждая функция, работающая с данными подключения, принимает
  `companyID`, `accountID` первыми параметрами после `ctx`;
- ключи подключения не покидают обработку этого подключения: нет общего
  кэша страниц, ответов или токенов между подключениями;
- **обязательный тест**: объект одной компании не записывается под
  префикс другой; задача одного подключения не выполняется ключами
  другого.

## 5. Хранение

**БД сервиса.**

- Отдельная логическая БД на общем инстансе PostgreSQL, одна роль
  на сервис (`svc_<name>`) с правами только на неё. Доступа к БД Conwix
  у роли нет — это проверяемый признак границы §1.
- Только техническое состояние: задачи, попытки, объекты, лимиты,
  курсоры. Без денег, ключей, тел ответов, ПДн.
- Идентификаторы — UUIDv7, генерация в сервисе, тип `uuid`; ссылки
  на Conwix — `company_id`, `marketplace_account_id` тем же типом.
- Индекс следует за запросом (CLAUDE.md §1): диспетчер выбирает задачи
  по всем компаниям — ведущий столбец там статус и время; чтения одного
  подключения — `company_id` первым.
- **Миграции** — в каталоге сервиса, встроены в бинарник, прогон явной
  командой (`make <name>-migrate`), не при старте. Как в CLAUDE.md
  «Миграции»: одна миграция на задачу, рабочий `down` либо пометка
  «откат только восстановлением», проверка с пустой базы входит
  в `make db-rebuild-check`.
- **Гейт выкладки:** выкладка проверяет командой бинарника, что миграции
  сервиса применены, и при неприменённых останавливается до запуска
  контейнера сервиса — аналог `doctrine:migrations:up-to-date`, который
  миграций сервиса не видит. Применяет агент отдельным шагом
  (`<name> -migrate` на сервере), затем повторяет выкладку.
  Автоматического применения внутри выкладки нет (CLAUDE.md «Миграции»).

**Чтение** (CLAUDE.md §5 без механизмов монолита).

- SQL пишется явно (`pgx`), без ORM; выбираются только нужные колонки,
  результат — в структуру с полями, не `map[string]any`.
- **Любой список — с лимитом**, в том числе внутренний: выдача задач
  диспетчеру, ответы `/internal/*`. Растущие таблицы (попытки, объекты) —
  keyset-пагинация.
- `COUNT(*)` по журналу попыток и объектов не выполняется; счётчики
  покрытия — агрегатом по задачам в ограниченном окне дат.
- Запросов в цикле нет: связанное — одним запросом по списку
  идентификаторов.

**Хранилище.**

- Свой бакет на сервис, отдельный пользователь хранилища с правами
  только на него. Бакет сырья PHP (ADR-024) сервисам не выдаётся.
- Объекты неизменяемы, запись `If-None-Match: *`; новая загрузка — новый
  объект. sha256 и размер — в журнале.
- Срок хранения — правилом жизненного цикла бакета (ADR-043: 90 дней).

## 6. Деньги

Сервисы первой волны денег не вычисляют: тела ответов хранятся как есть.
Если вычисление понадобится — ADR-004 без исключений (целые минорные
единицы и валюта, деление аллокацией с явным округлением), и это новый
пункт согласования. `float32`/`float64` в денежном коде запрещён
линтером (`services/go.md` «Деньги и числа»).

## 7. Идемпотентность и конкурентность

CLAUDE.md §4 действует целиком:

- защита — уникальный индекс и перехват конфликта; «найти, и если нет —
  записать» запрещено;
- захват задачи — `FOR UPDATE SKIP LOCKED` с арендой; истёкшая аренда
  возвращает задачу с сохранённым курсором;
- страница и курсор пишутся одной транзакцией;
- лимиты площадки — на подключение и endpoint, не глобальные
  (CLAUDE.md «Работа с данными маркетплейсов»).

## 8. Наблюдаемость

- Структурированный журнал JSON. Обязательные поля в каждой записи —
  через общий обработчик, не в каждом вызове: `service`, `company_id`,
  `marketplace_account_id`, `job_id`, `trace_id`, `resource_type`,
  `outcome`, `error_class`, `duration_ms`.
- **Запрещено в журнале и трекере:** ключи и токены, тела ответов, суммы,
  ПДн.
- Свой проект GlitchTip, только ERROR. Ожидаемые условия (`not_ready`,
  пауза лимита) — `warning` в журнал, не в трекер.
- Сбой телеметрии не прерывает загрузку.

## 9. Тесты

- Уровни — по зависимостям, как CLAUDE.md §9: без БД и хранилища — unit,
  с ними — интеграционные в `test/` или с явным пропуском без переменной
  окружения.
- **Фикстуры — по CLAUDE.md §9**: побайтовые ответы кабинета, те же, что
  в `api/tests/Fixtures/Marketplace/`, с теми же границами (ПДн
  покупателей, данные третьих лиц, второй клиент — обезличить).
- Обращения к площадке в тестах запрещены: `httptest.Server` или мок
  на фикстурах.
- **Обязательное покрытие:** изоляция (§4), идемпотентность записи
  страниц и захвата задач, лимитер (отказ одного подключения не тормозит
  другие), классы ошибок, отказ `/internal/*` без токена и с токеном
  другого направления, отсутствие ключей в журнале.

## 10. Запуск и выкладка

- Dev: compose-профиль `services`; площадка — мок, реальных ключей
  в песочнице нет (CLAUDE.md «Периметр»).
- Цели: `make <name>-build`, `-up`, `-test`, `-vet`, `-lint`, `-migrate`.
- Prod: образ в ghcr только с `master`; выкладка создаёт роль и БД
  и проверяет миграции (§5), применение — отдельным шагом агента;
  контейнер стартует только при
  `<NAME>_ENABLED=true`; включение по подключениям — allowlist.
- Откат — `<NAME>_ENABLED=false` и выкладка или `docker stop`: загрузка
  PHP от сервиса не зависит.

## 11. Отличия от ВашФинДир

Копии независимы; исправление, найденное в одной, переносится в другую
руками отдельной задачей. Коммит-источник — в README сервиса.

| Вопрос | ВашФинДир | Conwix |
|---|---|---|
| Идентификатор подключения | `connection_ref` | `company_id` + `marketplace_account_id` |
| Ключ объекта | `ozon/{connection_ref}/…` | `ozon/{company_id}/{marketplace_account_id}/…` |
| Фикстуры | обезличенные | побайтовые ответы кабинета (§9) |
| Миграции | forward-only, применяет выкладка | рабочий `down`, одна на задачу, `db-rebuild-check`; выкладка только проверяет |
| Выдача подключений | одним ответом, кэш без срока | keyset-пагинация; отсутствие в выдаче снимает ключи; кэш не дольше 30 минут |
| Деньги | десятичные строки, `shopspring/decimal` | не вычисляются; иначе ADR-004 |
| Новая зависимость | одна строка обоснования в PR | пункт согласования плана (CLAUDE.md) |
| Выдача фактов в PHP | контракт `source-fact-envelope` (проект) | вторая волна, отдельный ADR |
