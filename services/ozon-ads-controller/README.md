# ozon-ads-controller — observe, этапы 00–08/10/11

Основание: [ADR-052](../../docs/adr/0052-ozon-ads-cost-control.md).
Сервис читает CPC-расходы и сохраняет предполагаемые решения. Он не управляет
рекламой и не обеспечивает защиту бюджета. Исполнителя нет; интерфейс наблюдения выпущен на этапе10. `ADS_MODE=control` завершает запуск ошибкой, endpoint'ы изменения
рекламы не входят в allowlist последнего сетевого адаптера.

PHP владеет политиками, версиями, авторизацией и аудитом. Go владеет собственной
БД, арендой кабинета, расписанием чтений, качеством наблюдений и расчётом.
В БД Conwix Go не подключается. Последняя проекция доставляется в PHP отдельно;
её задержка не блокирует локальные сроки. История и Messenger в пути нет.

## Настройки

| Переменная | Назначение |
|---|---|
| ADS_DB_DSN | Собственная PostgreSQL БД; роль только этого сервиса |
| ADS_PHP_URL | Внутренний HTTP(S) адрес PHP, без query/userinfo |
| ADS_OUTBOUND_TOKEN | Сервис → PHP, существующий internal-service контур, минимум 32 символа |
| ADS_INBOUND_TOKEN | PHP → сервис, другой токен минимум 32 символа |
| ADS_ENABLED | Только `true` включает фоновые чтения; по умолчанию выключены |
| ADS_MODE | Только `observe`, по умолчанию observe |
| ADS_LISTEN | Внутренний listener, по умолчанию :8080 |
| ADS_WORKERS | 1–32 работника кабинетов, по умолчанию 4 |

Секреты только в env и памяти; не в Git, БД, журнале, метриках или fixtures.
Ozon URL фиксирован в wiring. Редиректы запрещены, запрос ≤10 с, цикл ≤45 с,
тело ≤8 MiB; ошибки не включают URL, тело ответа или ключи.
Транспорт Ads — собственный clone штатного `http.Transport`, только HTTP/1,
новое соединение на каждую явную отправку. Это исключает скрытый повтор GET
на использованном соединении без нового резерва квоты. Произвольные RoundTripper
отклоняются; исходный клиент не изменяется. Дополнительные TLS handshakes
учитываются при будущей сетевой приёмке, не выдаются за проверенный live SLO.
Ключи получаются существующим marketplace-connections v1; сохраняются только
совпадающие company/account из полной выдачи политик. Разрешение/кэш ≤120 с,
полная синхронизация каждые 60 с. Неполная выдача не применяется. Отзыв
отменяет активные HTTP-чтения кабинета; следующий запрос цикла не выполняется.
После окончательного 401/403 кабинет ждёт новой updated_at revision; в БД
сохраняется только эта несекретная revision, поэтому рестарт паузу не снимает.

## Расписание и данные

На кабинет максимум 10 политик; общий предел выдачи 10 000, без обещания
производительности на этом масштабе до этапа 11. Обычный интервал ≥600 с.
Ближайший poll резервируется транзакцией захвата до HTTP, чтобы падение
работника не создавало немедленный повтор. Дедлайны окна и разрешений сохраняются
отдельно от времени poll; аренда 90 с, запись результата проверяет её token.
429 переносит следующий poll не раньше интервала и Retry-After. Один кабинет
занимает одного работника; остальные обрабатываются ограниченным пулом.

Дневной расход — max агрегата, SKU и предыдущей сопоставимой суммы; источники
не складываются. День UTC+03, окно [start,stop), перенос через полночь запрещён.
Пустой/вчерашний ответ не создаёт ноль. После budget stop действует latch до
нового дня; повышение лимита не снимает его. Неизвестный резерв остаётся null.
Расчёт оценки резерва на истории точный (целые числа/big.Rat, вверх до копейки),
но в работающем observe не применяется без принятого горизонта риска.
Ручная пауза, исчезновение и неподдерживаемая кампания блокируют запуск.

`complete` относится к проверенным строкам ответа, не доказывает покрытие
удалённых SKU или всех страниц Ozon. `source_age_known=false` всегда:
время HTTP не является watermark. Ошибки и отсутствие свежего первичного
источника не скрываются предыдущим известным расходом.

Квота: общий для экземпляров сервиса консервативный предел 70 000 HTTP за
скользящие 24 ч, включая auth и неудачные попытки, с запасом минутного окна.
Реальные границы организации и общие потребители ещё требуют проверки этапа
04/12. Генерации отчётов сервис не запускает; агрегат и оперативный SKU выбраны
согласно исследованию официальных исключений. Этот лимитер не координирует
существующий ozon-fetcher: живой выпуск до согласования квоты запрещён.

Шаг часов после старта и p99 ограниченного mock-стенда проверены на этапе11.
Дрейф между экземплярами, боевой p99/SLO, многосуточная
полнота и измерение задержки появления расхода — незакрытые гейты 02/04/11/12.
Observe не может из-за них изменить рекламу. Не представлять проверки
детерминированных дат как полноценный аварийный/нагрузочный стенд.

## Проверки и миграции

`make ozon-ads-controller-fmt ozon-ads-controller-vet ozon-ads-controller-lint
 ozon-ads-controller-test` — контейнерные гейты, race и покрытие internal ≥70%.
`TEST_DB_DSN` — отдельная тестовая БД, каждый тест создаёт свою схему.
`-migrations-check` проверяет неприменённые миграции, обычный старт при них
запрещён. `-migrate` применяет одну встроенную goose-миграцию; down проверяется тестом.
Данные последнего дня сохраняются между рестартами; физического удаления
истории при отзыве разрешения нет. Runtime — последняя проекция, не журнал
всех решений; PHP хранит отдельный журнал принятых проекций и настроек с этапа10.

`GET /health`, `/ready` (БД), `/internal/status` (токен обратного направления).
Контейнер не имеет публичного роутера или опубликованного порта. Продовая
топология/выкладка не добавлены: живой допуск этапа12 остаётся закрытым.

## Стенд этапа 11

`make ozon-ads-controller-stand` — настоящая PostgreSQL в случайной схеме,
только БД/роль ozon_ads_test/svc_ozon_ads и localhost HTTP mock. Проверяет
штатные четыре работника, профили10/100 и100/1000, две независимые реплики,
массовые предполагаемые budget stop без ранних HTTP, ошибки и восстановление.
Пороги заданы [до замеров](../../docs/plan/ozon-advertising-stage11-passport.md).
[Результаты и границы доказательств](../../docs/plan/ozon-advertising-stage11-implementation.md).

`GET /internal/observations?limit=100&cursor=...` — закрытая диагностика по
каждой кампании, keyset, без денег/ключей/произвольных ошибок. /health сам
по себе не означает соблюдение сроков. Watcher должен обходить страницы,
поднимать тревогу на deadline_missed/clock_skew/permission_expired/source errors
и не считать observed_source_age_unknown доказательством свежести Ozon.
Production watcher здесь не подключается; endpoint проверен на стенде.

Worker clock-step guard сравнивает wall с monotonic elapsed. Отклонение >5с
защёлкивает остановку захвата кабинетов; восстановление — исправление часов
и рестарт. Исходный offset между серверами/ошибка NTP этим не доказаны.
