# Перенос UI Kit в проект

Переиспользуемая инструкция. Указать файл кита в строке ниже и отдать Claude Code. Ничего больше править не нужно.

```
ФАЙЛ КИТА: docs/design/ui-kit/<имя-файла>.html
```

---

## Что это за задача

Перенести токены и шкалы из HTML-макета дизайн-системы в код. Направление одностороннее: макет читает человек, код правится вручную. Скрипта, сверяющего два источника, нет и не будет — он всегда симптом того, что источников должно быть меньше (`docs/patterns.md`).

Задача не создаёт архитектурных решений. Если по ходу выясняется, что решение требуется, — остановиться и спросить, а не выбрать самому.

## Прежде чем начать — прочитать

- `docs/patterns.md`, разделы «Дизайн-система», «Запрет произвольных значений», «Чего в UI Kit нет и почему»
- `docs/structure.md`, раздел «packages/ui»
- `CLAUDE.md`, «Периметр автономной работы»

Правила из этих документов приоритетнее того, что нарисовано в макете. Макет — источник значений, а не источник архитектуры.

---

## Шаг 0. Сверка макета с правилами проекта

До переноса — пройти по маркерам расхождений. Каждый найденный: не переносить, вынести в отчёт, ждать решения человека.

| Что искать в макете | Правило проекта | Что делать при расхождении |
|---|---|---|
| Тёмная тема, dark-пары токенов, `prefers-color-scheme` | интерфейс всегда светлый, за системной темой не следует | переносить только светлые значения; dark не переносить |
| Пагинация с номерами страниц и общим счётчиком на таблице фактов | таблицы фактов — keyset-курсор, без номеров и без total; offset только для справочников | не реализовывать; вынести в отчёт |
| Размер шрифта вне шкалы 12/14/16/18/20/24/30/36 | шкала закрыта | если в макете это оформленное исключение с подписью — завести именованный токен; если нет — вынести в отчёт |
| Радиус вне набора 4/6/8/12/full | набор закрыт | то же |
| Отступ вне шкалы 4/8/12/16/20/24/32/40/48/64 и вне названных в макете исключений | шкала закрыта | то же |
| Компонент, которого нет в `packages/ui` | «третье повторение», не раньше | не создавать; см. шаг 4 |

Отсутствие расхождений — тоже результат, его надо явно указать в отчёте.

## Шаг 1. Цветовые токены

Источник — таблица токенов в разделе «Цветовые токены» макета.

**Правило именования, механическое:** слэш → дефис, префикс по типу.

| В макете | В `theme.css` |
|---|---|
| `text/primary` | `--color-text-primary` |
| `surface/raised` | `--color-surface-raised` |
| `accent-subtle/hover` | `--color-accent-subtle-hover` |
| `positive/bg` | `--color-positive-bg` |
| `chart/cat-1` … | `--color-chart-cat-1` … |
| `chart/seq-1` … | `--color-chart-seq-1` … |
| `shadow/card` | `--shadow-card` |

Имя в коде должно восстанавливаться из имени в макете одним правилом. Отсебятины быть не должно.

**Критерии выполнения:**
- Каждая строка таблицы макета имеет переменную в `packages/ui/src/theme.css`.
- Обратно: каждая переменная соответствует строке таблицы. Переменных «про запас» нет.
- Все объявлены внутри `@theme static` — не в `:root`, не в обычном `@theme`. Обычный `@theme` вырежет `--color-chart-*` из production-CSS как неиспользуемые, а они нужны графикам в runtime.
- Значения `--color-chart-*` совпадают с макетом посимвольно: перекрасить статью затрат — то же, что переименовать статью.
- В `apps/` не добавлено ни одного объявления токена.
- Ни один hex не продублирован под двумя именами.

## Шаг 2. Типографика и шкалы

**Критерии выполнения:**
- Каждый размер шкалы макета объявлен переменной.
- Начертания ограничены набором из макета, лишних нет.
- `body` имеет базовый размер интерфейса из макета; на `html` размер не переопределён — шкала отступов в `rem`, смещение на `html` сдвинуло бы её целиком.
- `tabular-nums` включён глобально для `table`, `input`, `output`. Если правило уже есть — не дублировать.
- IBM Plex Sans через Fontsource локально; внешнего запроса к Google Fonts нет.
- Оформленные исключения макета (размер вне шкалы с подписью об области применения) существуют именованными переменными с говорящим именем и комментарием, повторяющим формулировку ограничения из макета. Произвольным значением такое исключение остаться не может: `text-[11px]` — ошибка линтера.

## Шаг 3. Существующие примитивы

Пройти по каждому файлу в `packages/ui/src` и привести к обновлённым токенам.

**Критерии выполнения:**
- В файлах примитивов нет hex-литералов.
- Нет произвольных значений Tailwind ни в какой форме: `bg-[#...]`, `text-[13px]`, `p-[7px]`, `w-[calc(...)]`, `[&>div]:flex`.
- Статусные варианты берут цвета из статусных токенов, не из палитры графиков.
- Публичный API не изменился: `className` наружу по-прежнему не выставлен.
- Внешний вид соответствует соответствующему разделу макета.

## Шаг 4. Новых примитивов не создавать

Макет содержит десятки компонентов — таблицу, тултип, поповер, модалку, drawer, пагинацию, графики, состояния пустоты. `patterns.md` перечисляет их как отсутствующие намеренно, до третьего продуктового повторения. Первая таблица и её skeleton живут в своей фиче.

**Критерии выполнения:**
- В `packages/ui/src` не появилось ни одного нового файла компонента.
- `index.ts` экспортирует тот же набор, что до задачи.

## Шаг 5. Ссылка на эталон

**Критерии выполнения:**
- Файл кита лежит в `docs/design/ui-kit/`.
- В `patterns.md` и `structure.md` ссылка на эталон указывает на этот файл; ссылок на прошлую версию как на актуальную не осталось.
- Прошлые версии не удалены.
- Формулировка про одностороннее направление сохранена без изменений.

## Чего в этой задаче быть не должно

- Скрипта или теста, сверяющего `theme.css` с HTML-макетом.
- Dark-палитры, `prefers-color-scheme`, переключателя темы — пока решение не изменено отдельным ADR.
- Новых компонентов в `packages/ui`.
- Токенов, объявленных в `apps/`.
- Произвольных значений Tailwind. Осознанное исключение — подавление с причиной в комментарии.
- Реализации того, что макет показывает, а `patterns.md` запрещает. Макет не отменяет ADR.
- Изменений в `apps/` за пределами замены изменившихся имён токенов.

## Проверки перед сдачей

- [ ] `make front-typecheck` зелёный
- [ ] `make front-lint` зелёный, включая `local/no-arbitrary-tailwind` в обоих приложениях
- [ ] `make front-test` зелёный
- [ ] `make front-knip` без новых неиспользуемых экспортов
- [ ] `make front-build` собирается, и в собранном CSS присутствуют все `--color-chart-*` — проверка, что `@theme static` отработал
- [ ] Диф не выходит за `packages/ui/`, `docs/design/`, `docs/patterns.md`, `docs/structure.md` и точечные замены имён токенов в `apps/`

## Отчёт по задаче

1. Число перенесённых токенов и число строк в таблице макета — должны совпасть.
2. Токены, у которых имя в коде отличалось от имени в макете до правки.
3. Места, где потребовалось подавление линтера, с причинами.
4. Результат шага 0: найденные расхождения макета с `patterns.md`, либо явное «расхождений нет».
