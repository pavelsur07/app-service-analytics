# Операционный чек-лист

Не архитектурные решения, а обязательные к выполнению вещи.
Список короткий намеренно: всё, что здесь есть, отделяет
«работает у меня» от «работает у клиентов».

## До первого платящего клиента

- [ ] **Резервное копирование PostgreSQL с восстановлением на момент времени.**
      Настроить — половина дела. Обязательно **развернуть копию и убедиться,
      что данные на месте**. Непроверенная копия резервной копией не является.
- [ ] Расписание копий и срок хранения зафиксированы письменно.
- [ ] Raw-слой входит в периметр копирования: это единственный источник
      истины при пересчётах.
- [ ] Мастер-ключ шифрования учётных данных — в секретах окружения,
      отдельно от репозитория и от дампов базы. Проверить, что он
      не попадает в резервные копии базы в открытом виде.
- [ ] Трекер ошибок подключён и получает исключения из воркеров,
      а не только из веб-процесса.
- [ ] Оповещение о свежести данных: нет новых фактов по активному
      подключению дольше суток → письмо себе.
- [ ] Оповещение о недоступности приложения.
- [ ] Staging: копия схемы с боевыми данными для прогона миграций.
- [ ] Воркеры под менеджером процессов, с перезапуском при каждом релизе
      и ограничением по памяти. Воркер на старом коде — источник
      необъяснимых расхождений.
- [ ] Проверка работоспособности проверяет зависимости (база, Redis,
      глубина очереди), а не факт запуска процесса.

## Раз в релиз

- [ ] Миграция прогнана на копии боевых данных.
- [ ] Миграция прочитана человеком.
- [ ] Воркеры перезапущены после выкладки.

## Расширение браузера — перед каждой публикацией

Отдельный раздел, потому что здесь конвейер не помогает: сборка бывает
зелёной у расширения, которое не выполняется вовсе. Три дефекта пакета 4
нашлись открытой карточкой в браузере — ни CI, ни оба внешних ревьюера
их не увидели. Проверять руками, на **свежем профиле Chrome**: в рабочем
профиле лежит старое подключение и прогретый кэш, и они прячут ровно те
отказы, которые ловит клиент.

- [ ] Консоль вкладки маркетплейса **без наших ошибок**. Первое, что
      смотреть, — `SyntaxError` в `content/*.js`: content-script MV3
      грузится обычным скриптом, и любой `import` в нём означает, что
      скрипт не выполнился ни разу. Сборка при этом зелёная.
- [ ] Консоль **без ошибок гидратации** с упоминанием наших узлов.
      Карточка приходит с сервера отрисованной; узел, вставленный до
      гидратации, ломает страницу маркетплейса. Это хуже, чем отсутствие
      панели: мы портим чужой сайт.
- [ ] Сеть идёт из service worker, не из content-script. Признак
      нарушения — `blocked by CORS policy` в консоли вкладки.
- [ ] Панель появилась на карточке своего товара и цифры совпадают
      с теми, что показывает приложение по тому же артикулу.
- [ ] Панель исчезла и появилась заново при переходе на соседний товар
      без перезагрузки страницы.
- [ ] Панель читается на тёмной теме маркетплейса.
- [ ] Якорь не найден → предупреждение в консоли. Проверять именно
      наличие сигнала: молчащая панель неотличима от «нет продаж».
- [ ] Манифест боевой сборки: локальных доменов нет, разрешений
      не больше, чем нужно. Локальный домен в опубликованном пакете —
      отказ на ревью в сторе.
- [ ] Размер content-script в пределах порога. Он грузится на каждой
      карточке, в отличие от popup, который открывают по клику.

## Расширение браузера — раз в месяц

- [ ] Открыть карточку своего товара и убедиться, что панель на месте.
      Маркетплейс меняет вёрстку без предупреждения, и якорь отваливается
      молча — единственный признак живёт в консоли клиента, куда мы
      не смотрим.
- [ ] Доля обращений к API расширения, отвечающих 401. Устойчивый рост
      означает, что клиенты не переподключаются после истечения токена
      и расширение у них просто перестало работать.

## Раз в месяц

- [ ] Восстановление из резервной копии проверено фактически.
- [ ] `composer audit` и `npm audit` без известных уязвимостей.
- [ ] Зависимости обновлены планово.
- [ ] Просмотрен список подключений в состоянии `broken`:
      устойчиво высокая доля означает проблему в инструкции
      по подключению, а не у клиентов.

## Раз в квартал

- [ ] Объём raw-слоя и время резервного копирования: не пора ли
      выносить сырьё в объектное хранилище.
- [ ] Время ночного пересчёта и глубина очереди против порогов
      из ADR-001.
- [ ] Предупреждения об устаревших вызовах Symfony — держать на нуле
      ради перехода на следующую LTS.
- [ ] Календарь версий: ноябрь 2027 — Symfony 8.4 LTS;
      декабрь 2026 — окончание активной поддержки PHP 8.4.

## Отложено сознательно

Не делать, пока не сработает условие:

| Что | Когда браться |
|---|---|
| Самостоятельная регистрация, восстановление пароля | ручное заведение тормозит, ориентир 10–15 компаний |
| Второй фактор для селлеров, роли и разрешения | клиенты просят доступ для сотрудников |
| Экспорт данных клиента | первый запрос от клиента или требование договора |
| Справедливое распределение очереди между клиентами | один клиент реально блокирует остальных |
| Объектное хранилище под raw | объём мешает резервному копированию; схема ключей принята заранее — см. ниже |
| Отдельное аналитическое хранилище | пороги из ADR-001 |
| Тарифы | до этого — булевы флаги на компании, кода про деньги нет |

### Схема ключей объектного хранилища

Принята заранее, чтобы переезд не потребовал переименования уже
накопленного сырья:

```
raw/v1/company={uuid}/marketplace={slug}/account={uuid}/report={slug}/period=YYYYMMDD_YYYYMMDD/{sha256}.json.gz
```

Ключ детерминирован полями уникального индекса `raw_document` —
повторный PUT перезаписывает тот же объект, а не создаёт второй.

Переезд тянет за собой: версионирование бакета становится обязательным;
восстановление — двухкомпонентным (PostgreSQL на момент времени плюс
бакет на тот же момент); раздел резервного копирования переписывается
целиком.
