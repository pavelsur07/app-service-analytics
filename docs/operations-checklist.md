# Операционный чек-лист

Не архитектурные решения, а обязательные к выполнению вещи.
Список короткий намеренно: всё, что здесь есть, отделяет
«работает у меня» от «работает у клиентов».

## До первого платящего клиента

- [ ] **Резервное копирование PostgreSQL с восстановлением на момент времени.**
      Настроить — половина дела. Обязательно **развернуть копию и убедиться,
      что данные на месте**. Непроверенная копия резервной копией не является.
- [ ] Расписание копий и срок хранения зафиксированы письменно.
- [ ] Raw-слой входит в периметр копирования: это единственный источник
      истины при пересчётах.
- [ ] Мастер-ключ шифрования учётных данных — в секретах окружения,
      отдельно от репозитория и от дампов базы. Проверить, что он
      не попадает в резервные копии базы в открытом виде.
- [ ] Трекер ошибок подключён и получает исключения из воркеров,
      а не только из веб-процесса.
- [ ] Оповещение о свежести данных: нет новых фактов по активному
      подключению дольше суток → письмо себе.
- [ ] Оповещение о недоступности приложения.
- [ ] Staging: копия схемы с боевыми данными для прогона миграций.
- [ ] Воркеры под менеджером процессов, с перезапуском при каждом релизе
      и ограничением по памяти. Воркер на старом коде — источник
      необъяснимых расхождений.
- [ ] Проверка работоспособности проверяет зависимости (база, Redis,
      глубина очереди), а не факт запуска процесса.

## Раз в релиз

- [ ] Миграция прогнана на копии боевых данных.
- [ ] Миграция прочитана человеком.
- [ ] Воркеры перезапущены после выкладки.

## Раз в месяц

- [ ] Восстановление из резервной копии проверено фактически.
- [ ] `composer audit` и `npm audit` без известных уязвимостей.
- [ ] Зависимости обновлены планово.
- [ ] Просмотрен список подключений в состоянии `broken`:
      устойчиво высокая доля означает проблему в инструкции
      по подключению, а не у клиентов.

## Раз в квартал

- [ ] Объём raw-слоя и время резервного копирования: не пора ли
      выносить сырьё в объектное хранилище.
- [ ] Время ночного пересчёта и глубина очереди против порогов
      из ADR-001.
- [ ] Предупреждения об устаревших вызовах Symfony — держать на нуле
      ради перехода на следующую LTS.
- [ ] Календарь версий: ноябрь 2027 — Symfony 8.4 LTS;
      декабрь 2026 — окончание активной поддержки PHP 8.4.

## Отложено сознательно

Не делать, пока не сработает условие:

| Что | Когда браться |
|---|---|
| Самостоятельная регистрация, восстановление пароля | ручное заведение тормозит, ориентир 10–15 компаний |
| Второй фактор для селлеров, роли и разрешения | клиенты просят доступ для сотрудников |
| Экспорт данных клиента | первый запрос от клиента или требование договора |
| Справедливое распределение очереди между клиентами | один клиент реально блокирует остальных |
| Объектное хранилище под raw | объём мешает резервному копированию |
| Отдельное аналитическое хранилище | пороги из ADR-001 |
| Тарифы | до этого — булевы флаги на компании, кода про деньги нет |
| Расширение для браузера | после подтверждения ценности веб-продукта |
