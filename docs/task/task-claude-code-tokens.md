# Задача для Claude Code: перенос токенов UI Kit в `packages/ui/src/theme.css`

## Вход

Файл кита: `UI_Kit_dc__16_.html` (контрольная сумма `56052ad9685737b494131ede8f998e6d`). Раздел 01 «Цветовые токены» содержит таблицу с именами и hex, раздел 02 — шкалы типографики и отступов, раздел 03 — layout.

## Прежде чем начать — прочитать

- `docs/patterns.md`, раздел «Дизайн-система» — там уже зафиксированы правила, которым перенос обязан подчиняться.
- `docs/structure.md`, раздел «packages/ui».
- `CLAUDE.md`, «Периметр автономной работы».

Задача не создаёт новых архитектурных решений. Если по ходу выясняется, что решение требуется, — остановиться и спросить, а не выбрать самому.

## Блокирующий вопрос до начала работы

**Тёмная тема.** Кит содержит раздел 14 с шестью компонентами в тёмной теме и парные dark-значения для каждого токена. `patterns.md` говорит обратное: «Интерфейс всегда использует светлую палитру и не переключается вслед за системной темой».

До получения ответа — **переносить только светлые значения**. Dark-пары не переносить, `prefers-color-scheme` не подключать, вторую палитру в `theme.css` не заводить.

Если решение изменится, это отдельная задача с ADR, а не побочный эффект переноса.

## Задача 1. Цветовые токены

**Что сделать:** перенести все токены из таблицы раздела 01 кита в `packages/ui/src/theme.css` внутрь `@theme static`.

**Правила именования** — механические, без интерпретации:

| В ките | В `theme.css` |
|---|---|
| `text/primary` | `--color-text-primary` |
| `surface/raised` | `--color-surface-raised` |
| `accent-subtle/hover` | `--color-accent-subtle-hover` |
| `positive/bg` | `--color-positive-bg` |
| `chart/cat-1` … `cat-8` | `--color-chart-cat-1` … `-8` |
| `chart/seq-1` … `seq-5` | `--color-chart-seq-1` … `-5` |
| `shadow/card`, `popover`, `modal` | `--shadow-card`, `--shadow-popover`, `--shadow-modal` |

Слэш → дефис, префикс по типу токена. Отсебятины в именах быть не должно: имя в `theme.css` восстанавливается из имени в ките одним правилом.

**Критерии выполнения:**
- Каждая строка таблицы раздела 01 кита имеет соответствующую переменную в `theme.css`.
- Обратно: каждая переменная в `theme.css` соответствует строке таблицы. Переменных «про запас» нет.
- Все объявлены внутри `@theme static`, не в `:root` и не в обычном `@theme`. Причина в `patterns.md`: цвета графиков нужны в runtime, обычный `@theme` вырежет их из production-CSS как неиспользуемые.
- Значения `--color-chart-*` совпадают с китом посимвольно. Перекраска статьи затрат равносильна переименованию статьи (`patterns.md`).
- В `apps/seller` и `apps/admin` не добавлено ни одного объявления токена.
- Ни один hex не продублирован под двумя именами.

## Задача 2. Типографика и шкалы

**Что сделать:** привести шкалы `theme.css` в соответствие разделу 02 кита.

Шкала размеров: 12 / 14 / 16 / 18 / 20 / 24 / 30 / 36. Базовый размер интерфейса 14px задаётся на `body`, не на `html` — шкала отступов в `rem`, смещение на `html` сдвинуло бы её целиком (`patterns.md`).

Начертания: 400 / 500 / 600 / 700, других нет.

**Отдельно — 11px.** В ките это оформленное исключение: «только значения на осях графиков и столбцах waterfall, нигде больше». В коде `text-[11px]` — ошибка линтера `local/no-arbitrary-tailwind`. Поэтому 11px обязан существовать как именованный токен, а не как произвольное значение. Завести переменную с говорящим именем, отражающим единственную область применения (не `--text-xs-2`, а что-то вроде `--text-chart-label`), и оставить комментарий с той же формулировкой ограничения, что в ките.

**Критерии выполнения:**
- Каждый размер шкалы объявлен переменной.
- 11px существует именованной переменной с комментарием об ограничении применения.
- `body` имеет `font-size: 14px`; на `html` размер не переопределён.
- `tabular-nums` включён глобально для `table`, `input`, `output` (`patterns.md`) — проверить, что это уже так, и не дублировать правило, если оно есть.
- IBM Plex Sans подключается через Fontsource локально; внешнего запроса к Google Fonts в коде нет.

## Задача 3. Существующие примитивы

`packages/ui/src` содержит `Button.tsx`, `Input.tsx`, `Card.tsx`, `Badge.tsx`.

**Что сделать:** проверить, что каждый использует токены из обновлённого `theme.css`, и заменить те места, где имя токена изменилось или цвет был захардкожен.

**Критерии выполнения:**
- В файлах примитивов нет hex-литералов.
- Нет произвольных значений Tailwind в любой форме — `bg-[#...]`, `text-[13px]`, `p-[7px]`.
- `Badge` покрывает четыре варианта, объявленные в `structure.md`: нейтральный, positive, negative, warning — и берёт цвета из статусных токенов, а не из палитры графиков.
- Публичный API примитивов не изменился: `className` наружу по-прежнему не выставлен.
- Внешний вид примитивов соответствует разделу 05 кита.

## Задача 4. Новых примитивов не создавать

**Явное ограничение задачи.** Кит содержит 15 разделов и десятки компонентов — таблицу, тултип, поповер, модалку, drawer, пагинацию, графики. `patterns.md` перечисляет `Table`, `Dialog`, `Dropdown`, `Select`, `DatePicker`, `Tabs`, `Skeleton` как то, чего в `packages/ui` нет намеренно, до третьего продуктового повторения.

**Критерии выполнения:**
- В `packages/ui/src` не появилось ни одного нового файла компонента.
- `index.ts` экспортирует тот же набор, что и до задачи.
- Ни один компонент из кита не «перенесён на будущее».

**Что сделать:** положить файл кита в `docs/design/ui-kit/` под номером следующей версии, обновить ссылку в обоих документах. Старую версию не удалять.

**Критерии выполнения:**

- Формулировка про одностороннее направление («макет читает человек, код правится вручную, скрипта сверки нет») сохранена без изменений.
- Скрипт сверки макета и кода не создан.

## Чего в этой задаче быть не должно

- Скрипта или теста, сверяющего `theme.css` с HTML-китом. Прямо противоречит `patterns.md`.
- Dark-палитры, `prefers-color-scheme`, переключателя темы.
- Новых компонентов в `packages/ui`.
- Токенов, объявленных в `apps/`.
- Произвольных значений Tailwind. Осознанное исключение оформляется подавлением с причиной в комментарии.
- Изменений в `apps/seller` и `apps/admin` за пределами замены имён токенов, если какое-то имя изменилось.
- Правок под пагинацию: расхождение кита (offset с номерами страниц) с `patterns.md` (keyset для таблиц фактов) — отдельный вопрос, решается ADR, в эту задачу не входит.
