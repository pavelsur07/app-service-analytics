## ADR-031: Ozon — штуки без оценки не обнуляют прогноз выкупа

**Дата:** 2026-09-25
**Статус:** Accepted
**Модуль:** Ingestion
**Уточняет:** ADR-020 — раздел «Прогноз» ADR-019, повторно принятый
ADR-020, в части того, когда прогноз агрегата равен NULL. Формулы
прогноза, обучающее окно (ADR-029) и классификация не меняются.

### Контекст

Прогноз агрегата (SKU за период, день, сводка отчёта) сейчас NULL, если
**хотя бы одна** его штука без исхода не получила оценки:

- исход не распознан, а статус уже terminal (unknown по ADR-019);
- статус ещё активен, но по заказу уже есть возврат — ADR-019 снимает
  с такой строки право на прогноз как с противоречивого снимка;
- нет обучающей ставки ни у SKU, ни у кабинета.

Сводка отчёта дополнительно NULL, если NULL прогноз хоть одного SKU.

Проверка на прошлых датах (ADR-030) на production 2026-09-25 показала
следствие: у 186 из 209 проверенных дней кабинета прогноза нет. Штуки
без оценки есть в 36 из 42 дней с 15.08 — в среднем 4,3% количества,
максимум 14,5%; за 30 дней — у 28 из 47 SKU. Из них 96 штук — закрытые
с нераспознанным исходом, 33 — активные с возвратом. Прогноз, который
почти никогда не показывается, не выполняет своей задачи, а там, где он
есть, ошибка 2,1 п.п. против 4,2 у оценки по известным исходам.

### Решение

**Штука без оценки исключается из прогноза агрегата, а не обнуляет его.**
Штука без оценки — без исхода и либо без права на прогноз
(`is_forecast_eligible = false`), либо без обучающей ставки для своей
стадии. Её прогноза по-прежнему нет — меняется только то, что происходит
с агрегатом, в который она входит.

Для агрегата:

- **ставка** — как в ADR-019, по штукам с оценкой:
  ожидаемые D / ожидаемый знаменатель;
- **ожидаемое количество выкупа** — ожидаемые D штук с оценкой,
  масштабированные на всё заказанное количество:
  `D_ожид × заказано / заказано_с_оценкой`. Предположение то же, что у
  ставки: штуки без оценки выкупаются так же, как остальные. Без
  масштабирования «ожидается N из M» занижало бы N на долю исключённых;
- **NULL**, если без оценки больше **10%** заказанного количества
  агрегата или ожидаемый знаменатель равен нулю.

Правило одно на любом уровне агрегации: SKU за период, день, сводка
отчёта. Сводка считается по суммам штук всех SKU, а не по уже
округлённым и обнулённым строкам SKU — иначе один маленький SKU снова
обнулял бы сводку.

Порог 10% выбран по production: он пропускает 40 из 42 дней кабинета
и 42 из 47 SKU за 30 дней; при большей доле неизвестного прогноз
держится в основном на допущении, а не на данных.

API не меняется: поля и их смысл прежние, прогноз реже NULL.
Проверяется командой ADR-030 на тех же датах.

### Альтернативы, которые отвергли

- **Оставить обнуление.** Прогноз почти всегда отсутствует там, где
  нужен, — на дне и сводке.
- **Исключать без порога.** День, где половина штук неизвестна, получил
  бы уверенно выглядящую цифру по второй половине.
- **Исключать без масштабирования количества.** Ставка и «ожидается N
  шт» расходились бы: N считался бы по меньшей базе, чем M.
- **Считать штуку без оценки невыкупом (или выкупом).** Это ровно то
  «правдоподобное число», от которого ADR-019 отказался для unknown.

### Последствия

**Получаем:** прогноз на уровне дня и сводки появляется почти всегда;
его точность измерима командой ADR-030.

**Платим:** агрегат с 1–10% неизвестного опирается на допущение, что
неизвестные штуки ведут себя как остальные. Доля неизвестного наружу
пока не отдаётся — это отдельное решение о контракте API.

**На что обратить внимание потом:** если доля нераспознанных исходов
растёт, это вопрос справочника причин (ADR-019), а не порога.
