# ADR-050: исследование категорий Ozon через Python-сервис

Дата предложения: 31.10.2026. Статус: **Accepted (01.11.2026)**.
Вступает в силу после merge PR #302 с зелёным обязательным CI.

Этап 0 [плана](../plan/product-research-ozon.md). Независимое ревью и повторная
проверка исправлений завершены: [результаты](../plan/product-research-ozon-review.md).
Начало этапа разрешено владельцем; серверный токен и company-scoped кэш
подтверждены отдельно 31.10.2026. Токен проверен через REST; секрет MPSTATS_API_TOKEN добавлен в GitHub Actions.
FBO+FBS подтверждён новым ручным экспортом и API FBS=1 по всем 62 148 SKU.

## Контекст

Нужны проекты исследования одной категории Ozon с несколькими сезонами.
Данные MPStats собираются целыми календарными месяцами. Очистка, панель
SKU × месяц, XLSX, обогащение и анализ не входят в первый выпуск.
Python выбран для будущей аналитики; в MVP он выполняет сбор сырья.

ADR-043 регулирует Go-загрузчик кабинетов Ozon, а не MPStats. Его выдача
ключей всех кабинетов, account scope, 90-дневное хранение и правила Go
не переносятся автоматически. ADR-044 определяет разделение пространства S3.

## Решение

### Владение и связи

- Новый модуль Symfony `ProductResearchOzon`: проекты, периоды, авторство,
  права, запуск и проекция прогресса. Слои Domain/Application/Infrastructure/Ui.
- Зависимости: `ProductResearchOzon → Identity → Shared`, доступ к Identity
  только через существующий разрешённый Facade. Новых связей с Ingestion
  и SalesPlanning нет. Точные границы Deptrac добавить вместе с модулем.
- Сервис `services/product-research-ozon`: MPStats, каталог категорий,
  задачи, попытки, месячные снимки, кэш. БД `product_research_ozon`, роль
  `svc_product_research_ozon`, без доступа к БД Conwix.
- В MVP БД сервиса содержит только техническое состояние и метаданные
  снимков; тела ответов и денежные показатели остаются в сырье S3.
  Аналитические таблицы и финансовые расчёты требуют следующего ADR.
- UI обращается только к Symfony. Пользовательский HTTP-запрос не вызывает
  Python синхронно. Справочник обновляет фоновая задача Symfony через
  внутренний API сервиса; поиск идёт по последней полной локальной проекции.
  Пустой ещё не полученный каталог отличается от пустой выдачи поиска.

### Доставка и восстановление

Проект/запуск и намерение отправки записываются одной транзакцией в БД
Symfony. Предлагается transactional outbox модуля; существующий Messenger
worker вызывает relay, новый транспорт или брокер не вводится. Периодическая
сверка подбирает недоставленные записи даже при потере уведомления relay.

Python подтверждает приём после commit в своей БД. Ключ `(company_id, run_id)`
уникален, хэш параметров неизменен; повтор с другим телом — конфликт.
Доставка at-least-once; exactly-once HTTP не обещается.
Задачи захватываются с арендой и fencing-версией. Потерявший аренду worker
не публикует результат. Даты запуска фиксируются до отправки.

Symfony получает прогресс фоновым polling с лимитом/keyset. Версия состояния
монотонна внутри запуска; старый запуск не заменяет проекцию нового.
Полная сверка восстанавливает пропущенный прогресс. Внутренний API отдаёт
статусы и метаданные, не сырые строки, суммы или секреты.

### Изоляция и токен

Один серверный токен MPStats — подтверждённый выбор владельца. Только секрет
окружения Python-сервиса; не передаётся Symfony, браузеру, фикстурам или БД.
HTTP-заголовок `X-Mpstats-TOKEN`, не URL. Редирект на другой host запрещён.
Ротация — обновление секрета и контролируемый перезапуск API/worker.
Настройка поколения credentials несекретна; после ротации снимается пауза
авторизации, старый процесс не продолжает работу с отозванным поколением.

Лимитер MPStats общий на серверное подключение и endpoint, а не на компанию:
одна квота токена обслуживает всех. 401/403 блокирует вызовы этого подключения.
Очередь выбирает компании справедливо, чтобы большой проект не занял все слоты.

Проекты, снимки, кэш и локальная проекция каталога ограничены компанией.
Кэш: company + source_connection_id + категория + даты + FBS + RUB +
версия контракта/семантические параметры. Секрет в ключе отсутствует.
Повторное использование между компаниями запрещено даже с общим токеном.

Путь S3:
`conwix/svc/product-research-ozon/v1/companies/{company_id}/connections/{source_connection_id}/snapshots/{snapshot_id}/pages/{page_no}/{sha256}.json`.
ID компании проверяется через найденную company-scoped строку; готовый ключ
из запроса не принимается. Первоначально требовались отдельные права на префикс.
**Уточнение владельца 02.11.2026:** использовать уже подключённое S3 и его
реквизиты, получаемые при деплое через секреты. Для research в MVP разрешён
существующий ключ `RAW_STORAGE_*`, как отдельное решение для этого сервиса.
Бакет/endpoint те же, пространство research отделено постоянным префиксом.
IAM-изоляции от остального бакета у общего ключа нет; граница держится
company-scoped портом и сборкой ключей внутри сервиса. Ротация затрагивает
PHP/ozon-fetcher/research и требует обновления всех потребителей.
Отдельный ключ остаётся последующим усилением, не условием текущего запуска.
Межсервисный токен PHP → Python отдельный,
не короче 32 символов; сеть internal, без публичного маршрута.

### Пилотный просмотр UI без MPStats

02.11.2026 владелец поручил открыть интерфейс двум подтверждённым кабинетам.
Research использует отдельный источник MPStats и не требует личного подключения
Ozon для просмотра собственных исследовательских проектов. Поэтому только
точные research list/project маршруты освобождены от onboarding gate ADR-021,
и только после успешного server availability для текущей компании. Pending
availability ожидается, error/false не открывают исключение. RequireAuth,
membership, blocked-company, extension scope и API rollout сохраняются.
Остальные разделы, включая продажи, по-прежнему требуют active подключения.
Пилотные идентификаторы хранятся только в защищённом company allowlist.

Просмотр включается PHP-флагом и allowlist, но PHP `RESEARCH_CATALOG_SOURCE_ID`
остаётся пустым до допуска MPStats. Существующий CatalogContext отклоняет
поиск/создание по неподготовленному каталогу и новый run возвращает
catalog_not_ready до записи run/outbox и изменения проекта. Исходный source ID
сохраняется в защищённом Python env для последующей настройки.
Python catalog/collection/worker выключены, standby=true, MPStats secret
отсутствует. UI-допуск не является разрешением live-сбора или закрытием этапа 9.

### Календарь, сырьё и ограничение MVP

Предлагаемые defaults: FBS всегда включён, RUB, «Новинки: Неважно»,
календарь Europe/Moscow (продуктовый выбор, timezone MPStats ещё не подтверждён).
Периоды — диапазоны месяцев; пересечения дают одну потребность в месяце.
Текущий месяц доступен по флагу со 2-го числа до вчера включительно.

Базовый лимит проекта — 24 уникальных месяца; один активный запуск на проект,
один запрос MPStats одновременно на подключение. Это наши ограничения,
не заявленные квоты поставщика. Число запросов в минуту задаётся после
подтверждения тарифа; без настройки квоты загрузка не включается.
Паузы не удерживают worker; срок ожидания месяца — 24 часа, после чего
ошибка с возможностью повторить. `Retry-After` нельзя сокращать ради deadline:
при превышении остаёмся без нового запроса и завершаем попытку.

Страницы неизменяемы; снимок публикуется после проверки counts и уникальности
ID. Проверки не гарантируют snapshot isolation изменяемого источника:
гарантия API ещё не подтверждена. Текущий месяц всегда получает новый снимок.
Старый снимок сохраняется, но не закрывает новый диапазон дат.

Снимки, на которые ссылается проект, хранятся весь срок существования проекта;
автоматический TTL 90 дней не применяется. Удаление проектов и сборка мусора
не входят в MVP. До включения обязательны лимит хранилища/оповещения; стоимость
долгого хранения — принятая издержка предлагаемого подхода. Недописанное сырьё
не считается кэшем, политика очистки orphan-объектов — до включения сервиса.

### Python и миграции

Предлагаемый стек и точные кандидаты версий — в
[пакете этапа 0](../plan/product-research-ozon-stage0.md).
Проверены Python 3.14.10, image digest и hash-lock 71 пакета.
`make product-research-ozon-stage0-check` проверяет стек и офлайн-эталоны.
SQL явный, Psycopg binary; ORM в runtime нет. Alembic + SQLAlchemy Core только для
миграций. Миграции входят в образ, выполняются отдельной Make-целью, не при
старте; перед запуском проверяется совпадение ревизии. UUIDv7 в приложении.
Денежная сверка: decimal-парсинг исходного JSON и точный перевод в минорные
единицы по подтверждённой валюте; float запрещён, оригинал не меняется.

## Изменения правил при принятии

1. CLAUDE.md / корневой AGENTS.md: добавить Python и модуль, зависимости и гейты.
2. services/AGENTS.md: отделить общие инварианты от Go/ozon-fetcher механизмов;
   добавить ссылку на Python-правила; server connection вместо marketplace
   account только для этого сервиса, общий лимитер, отличающийся retention.
3. services/python.md: утвердить черновик из пакета этапа 0.
4. docs/patterns.md, docs/structure.md: стек, паттерны, карта новых каталогов.
5. Шаблон ревью: подбирать языковой контекст, не требовать Go-документ для Python.

В этом пакете подготовлены изменения правил, локальный hash-lock и проверки
этапа 0. Runtime, таблицы, контейнеры приложения и модуль Symfony создаются
только на соответствующих этапах. Закрытие и merge — после полного ревью.

## Альтернативы

- Всё в Symfony: проще эксплуатация, но будущая аналитика требует Python;
  выбран отдельный сервис с ценой второго runtime.
- Несколько микросервисов/брокер/workflow-платформа: лишняя сложность MVP.
- Общая БД: запрещает независимую эволюцию и ослабляет изоляцию.
- Один сезонный отчёт: не доказана полнота помесячной детализации.
- Общий кэш компаний: отвергнут подтверждённым решением владельца.

## Проверенные основания и условия принятия

- Прямой REST проверен: категории (6 567 путей), квота (10 000 Ozon на момент
  проверки тестового токена), POST отчёта, body пагинации, FBS, RUB.
- Полный январь 2026: 102 JSON-страницы, 50 702 SKU без дублей; все ID и суммы
  совпали с API CSV. Дополнительная сортировка id устранила обнаруженные дубли.
- По явному подтверждению владельца 31.10.2026 эталон ручной сверки —
  февраль 2025 «Защита от насекомых»; январский ручной CSV не требуется.
  Январский API-набор сохранён для полной пагинации.
- Ручной февраль 2025: 62 148 SKU, продажи/выручка совпали с API FBS=1
  по каждой строке; ручная схема 41 колонка, API CSV 49, REST 62 поля.
- Вычисляемые показатели, остатки и часть метаданных UI/API отличаются.
  Сырьё сохраняется как есть. Доля выручки API может быть долей страницы;
  аналитическая доля будет вычисляться отдельно по полному месяцу.
- Лимит запросов в минуту, гарантии snapshot isolation и timezone провайдера
  не доказаны и не выдаются за свойства API. Одновременность 1, консервативная
  пауза/Retry-After и опрос квоты на подключение — требования реализации.
  Проверка актуального тарифа и лимитов обязательна до production-включения,
  не подменяется экспериментом с тестовым токеном.
- Полные независимые Codex CLI 5A/5B завершены; два замечания исправлены,
  повторные 5A/5B подтвердили изменения без новых замечаний.
  Итоговые документы проходят отдельную проверку; merge требует зелёного CI.
