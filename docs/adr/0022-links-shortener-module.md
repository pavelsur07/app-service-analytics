## ADR-022: Сокращатель ссылок как модуль монолита

**Дата:** 2026-09-02
**Статус:** Accepted
**Модуль:** Links (новый)

### Контекст

Компании нужны короткие отслеживаемые ссылки для собственных рассылок
и кампаний на домене lin.conwix.com, с мини-дашбордом в админке.
Нагрузка — внутренняя, порядок сотен переходов в сутки.
Боевая машина имеет 1.9 ГиБ памяти на семь контейнеров; запас невелик.

### Решение

Заводим модуль Links в существующем монолите. Публичный редирект —
контроллер в Links/Ui, привязанный к хосту lin.conwix.com. Хост
добавляется третьим роутером Traefik на тот же nginx и тот же php-fpm;
новых контейнеров нет. Хранение — PostgreSQL, две таблицы: short_link
и short_link_click (сырые события, без денормализованных счётчиков).
Запись клика синхронная, её отказ не блокирует редирект. Код ссылки —
случайный base62(7) с уникальным индексом. Ответ — 302.
UI — фича links в apps/admin. На роутер вешается rateLimit Traefik.

Первичная вставка `short_link` — узкое исключение из общего
правила ORM для редактируемых человеком данных: она идёт одним DBAL
`INSERT ... ON CONFLICT (code) DO NOTHING`. Так коллизия случайного
кода не закрывает EntityManager, и повтор не превращается в гонку
«проверить, затем вставить». Все последующие правки `short_link` идут
через ORM с optimistic version.

`short_link_click` — append-only событие собственного HTTP-контура, а не
восстанавливаемый из внешнего источника факт. Два одинаковых
перехода обязаны остаться двумя строками, поэтому естественного ключа
и `ON CONFLICT` здесь нет: PK — суррогатный UUIDv7, запись — обычный DBAL
`INSERT`. Внешние ключи для скалярных UUID-ссылок не создаются:
Doctrine их не видит без ORM-ассоциаций и при следующем `migrations:diff`
предложит их удалить. Целостность держат отсутствие delete-сценариев
и явный порядок очистки тестовых данных; индексы на обоих ссылках
остаются.

Дни и границы месяца для статистики ссылок считаются в UTC. Это не
данные маркетплейса, поэтому к ним не применяется операционный пояс
Ozon `Europe/Moscow`; один и тот же UTC-календарь используется в API и UI.

Публичная граница дублируется на двух уровнях: nginx-виртуальный
хост пропускает в PHP только `/{base62(7)}`, а Symfony повторяет ограничения
хоста и пути. Fail-open при отказе записи клика оставляет warning с
`link_id`, кодом ссылки, `request_id` и самим исключением; сырые
заголовки и referer в журнал не попадают.

### Альтернативы, которые отвергли

- **Отдельный сервис (Go/Node)** — отвергли: изоляция нагрузки достигается
  rate-limit'ом в Traefik, а цена — новый язык, образ, задача CI и контейнер
  на машине, где памяти уже мало.
- **Готовый внешний сервис (Dub, Bitly)** — отвергли: собственный домен
  требует платного тарифа, данные о кампаниях уезжают наружу,
  а self-hosted Dub тянет стек тяжелее нашего продукта.
- **Счётчик переходов колонкой в short_link** — отвергли: конкурентная
  запись в строку, читаемую редиректом, и потеря разбивки по времени.
- **Redis-кэш code → url** — отвергли: оптимизация без замера.
- **301 вместо 302** — отвергли: кэш браузера убивает и статистику,
  и возможность сменить цель у уже розданной ссылки.
- **Асинхронная запись клика через Messenger** — отвергли: doctrine-транспорт
  пишет в тот же PostgreSQL, выигрыша нет, задержка есть.

### Последствия

**Получаем:**

- Ноль новых технологий, ~день работы, полный контроль над данными.
- Статистика в том же PostgreSQL, доступна обычным SQL.

**Платим:**

- Публичный неаутентифицированный эндпоинт делит пул php-fpm с продуктом:
  всплеск на lin.conwix.com влияет на app.conwix.com.
- Сырые клики растут без ограничения; политика хранения не определена.
- Точность счётчика зависит от качества фильтра ботов, который придётся
  подкручивать.

**На что обратить внимание потом:**

- p95 редиректа > 100 мс или срабатывания rateLimit в Traefik → выносим
  в отдельный пул php-fpm, затем в отдельный процесс.
- Строк в short_link_click > 5 млн или агрегат по дням > 200 мс →
  суточная роллап-таблица.
- Доля отфильтрованных как боты устойчиво > 50% → фильтр перестал
  различать, нужен другой признак.
