## ADR-005: Стратегия тестирования и подготовка данных в тестах

**Дата:** 2026-08-02
**Статус:** Accepted
**Модуль:** весь проект

### Контекст

Разработка ведётся одним человеком с активным использованием
LLM-кодогенерации. Основные риски продукта — молчаливые ошибки
в денежных расчётах, задвоение данных при повторном запуске обработчиков
и утечка данных между компаниями. Все три класса не видны глазами
и обнаруживаются клиентом.

Классификация тестов и способ подготовки данных пронизывают весь тестовый
код: смена подхода на трёхстах тестах — это переписывание всех трёхсот.

Уровень статического анализа относится к той же категории: подъём
на существующем коде подсвечивает тысячи нарушений, и выбор становится
плохим — неделя рефакторинга без продуктовой ценности либо массовое
подавление, после которого проверка мертва.

### Решение

**Уровни тестов** с раздельным запуском:

| Уровень | Зависимости | Что покрывает |
|---|---|---|
| unit | нет | денежная арифметика, аллокация, доменные политики, парсеры ответов площадок, метрики остатков |
| integration | контейнер + БД | репозитории и DQL, маппинг Doctrine, обработчики очереди, идемпотентность, применимость миграций |
| functional | HTTP-клиент | изоляция арендаторов, аутентификация и доступ, формат ошибок, соответствие ответа схеме |

Уровень определяется зависимостями: нужна БД — не unit.

Контрактные тесты внешних API — на зафиксированных фикстурах ответов,
без обращений в сеть.

Сброс БД между тестами — транзакция с откатом. Тесты, управляющие
транзакциями самостоятельно, помечаются отдельно и чистят за собой явно.

**Подготовка данных — только через Builder на каждую сущность.**
Билдер: имеет валидные умолчания для всех обязательных полей;
детерминирован (случайность только для полей, не влияющих на утверждения);
неизменяем — каждый метод возвращает новый экземпляр; разделяет операции
«собрать» и «сохранить»; позволяет задать компанию явно; создаёт
связанные сущности через их билдеры; не содержит бизнес-логики;
создаётся в том же изменении, что и сущность.

**Обязательное покрытие backend:** денежная арифметика и аллокация;
идемпотентность каждого обработчика очереди; изоляция данных между компаниями.

**Обязательное покрытие frontend:** чистые функции форматирования
и вычислений; изоляция кэша при смене компании; разбор ошибок API.
Тесты идут через мок-сервер, отвечающий по схеме OpenAPI.
Один сквозной сценарий Playwright.

**Все проверки блокируют merge с первого коммита:** PHPStan level 9,
Deptrac, TypeScript strict, синхронность OpenAPI, тесты.
Baseline PHPStan пустой.

CRUD, контроллеры, рендер компонентов, вёрстка — не тестируются.

### Альтернативы, которые отвергли

- **Плоский набор тестов без уровней** — отвергли: медленные тесты с БД
  смешиваются с быстрыми, полный прогон становится долгим,
  и его перестают запускать.
- **Глобальные фикстуры** — отвергли: тест зависит от данных, которых
  не видно в самом теле теста; правка фикстуры ломает десятки
  несвязанных тестов; связь «почему упало» теряется.
- **Unit-тесты с моками репозиториев** — отвергли: проверяют, что мок
  настроен правильно, а не что запрос работает.
- **Мягкий режим проверок с последующим ужесточением** — отвергли:
  подъём уровня на существующем коде никогда не становится приоритетом
  при наличии клиентов и очереди задач.
- **Массовое покрытие компонентов фронтенда** — отвергли: выдуманные
  поля и методы ловятся компилятором мгновенно и бесплатно;
  тест на то же самое стоит на порядок дороже.

### Последствия

**Получаем:**
- Unit-тесты выполняются за секунды и запускаются при каждом сохранении.
- Тест самодостаточен: все значимые данные объявлены в его теле.
- Механическая защита от трёх главных рисков продукта.

**Платим:**
- Builder на каждую сущность — код, требующий обновления
  при изменении сущности.
- Первые недели идут медленнее: сгенерированный код доводится
  до level 9 и strict вручную.

**На что обратить внимание потом:**
- Прогон integration-тестов дольше двух минут → пересмотреть
  стратегию сброса БД.
- Появление подавлений в baseline PHPStan → правило перестало работать,
  обсуждать, а не добавлять молча.
