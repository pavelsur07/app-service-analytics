## ADR-001: Выбор технологического стека

**Дата:** 2026-08-02
**Статус:** Accepted
**Модуль:** весь проект

### Контекст

Pre-PMF, первые клиенты. Команда: один разработчик (PHP, React) +
LLM-ассистированная разработка. Продукт — аналитика для селлеров
маркетплейсов: план-факт продаж, юнит-экономика, остатки.

Основная нагрузка — фоновый ingestion внешних API с ретраями и rate limit,
плюс денежные расчёты, обязанные сходиться с отчётами площадок.
Решающее ограничение — cognitive load и скорость доставки,
не производительность.

### Решение

Монолит на PHP 8.4 / Symfony 7.4 LTS под php-fpm, фронтенд React + TypeScript + Vite.
PostgreSQL — единственное хранилище данных. Асинхронная обработка через
Symfony Messenger на doctrine-транспорте, два транспорта:
`async_ingestion` и `async_calc`.

Redis — исключительно сессии, rate limit и распределённые блокировки.
Состояние пайплайнов, статусы и любые данные для отчётности — только PostgreSQL.

Деньги хранятся в целых копейках; float запрещён линтером.
Контракт фронт-бэк — OpenAPI, TypeScript-типы генерируются из схемы в CI.
PHPStan level 9 в CI с первого коммита.

Развёртывание: Traefik (TLS, маршрутизация) → Nginx (статика SPA + прокси)
→ php-fpm. Три поддомена: лендинг, приложение селлера, админка.
Внешние сервисы: S3, GlitchTip, SMTP провайдера.

### Альтернативы, которые отвергли

- **TypeScript end-to-end** — отвергли: разработчик бегло владеет PHP,
  а беглость в команде из одного человека перевешивает выгоду общего языка.
  Основную выгоду (типы, общие с фронтом) закрываем генерацией из OpenAPI.
- **Python + FastAPI** — отвергли: сильнее в decimal и аналитическом тулинге,
  но добавляет второй незнакомый язык при отсутствии сегодняшней проблемы,
  которую он решает.
- **RabbitMQ вместо doctrine-транспорта** — отвергли: новый компонент в проде
  ради потолка пропускной способности, до которого мы не дойдём на этой стадии.
  Упавшие сообщения в doctrine-транспорте видны обычным SQL.
- **API Platform** — отвергли: экономит код на CRUD, но её абстракции плохо
  генерируются LLM и дорого отлаживаются одним человеком.
- **Symfony 8.1 (текущая стабильная ветка)** — отвергли: поддержка минорной
  версии длится восемь месяцев, что означает обязательное обновление каждые
  полгода. При команде из одного человека это регулярный расход времени
  без продуктовой ценности. Дополнительно: ветка 8.x существует менее года
  и слабо представлена в обучающих данных моделей, что снижает точность
  генерации кода.
- **Symfony 6.4 LTS** — отвергли: исправления ошибок заканчиваются
  в ноябре 2026, то есть ветка на излёте.
- **PHP 8.3** — отвергли: активная поддержка закончилась в декабре 2025,
  остались только исправления безопасности.
- **PHP 8.5** — отвергли на текущей стадии: свежая ветка, тонкий корпус
  примеров и отставание части расширений; выгоды над 8.4 для этого
  проекта нет.
- **Отдельное аналитическое хранилище (ClickHouse)** — отвергли: объёмы
  не требуют, вторая СУБД означает бэкапы, мониторинг и дежурство,
  которых команда не потянет.
- **Traefik и Nginx как два прокси в цепочке с дублирующими функциями** —
  отвергли дублирование: у каждого своя зона, TLS и маршрутизация
  не повторяются на втором уровне.
- **Микросервисы, отдельный сервис ingestion** — отвергли: blast radius
  растёт, отладка становится распределённой, продуктовой выгоды ноль.

### Последствия

**Получаем:**
- Максимальную скорость на знакомом стеке, минимум сущностей в голове.
- Зрелый слой фоновых задач с ретраями из коробки.
- Реверсивность: транспорт очереди и аналитическое хранилище меняются
  позже без переписывания домена.

**Платим:**
- Новые возможности ветки 8.x недоступны.
- В ноябре 2027 предстоит один мажорный переход 7.4 → 8.4 LTS вместо
  серии мелких обновлений.
- Нет compile-time контракта между API и фронтом; полагаемся
  на дисциплину генерации из OpenAPI.
- Потолок аналитики на чистом PostgreSQL.
- Риск устаревших идиом Symfony в LLM-коде; компенсируется CLAUDE.md.
- Два языка в проекте и переключение между ними в течение дня.

**На что обратить внимание потом:**
- Накопление предупреждений об устаревших вызовах → переход на следующую
  LTS перестаёт быть механическим; держать на нуле.
- Ноябрь 2027, выход Symfony 8.4 LTS → планировать переход, не откладывая
  до конца поддержки 7.4 в ноябре 2028.
- Декабрь 2026, окончание активной поддержки PHP 8.4 → плановый переход
  на актуальную ветку PHP.
- p95 загрузки дашборда за 12 месяцев данных > 2 с при 100 активных
  компаниях → выносим витрины в ClickHouse.
- Ночной пересчёт > 2 часов → счётный слой отдельным воркером.
- Глубина очереди doctrine-транспорта устойчиво > 10k → переход на AMQP.
- Доля обращений «у вас неправильная цифра» не падает → проблема
  не в стеке, а в детализации разложения юнит-экономики.
