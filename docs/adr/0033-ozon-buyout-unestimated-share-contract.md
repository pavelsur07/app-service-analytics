## ADR-033: Ozon — доля заказов без оценки прогноза в контракте API

**Дата:** 2026-09-25
**Статус:** Accepted
**Модуль:** Ingestion
**Дополняет:** ADR-031 — закрывает названное там «отдельное решение
о контракте API» для доли штук без оценки.

### Контекст

После ADR-031 прогноз агрегата строится без штук без оценки, если их
не больше 10%. Цифра прогноза при этом выглядит так же, как построенная
по всем заказам: клиент не видит, что часть заказов в неё не вошла.
ADR-031 оставил вывод этой доли наружу отдельным решением о контракте.
Владелец согласовал вывод 2026-09-25.

### Решение

Поле `unestimatedRateBps` добавляется в три ответа отчёта выкупа:
строку SKU, сводку отчёта и точку дневного ряда.

- **Смысл:** доля заказанного количества агрегата без оценки прогноза
  по определению ADR-031 — `unestimated_quantity / ordered_quantity`.
- **Единицы:** basis points, округление до целого, как у остальных
  долей отчёта.
- **NULL:** только если в агрегате нет заказов.
- **Связь с порогом:** при значении больше 1000 прогноз агрегата NULL
  (ADR-031); поле при этом отдаётся — оно объясняет, почему прогноза нет.
- **Сводка** считается по суммам штук всех SKU, как прогноз сводки
  в ADR-031, а не усреднением долей строк.

Поле только добавляется; существующие поля и их смысл не меняются.
Экран показывает «прогноз по N% заказов», когда прогноз есть и доля
больше нуля.

### Альтернативы, которые отвергли

- **Не отдавать долю.** Цифра прогноза выдаёт себя за построенную по
  всем заказам — это расходится с требованием объяснимости расчёта.
- **Отдавать количество штук вместо доли.** Остальные показатели отчёта —
  доли в bps; количество пришлось бы делить на клиенте, а арифметика
  в компонентах не ведётся.

### Последствия

**Получаем:** клиент видит, по какой части заказов построен прогноз, и
почему его нет, когда неизвестного больше 10%.

**Платим:** ещё одно обязательное поле в трёх ответах; изменение
определения штуки без оценки меняет и его смысл.
