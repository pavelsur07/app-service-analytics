# Этап 2. Изменяющие сессионные запросы защищены от CSRF

## Задача и ожидаемый результат

Отклонять изменяющие запросы с соседнего/чужого origin до firewall login,
logout и контроллеров. Штатные seller/admin клиенты продолжают работать;
Bearer extension/internal сохраняют собственную аутентификацию.

## Контракт и реализация

- Все небезопасные методы `/api/`, кроме точных `/api/extension/` и
  `/api/internal/`, требуют `X-Conwix-Request: 1`.
- Если Origin указан — точное совпадение со списком своего контура,
  без wildcard и доверия Host/X-Forwarded-Host. `null` и соседние origin запрещены.
- Если Origin отсутствует — проверить origin Referer; при отсутствии обоих
  всё равно обязателен заголовок. CORS не разрешает чужие origin.
- Непустое тело требует MIME `application/json`; пустое тело допустимо.
  Неверная защитная информация — JSON 403, неподходящее тело — JSON 415.
- Subscriber kernel.request с приоритетом 16: после RouterListener (32),
  до Firewall (8). Не читать/создавать сессию для этой проверки.
- `SESSION_SELLER_ORIGINS` и `SESSION_ADMIN_ORIGINS` — явные списки среды;
  prod defaults только HTTPS conwix.com, dev содержит localhost/internal.
- API-клиенты seller/admin добавляют заголовок ко всем мутациям,
  включая POST без тела и DELETE. GET его не требует.
- Контракт OpenAPI описывает заголовок и ошибки; экспорт и TS генерируются.

## Файлы

Новый `Identity/Ui/EventListener/SessionRequestProtectionSubscriber.php`,
конфигурация services/env/prod compose, API-клиенты seller/admin, источник
OpenAPI, сгенерированные схемы, новые functional/MSW/e2e-тесты.
Общий test helper для сессионного клиента задаёт легитимный заголовок;
security regression-тесты используют исходный WebTestCase и задают
заголовки явно, чтобы helper не скрывал отсутствие защиты.
