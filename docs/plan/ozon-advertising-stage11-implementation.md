`GET /internal/observations`: обратный токен, страницы1..100, keyset по
company/account/policy, no-store, DB deadline2с. Только ID, версии, сроки и
классифицированный signal. Не выдаются деньги, runtime-document, ключи или
произвольные ошибки. Это операционное межарендаторное чтение собственной БД,
не новый API продавца или контракт PHP/UI.

## Пределы доказательств: этап11 остаётся открытым целиком

- До live нужны soak с меняющейся конфигурацией/publisher, физический SIGKILL,
  сбой/восстановление PostgreSQL и сетевые разделения. Close/Open pool и две
  логические реплики не называются отказом хоста или настоящим split-brain.
- Clock guard ловит шаг после старта, но не доказывает синхронизацию разных
  серверов, не исправляет исходный offset и не проверяет NTP. Внешний clock
  monitor/калибровка до запуска — незакрытый гейт.
- Endpoint замечает просрочки на стенде; production watcher/доставка тревог
  и топология контроллера не подключены. Наличие endpoint не означает
  действующий production-мониторинг.
- Rollback observe — отмена работников/отзыв grant/прекращение чтений.
  Реклама продолжает жить по собственным настройкам Ozon. Реальные остановки
  и rollback control не проверены и не обещаются.

## Общие квоты

`services/ozon-fetcher/internal/app/ingestion.go` передаёт Performance-клиенту
свой limiter из `internal/ratelimit/ratelimit.go`: cabinet/endpoint,
AIMD/Retry-After. Он не читает `ads_http_quota`. Новый контроллер резервирует
в собственной БД все попытки до HTTP, включая OAuth/ошибки. Совместного
суточного счётчика нет; два независимых потолка70000 не дают общий70000.
Неизвестные скрипты/ключи владельца нельзя считать нулевым потреблением.

Для следующего ADR предложены варианты, без внедрения здесь:

1. Узкий MVP: явные доли двум потребителям с проверяемой суммой/резервом;
   оба считают OAuth/redirect/retry/отклонённые попытки. Сначала уменьшается
   старая доля, потом увеличивается новая, чтобы релиз не дал временное превышение.
2. Динамическая ёмкость: один владелец резерва и протокол неизвестного исхода,
   без общей очереди и прямого доступа к чужим БД. Нужен принятый ADR новых границ.

Числа долей не утверждены как рабочие. Область общего счётчика Ozon,
организация и прочие потребители не установлены полностью. Источники/пределы
вывода — в паспорте. Этапы04/11/12 целиком не закрыты, Ads выключен.
