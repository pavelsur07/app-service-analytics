# Этап 1. Сброс пароля завершает доступ расширений

## Задача

Устранить P1: предъявленный до восстановления аккаунта Bearer-токен не
должен давать доступ после успешного сброса пароля. Закрыть гонку с выпуском
из запроса, уже прошедшего аутентификацию старой сессией.

## Ожидаемый результат

Смена пароля, погашение ссылок, отзыв всех токенов пользователя и аудит —
одна транзакция. Следующий запрос старым токеном получает 401. Токены
других пользователей и уже записанные сведения об отзыве сохраняются.
Новый вход новым паролем позволяет переподключить расширение.

## Решения и интерфейсы

- Пересмотр ADR-037/уточнение ADR-010 разрешён поручением начать общий план.
- Используется существующая advisory-lock граница password-reset по userId;
  та же блокировка добавляется для пользовательского выпуска extension.
- Добавить в `ExtensionTokenRepository` операцию
  `addForAuthenticatedUser(string $companyId, ExtensionToken $token, string $passwordHash): bool`.
  Она под блокировкой сравнивает сохранённый хэш пароля с хэшем пользователя,
  аутентифицированного в начале запроса, и только затем сохраняет токен.
  companyId первым параметром, соответствие компании токена проверяется.
- `IssueExtensionTokenAction::__invoke(Uuid $companyId, Uuid $userId,
  string $passwordHash): ?IssuedExtensionToken`; null означает устаревшую
  аутентификацию. HTTP-контроллер отвечает 401, открытый секрет не возвращает.
- Обычные `add/save` остаются для существующих портов и Builder;
  HTTP-выпуск использует исключительно защищённую операцию.
- Новых зависимостей, миграций, Facade и конфигурации очереди нет.
- Гарантия отзыва действует для аутентификации после commit сброса;
  уже выполняющийся до commit запрос не отменяется задним числом.

## Чек-лист готовности

- [ ] Каждый новый защитный сценарий увиден RED до production-исправления.
- [ ] Старые токены A получают 401, новый после входа работает.
- [ ] Отзыв охватывает все компании A и не касается B.
- [ ] Повтор сброса и прежний отзыв не переписывают след.
- [ ] Ошибка внутри транзакции не оставляет частичный результат.
- [ ] Выпуск старой сессией не переживает гонку со сбросом.
- [ ] Все обязательные проверки и три ревью завершены успешно.
- [ ] Результат подтверждён после поставки; ограничения записаны.

Невыполненное ревью блокирует готовность и merge даже при зелёных тестах.
Отозванные секреты при откате не восстанавливаются. Токены пользователей,
сбрасывавших пароль до выкладки, автоматически не отзываются.
