## Зафиксированные решения

- Один серверный токен Conwix, кэш и данные раздельно по компаниям.
  MPSTATS_API_TOKEN хранится в GitHub Actions Secrets; тестам он не нужен.
- Symfony владеет проектом, периодами, правами и проекцией прогресса.
  Python получает задания через внутренний контракт и владеет загрузкой.
  Доступа к БД монолита нет. Outbox и фоновые relay/polling без нового брокера.
- FBS=1, RUB, «Новинки: Неважно», пустые фильтры, целые календарные месяцы;
  текущий месяц только явно и до вчера. Europe/Moscow — календарь проекта.
- До 24 уникальных месяцев, один активный запуск проекта, один запрос
  подключения одновременно, ожидание месяца до 24 часов. Retry-After
  не сокращается ради deadline. Это ограничения Conwix, не квоты поставщика.
- Используемые снимки хранятся весь срок проекта; удаление и garbage collection
  вне MVP. Контроль бюджета хранения и текущего тарифа — до боевого включения.
- БД сервиса — технические состояния/метаданные, сырьё в своём S3-префиксе.
  Аналитические таблицы, фильтрация продаж, склейка и XLSX — следующие этапы.

## Проверенный контракт MPStats

POST `/api/analytics/v1/oz/category/items`: path/d1/d2/fbs/currency в query,
startRow/endRow/filterModel/sortModel в body. Сортировка revenue DESC/id ASC,
страницы по 500. На последней странице ответ endRow ограничен total.
GET `/api/user/report_api_limit`: подтверждён; доступно Ozon 10 000 для
тестового токена на момент проверки, не гарантия другого тарифа.
POST `/api/analytics/v1/oz/category/list`: 6 567 путей, целевая категория найдена.

202 — отложенный отчёт, 429 — квота/Retry-After. Их обработка закреплена
контрактом реализации; намеренно исчерпывать квоту или ломать авторизацию
не требуется. 401/403 при реализации тестируются на зафиксированном mock.
Неизвестные поля сохраняются. MCP не используется как побайтовое REST-сырьё.

[REST-проверка](product-research-ozon-rest-check.md): январь 2026, 102 страницы,
50 702 уникальных SKU; полное совпадение API JSON/CSV по ID, продажам и выручке.
[Ручная сверка](product-research-ozon-manual-csv-check.md): февраль 2025,
62 148 SKU; новый UI ZIP совпал по sales/revenue с API FBS=1 по каждой строке.
Предыдущий CSV соответствовал FBS=0; причина неизвестна, сохранён как диагностика.

[Карта колонок](product-research-ozon-columns.md): 41 поле ручного формата
найдено в REST; API CSV имеет 49 колонок, JSON 62 поля. Это разные профили.
Остатки, оборачиваемость и часть метаданных UI/API различаются; исходные
значения не меняются. percent_from_revenue зависит от страницы на проверенных
данных; будущая аналитическая доля рассчитывается отдельно по полному месяцу.

## Проверенный стек

CPython 3.14.10, Linux x86_64. Image:
`python@sha256:516b51cb9db2ef061e465c803e50f64361b82cefd91e525b889b967b83e83527`.
Прямые зависимости и полный hash-lock 71 пакета —
`services/product-research-ozon/stage0/requirements.in` и `requirements.lock`.
Resolver выполнен в контейнере с --ignore-installed, чтобы включить pip,
нужный транзитивному pip_api; lock проверен установкой --require-hashes.

FastAPI/Uvicorn/Pydantic; HTTPX; Psycopg binary; boto3; Alembic/SQLAlchemy Core
для миграций, без ORM runtime; pytest/Ruff/mypy/jsonschema/pip-audit/import-linter.
Версии — в lock, не дублируются отдельной устаревающей таблицей.

`make product-research-ozon-stage0-check` проверяет pip check/imports/audit,
затем Ruff check/format, mypy --strict и два unittest-сценария в контейнере
с --network none. Все проверки прошли. Схем БД нет — rebuild не запускался.

  служебных ключей подготовки экспорта и полей покупателей.

  определены в основном плане и реализуются вместе с API/worker на этапах 1–6.
  JSON-примеры API не выдаются за тест работающего сервиса.
