# Матрица спроса, этап 3 — сценарий и API

**Статус:** Реализовано в PR #244. Документ сохранён как справочный контекст
полноты загрузки, согласованного снимка и курсоров для тестов сценария.
Чек-лист ниже — исходный план завершённого этапа.

Общий план — `ozon-demand-matrix-report.md`; запросы — этап 2.

## Задача

Отдать матрицу фронтенду: `GET /api/companies/{companyId}/demand-matrix`
одним согласованным снимком данных, с определениями расчёта и признаком
неполной загрузки продаж.

## Решения этапа

- **Неполные данные — число подключений, а не дата.** В ответе
  `incompleteSalesAccounts`: подключения Ozon компании (кроме отозванных,
  как в «Остатках»), у которых продажи окна загружены не полностью
  (ADR-038): хотя бы у одного из 28 дней окна нет успешной отметки
  (отметки нет или последний прогон отказал), или успешная отметка
  вчерашнего дня поставлена до его окончания (полночь по Москве).
  День без отметки здесь — не загруженный, а не «судим по raw», как
  в ADR-038 для истории: отметки по продажам ставятся с 18.09.2026,
  окно 28 дней целиком позже, рескан продаж — 30 дней каждые сутки
  (ревью, замечание принято 2026-10-23). Вчерашний день перезагружается каждым тиком (окно 3 дня), поэтому
  отметка после полуночи — признак, что вчера загружено целиком. Сломанное
  подключение тоже неполное — и это правда. Заменяет `incompleteThrough`
  общего плана: дату «до какого дня полно» по нескольким подключениям
  честно не назвать.
- **Снимок данных один** — страница SKU, ячейки, колонки и отметки
  читаются в одной транзакции REPEATABLE READ, READ ONLY (как «Остатки»):
  иначе ночная загрузка между запросами дала бы ячейки, не сходящиеся
  со строками.
- **День отчёта** — сегодня по Москве; курсор привязан к дню и поиску,
  после полуночи страницу продолжают в дне курсора (как «Остатки»).
- **`search`** — до 100 символов (как поиск каталога SalesPlanning),
  длиннее — 422 `invalid_search`.

## Результат

- `Application/DemandMatrix/BuildDemandMatrixReportAction`,
  `DemandMatrixReport`, `DemandMatrixReportItem` (SKU + его ячейки);
- `Infrastructure/Query/DemandMatrix/DemandMatrixLoadsQuery` — отметки

- `Ui/Controller/ShowDemandMatrixReportController` с атрибутами Nelmio;
- `Ui/Response/DemandMatrix/*` — ответ, определения, SKU, ячейка, колонка;
- `packages/api-schema/openapi.json`, `src/schema.d.ts` — перегенерированы.

## Чек-лист приёмки

- [ ] функциональный тест: участник компании A получает 403 на матрицу B;
      матрица A не содержит данных B;
- [ ] функциональный тест разбора ввода: `limit=0`, `limit=201`,
      `search` длиннее 100, битый курсор, курсор другого поиска — 422;
- [ ] интеграционный тест сценария: ячейки приходят только своим SKU
      страницы; вторая страница по курсору продолжает первую;
      `incompleteSalesAccounts` — 0 при отметке вчера после полуночи,
      1 при отметке до полуночи, при отказавшем дне окна, без отметки;
      отозванное подключение не считается;
- [ ] `make lint stan deptrac test-unit test-int test-func api-types-check` зелёные.
