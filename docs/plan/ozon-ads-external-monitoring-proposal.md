## Рекомендация и выбор

Для первого кабинета предлагается внешний управляемый heartbeat-монитор
Better Stack с heartbeat period=30 секунд и grace=0, если выбранный тариф
разрешает эти настройки и стенд подтверждает доставку по целям N4.
Watcher внутри Conwix проверяет состояние локального контроллера
и отправляет внешний сигнал только при успешной проверке. Если упадёт watcher,
контроллер, узел или исходящая сеть, внешний сервис перестанет получать сигнал
и создаст тревогу. Закрытые endpoint контроллера не публикуются в интернете.

| Вариант | Возможности | Издержка |
|---|---|---|
| Better Stack, основной кандидат для N4 | Heartbeat: API допускает period от 30 секунд и grace от 0, инциденты/эскалация | Ещё один аккаунт; доступность нужных настроек на тарифе и стоимость проверить до подключения |
| Healthchecks.io, только с явно принятым более медленным обнаружением | Ожидание периодического сигнала, period/grace, уведомления | Минимум period=60 и grace=60: обнаружение отсутствия сигналов около 120 секунд плюс доставка; не закрывает исходную цель N4 |
| Собственный монитор на отдельном сервере | Контроль инфраструктуры и хранения | Отдельный узел, обновления, резервирование и наблюдение за самим монитором |

На дату проверки публичный [тариф Healthchecks.io](https://healthchecks.io/pricing/)
Hobbyist — $0, 20 проверок и 100 записей журнала на проверку. При сигнале раз
в минуту этого журнала недостаточно для суточного доказательства N3: результаты
стенда и история проверок сохраняются отдельно. Регистрация/оплата не выполнялись.

Первичный канал предлагается email ответственного, дополнительный канал
подключается после выбора владельца. Адреса и интеграционные токены не угадываются
по исходникам проекта и не публикуются в этом документе. Контакты пока не заданы.

Основание отдельного выбора: [CLAUDE.md — единственная точка согласования](../../CLAUDE.md#единственная-точка-согласования)
требует согласовать «новую внешнюю зависимость, которой в плане не было».
Реализация закрытой топологии и локальные проверки могут продолжаться автономно;
создание аккаунта выбранного провайдера ждёт решения по этому предложению.

## Контракт сигнала и защита данных

Цели N4 сохраняются: полный обход ≤10 секунд, тревога о просрочке ≤60 секунд
от next_tick с учётом порога 35 секунд. Предлагаемый локальный цикл watcher —
не реже 10 секунд; внешний heartbeat — period=30 секунд, grace=0. Нужно измерить
доставку end-to-end; поддержка параметров API не доказывает заданную задержку
уведомления. Это отдельные локальные проверки, интервал Ozon X не меняется.

Первоначальная рекомендация Healthchecks.io пересмотрена после проверки
[минимумов Management API v3](https://healthchecks.io/docs/api/): timeout и grace
оба не меньше 60 секунд. Модель 60+60 не удовлетворяет исходной цели N4 при
потере узла. Её нельзя принять молча или выдать за быструю защиту. Better Stack
остаётся кандидатом, а не уже проверенным решением; параметры фиксируются до стенда.

Сигнал — пустой HTTPS-запрос на секретный URL. Не отправляются company/account IDs,
кампании, суммы, токены Conwix/Ozon, тела API, логи или тексты произвольных ошибок.
Уникальный URL считается секретом: вне Git, аргументов журналируемых команд,
Sentry breadcrumbs, access/error logs и сообщений ревью. Отдельный секрет на
production и стенд; при утечке обязательна ротация. TLS проверяется штатно.

Успешный HTTP health сам по себе недостаточен. Watcher должен различать:

1. Живость управления: доступность собственной БД, свежесть разрешённой
   конфигурации, продвижение цикла работников, отсутствие просроченных локальных
   дедлайнов/зависших lease и работоспособность публикации наблюдений.
2. Качество данных пилота: плановый срок чтения относительно next_due/X,
   подтверждённая дата статистики, качество источников и состояние публикации.

Для них предлагаются отдельные проверки/сигналы. Пауза Ozon по квоте или 429
не выдаётся за падение всего сервиса; проблемы отдельного кабинета показываются
отдельно. При отсутствии live-кабинетов явно проверяется режим ожидания, а не
выдуманное успешное получение статистики. После X/паузы наличие работающего
локального цикла не объявляется свежими данными.

Проектные endpoint/поля состояния сначала сверяются с существующим Go engine
и контрактами. Публичный диагностический endpoint, прямой доступ внешнего
провайдера к БД или дополнительные секреты Ozon ему не выдаются.

## Ввод и приёмка

Оба [Healthchecks.io](https://healthchecks.io/docs/) и
[Better Stack](https://betterstack.com/docs/uptime/cron-and-heartbeat-monitor/)
начинают с нового/pending heartbeat. Создание записи без первого успешного
сигнала и контрольного пропуска не доказывает включённую тревогу.
Period/grace задаются по [контракту Healthchecks.io](https://healthchecks.io/docs/configuring_checks/)
либо [API Better Stack](https://betterstack.com/docs/uptime/api/create-a-hearbeat/).

- [ ] Владелец выбрал провайдера и канал/получателя; подключение входит в согласованный план.
- [ ] Эксплуатационная конфигурация хранится в ops/, порядок применения в ops/README.md.
- [ ] Секрет создан/установлен без попадания в Git, ревью и журналы; ротация описана.
- [ ] Контроль живости и качества данных различается, idle/paused не выдают ложный успех.
- [ ] Проверены успешный сигнал, отсутствие сигнала и восстановление на изолированном стенде.
- [ ] При остановке контроллера/watcher/узла тревога приходит вне узла Conwix.
- [ ] Проверено отсутствие утечек и новых обращений к Ozon при работе watcher.
- [ ] Проверены ошибки БД, устаревшая конфигурация, зависший worker, просроченный next_due и недоступность publisher.
- [ ] Подтверждена доставка ответственному и отдельный порядок реагирования; отправку не заменяет запись об инциденте.
- [ ] Зафиксированы фактическая задержка, поведение при недоступности провайдера и пределы приёмки.
- [ ] N4 закрывается только по собранным доказательствам; данное предложение само его не закрывает.

В observe уведомление не останавливает реальные кампании и не предотвращает
перерасход при отказе Conwix. Для будущего управления нужна отдельная доказанная
защита и исполнитель команд; внешний монитор эту гарантию не создаёт.
