# Stage 1 — скелет и dev-окружение

## Цель

Репозиторий по `structure.md` и локальное окружение, в котором два
фронтенда получают ответ от API и показывают его на экране.

## Входит

**Репозиторий**

```
app-service-analytics/
├── CLAUDE.md, README.md, Makefile, docker-compose.yml
├── docs/                        уже есть
├── api/                         Symfony, минимальная установка
├── apps/seller/                 React + Vite
├── apps/admin/                  React + Vite
└── packages/api-schema/         пока пустой
```

**Окружение в Docker**

| Контейнер | Роль |
|---|---|
| traefik | TLS локально, маршрутизация по поддоменам |
| nginx | статика и проксирование на php-fpm |
| php-fpm | Symfony |
| php-cli | composer, консольные команды, тесты |
| postgres | база |
| redis | сессии и лимиты |
| node | сборка и dev-сервер фронтендов |

Локальные адреса: `app.conwix.localhost`, `admin.conwix.localhost`.
Домены именно такие, а не `localhost:5173` — иначе поведение кук,
областей видимости и маршрутизации отличается от боевого,
и разница вылезет при первой выкладке.

**Приложение**

- Symfony с двумя эндпоинтами-заглушками: один для приложения селлера,
  один для админки. Каждый отдаёт имя приложения, версию сборки
  и время ответа. Без БД, без авторизации, без модулей.
- Два React-приложения, каждое показывает полученное на стартовом экране.
- Каркас модулей `Shared`, `Identity`, `Ingestion` — только папки слоёв,
  без классов.

## Не входит

- База данных в потоке запроса: контейнер поднят, миграций и сущностей нет.
- Аутентификация в любом виде.
- Полный набор зависимостей и проверок — это Stage 2.
- Разметка, стили, дизайн-система. Стартовый экран — заголовок и данные
  от API без оформления.
- Общие компоненты между двумя фронтендами. Пока их два независимых,
  выделять общее не из чего.

## Критерий готовности

На чистой машине после `git clone`:

1. `make init` отрабатывает без ручных шагов.
2. Открывается `app.conwix.localhost` — виден стартовый экран
   с данными от API приложения селлера.
3. Открывается `admin.conwix.localhost` — виден стартовый экран
   с данными от API админки, и данные **отличаются** от первого.
4. Остановка контейнера с API меняет экран на состояние ошибки,
   а не на белую страницу.

Четвёртый пункт добавлен намеренно: обработка недоступности API,
заложенная сейчас, стоит десять минут, а добавленная позже — правка
всех экранов.

## Риски

**Traefik и локальные поддомены** — самая вероятная точка задержки.
Если за разумное время не заводится, допустимо временно обойтись
записями в `hosts`; отказываться от поддоменов в пользу портов нельзя.

**Соблазн сразу подключить БД и авторизацию.** Ни то, ни другое
не нужно для критерия готовности и добавляет источники отказа
в этап, где проверяется сама сборка окружения.
