## Изменение и доказательства

get/set/clear не обращаются к native storage до успешного ограничения.
Отказ инициализации закрывает все операции. Инициализация запускается при
загрузке worker и popup, слушатели регистрируются синхронно.

- Unit RED: 2 теста подтвердили преждевременное чтение/запись и успешные
  операции при отказе ограничения. После исправления — GREEN.
- Extension: 71 тест, typecheck/lint/knip/build — успешно.
- Настоящий Chromium: content script из собранного manifest не читает
  connection, worker/popup читают, подключение сохраняется после рестарта.
- Дополнительно браузер перезапускается с копией manifest без worker:
  ограничение продолжает действовать до какой-либо повторной инициализации.
- Проверка чувствительности: в отдельной копии сборки уровень изменён на
  TRUSTED_AND_UNTRUSTED_CONTEXTS; браузерная проверка падает именно на чтении
  connection content script. Исходная сборка не изменялась этим экспериментом.
- `make test-e2e`: 7 сценариев успешно, затем native extension check успешно.
  Native проверка включена в эту обязательную CI-цель.

Минимум Chrome 140, версия расширения 0.3.1. Chrome 102 — появление метода
для session; Chromium 139 ещё явно отвергает другие storage areas.

## Готовность поставки и ограничения

Нужны зелёный окончательный CI и выпуск артефакта extension 0.3.1.
Старая установленная версия остаётся риском до обновления. При первом
обновлении со старой версии данные защищены после первой успешной установки
ограничения; уже доступный/украденный до неё токен задним числом не защищён.
Выпуск артефакта CI не равен публикации в Chrome Web Store и обновлению
всех клиентских браузеров. Вредоносное ПО на устройстве/trusted worker
остаётся за пределами защиты от content scripts.
