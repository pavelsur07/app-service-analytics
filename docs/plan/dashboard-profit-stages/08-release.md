## Подробный план

1. Сверить diff всей ветки с планом, обновить документацию девятого виджета и журнал этапов; не включать чужие файлы.
2. Прогнать итоговые backend-гейты, unit/integration/functional, контракт и seller-гейты. Подтвердить audit и полный E2E; не повторять уже подтверждённый неизменённый набор без причины.
3. Подготовить пакет высокого риска по шаблону репозитория, приложить применимые ADR и контекст исходных расчётов.
4. Выполнить два независимых прохода Codex CLI в новых отдельных сессиях: 5A (правила/ADR) и 5B (дефекты, деньги, изоляция). Прямое указание владельца: «ревю выполняй codex cli в отдельной сессии» — для этой задачи это заменяет проход Claude.
5. Разобрать замечания, исправить принятые, повторить затронутые проверки и ревью изменённого кода. Зафиксировать количество уникальных принятых замечаний.
6. Создать PR, дождаться обязательного зелёного CI итогового HEAD и завершённого ревью; выполнить merge и выкладку по постоянному разрешению проекта.
7. Проверить результат на production через разрешённый серверный контур, без запросов к Ozon и изменения клиентских цен; опубликовать фактический отчёт и ограничения.

Клиентская сверка и производительность на реальных объёмах не подтверждены; локально проверены синтетические данные и паритет с существующим отчётом. Недоступное ревью, красный CI или ошибка выкладки не считаются успешным завершением.
