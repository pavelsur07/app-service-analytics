# Этап 7. Сверка расчётов и план запросов

## Подробный план

1. Добавить Builder-тест паритета: сумма прибыли SKU плюс расходы кабинета совпадает с dashboard. Проверить отрицательный и положительный рекламный остаток, исправление цены и возврат другого периода.
2. Выполнить интеграционный набор и статические проверки тестов. Это дополнительные проверки существующей реализации; искусственный RED или изменение рабочего расчёта ради теста не нужны.
3. Снять EXPLAIN (ANALYZE, BUFFERS) QueryBuilder через dev-соединение на синтетических E2E-данных для короткого и длинного окна; сохранить планы и время локально.
4. Указать масштаб выборки и ограничения замера. Наличие только нескольких синтетических начислений не подтверждает производительность на объёмах клиента.
5. Клиентскую сверку отметить невыполненной: конкретная компания/отчёт не предоставлены. Внешние API и production-данные не требуются для локальной проверки.
