# Матрица спроса, этап 2 — запрос матрицы

Общий план — `ozon-demand-matrix-report.md`; этап 1 — `DemandSql`.

## Задача

SQL-слой матрицы: страница SKU с итогами, ячейки SKU × кластер покупателя
для этой страницы и список кластеров-колонок. Все расчёты — PostgreSQL
на целых и `numeric`, спрос — только из `DemandSql::linesCte()`.

## Решения этапа

- **Дни нулевого остатка — общий CTE.** `stock_runs`, `complete_days`,
  `requested_count`, `positive_count` выносятся из `StockPlacementSql`
  в `Query/Demand/StockoutSql::cte()`; «Остатки» и матрица считают
  «день без товара в кластере» одинаково. Ответ «Остатков» не меняется.
- **Пустая ячейка с дефицитом возвращается.** Ячейка отдаётся, если
  в ней были заказы за 28 дней **или** дни нулевого остатка: пустая ячейка,
  где товара не было, — не «нет спроса», а «спрос неизвестен».
- **Строки — SKU с заказами за 28 дней.** SKU без заказов совсем
  (нет товара нигде) — в «Остатках» (`no_sales`/`unknown_stock`), не здесь.
- **Колонки** — кластеры покупателя со спросом компании за 28 дней,
  по убыванию заказов; `null` — «кластер не указан», последней. Колонок
  у Ozon ~30, отдаются с ограничением `MAX_CLUSTERS = 200`.
- **Поиск** — подстрока SKU, артикула или названия (`ILIKE … ESCAPE '!'`,
  как `AccountCatalogSkuSearchQuery`).

## Результат

`api/src/Ingestion/Infrastructure/Query/DemandMatrix/`:

- `DemandMatrixSql` — окна (`WINDOW_DAYS = [7, 14, 28]`), `MIN_SALES = 10`,
  `ROUNDING = 'half_away_from_zero'`, CTE `by_sku`/`by_cell`, `parameters()`;
- `DemandMatrixSkuQuery` + `DemandMatrixSkuRow` + `DemandMatrixCursor` —
  страница SKU: `orders7/14/28`, `unknownClusterOrders28`,
  `demandMilliPerDay`, `trendBps`, артикул и название из каталога;
  keyset по `(orders28 DESC, sku ASC)`, `limit + 1`;
- `DemandMatrixCellQuery` + `DemandMatrixCellRow` — ячейки для списка SKU
  страницы одним запросом: `orders7/14/28`, `demandMilliPerDay`,
  `shareBps`, `trendBps`, `stockoutDays`;
- `DemandMatrixClustersQuery` — колонки.

Формулы: спрос в день = `ROUND(1000 × q28 / 28)` тысячных;
доля = `ROUND(10000 × q28_ячейки / q28_SKU_по_известным)`;
тренд = `ROUND(10000 × (q7 / 7) / (q28 / 28))`, `null` при `q28 < 10`.

## Чек-лист приёмки

- [ ] каждый запрос принимает `companyId` первым параметром, читает только её строки;
- [ ] интеграционные тесты (данные — Builder-ами):
  - [ ] заказ со склада кластера A покупателю в B — в ячейке B;
  - [ ] отменённые не считаются;
  - [ ] окна: вчера входит в 7/14/28, 8 дней назад — в 14 и 28, 15 дней назад — только в 28, 29 дней назад и сегодня — никуда;
  - [ ] «кластер не указан»: в `unknownClusterOrders28` и колонке `null`, в знаменатель доли не входит; доли по известным кластерам дают 10000;
  - [ ] тренд `null` при 9 заказах за 28 дней, считается при 10; рост 7-дневного спроса даёт `> 10000`;
  - [ ] дни нулевого остатка: полный снимок без строки кластера — день дефицита; ячейка без заказов с дефицитом возвращается; без полного снимка дефицита нет;
  - [ ] keyset: две страницы без пропусков и повторов; поиск по артикулу;
  - [ ] данные другой компании не видны ни в SKU, ни в ячейках, ни в колонках;
- [ ] `BuildStockPlacementReportActionTest` зелёный без правки ожиданий;
- [ ] `make lint stan deptrac test-unit test-int test-func` зелёные;
- [ ] `EXPLAIN ANALYZE` на проде (только чтение): `sales_fact` по
      `idx_sales_fact_company_business_date`, время страницы — в отчёт.

## Проверка

Тесты выше и план запроса на боевой базе крупнейшей компании.
