## Реализация и TDD

Пароль возвращает HTTP 202 и ограниченный пятиминутный challenge.
Единый guard запрещает системные данные и действия до TOTP/резервного
кода, включая прежние сессии. Завершение MFA меняет session ID.
Секрет зашифрован sodium с отдельным HKDF context; 10 случайных 128-битных
резервных кодов сохраняются только SHA-256 хэшами. PostgreSQL advisory lock,
условное погашение и транзакционный аудит защищают от повтора и конкуренции.
Смена версии фактора отменяет прежние сессии и набор кодов. Восстановление
при полной потере факторов — CLI с SuperAdmin-актором, внешней проверкой
личности и несекретной ссылкой в аудите; dry-run по умолчанию.

Защитные тесты начаты до реализации. Зафиксированы RED→GREEN для partial
и legacy-сессий, enrollment, RFC6238, replay, recovery, expiry, лимитов,
reset, шифрования и телеметрии. Двухпроцессный integration-тест подтверждает
ожидание реальной блокировки и единственное погашение recovery-кода.
Ошибка аудита откатывает активацию и выпуск кодов. UI покрыт существующим
единственным admin E2E: настройка, перевыпуск, вход и отказ повторного кода.
Sentry явно запрещает request body capture; scrubber удаляет секреты и
массивы recoveryCodes, сохраняя диагностические коды ошибок.
