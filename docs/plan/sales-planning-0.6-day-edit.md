# Этап 0.6 — правка дня и удаление SKU из черновика

Общий план — `sales-planning-stage0.md`, решения — ADR-040 п. 7, 8, 10, ADR-041.

## Результат

В черновике можно:

1. поправить штуки и цену одного дня одного SKU — например, акция
   с другой ценой; итог периода пересчитывается из дней;
2. убрать SKU из плана целиком.

Каждое действие пишет аудит с точными значениями дней до и после.

## API

| Метод | Путь | Тело / параметры |
|---|---|---|
| PUT | `…/sales-plans/{planId}/days` | `{version, marketplaceSku, date, quantity, priceMinor?}` → `{version}`; без цены у дня остаётся прежняя |
| DELETE | `…/sales-plans/{planId}/skus/{marketplaceSku}?version=N` | → `{version}` |

Отказы — как у ввода SKU: 404 нет плана; 409 `version_conflict`
или `sales_plan_not_editable`; 422 — тело, день вне периода, SKU нет
в плане, потолки.

## Решения внутри этапа

- **Запись — DBAL**, как ввод SKU (ADR-041): правка дня — `UPDATE`
  одной строки по естественному ключу, удаление SKU — `DELETE` строк SKU.
  Шапка (версия) и журнал — ORM, первыми в той же транзакции.
- **Строки черновика удаляются** — ADR-040 п. 8 разрешает убрать SKU
  из черновика; прежние значения дней остаются в журнале, поэтому
  удаление не теряет «было» (ADR-011).
- **Потолки**: штуки дня ≤ 1 000 000, итог SKU после правки ≤ 1 000 000
  (тот же предел, что у ввода за период, — выручка плана остаётся
  в bigint), цена — потолок `SalesPlanLine::MaxPriceMinor`.
- **SKU и день, которых нет в плане** — 422, а не создание строки:
  правка дня не добавляет SKU (для этого — ввод за период).
- **Аудит**: `sales_plan.day_changed` — «было/стало» одного дня;
  `sales_plan.sku_removed` — «было» все дни SKU, «стало» `null`.

## Фронтенд

- Группировка «день»: клик по ячейке черновика открывает правку дня
  под таблицей: штуки предзаполнены, РРЦ — пусто значит «не менять»
  (цену дня экран не выводит: деление выручки на штуки — арифметика
  над деньгами в компоненте). Версия фиксируется при открытии формы.
- В строке SKU черновика — «Убрать» с подтверждением.
- Версия — из последнего ответа; конфликт — перечитывание.

## Тесты

- Integration: правка дня — значение, версия, итог SKU, аудит до/после;
  день вне периода и SKU вне плана — отказ; потолок итога; удаление SKU —
  строки ушли, аудит с днями; версия — 409; не черновик — отказ.
- Functional: изоляция (план чужой компании — 404 для обоих маршрутов),
  разбор тела (дата, дробная цена, нет версии).
- Vitest: ключи не меняются; чистые функции, если появятся.
