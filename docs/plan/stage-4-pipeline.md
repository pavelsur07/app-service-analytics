## Цель

Конвейер, который прогоняет только затронутое, кэширует зависимости
и слои образов, версионирует сборки и делает версию видимой в приложении.

## Входит

**Фильтры по путям**

| Изменено | Что запускается |
|---|---|
| только `apps/seller` или `apps/admin` | typecheck, ESLint, Vitest, сборка фронтенда |
| только `api` | PHP-CS-Fixer, PHPStan, Deptrac, PHPUnit всех уровней |
| `docs`, `README` | ничего, кроме проверки оформления |
| `packages/api-schema` | обе половины |
| миграции, `docker-compose`, конвейер | всё целиком |

**Всегда, независимо от изменений**

- Проверка синхронности OpenAPI-схемы и сгенерированных типов.
- `composer audit` и `npm audit`.
- E2E-сценарий на собранном приложении.

Это исключение из правила фильтров и оно принципиально. Именно изменение
бэкенда ломает фронтенд, и пропуск контрактной проверки обнулит смысл
всей экономии: будем экономить минуты, чтобы ловить рассинхронизацию
руками. Стоит она секунды.

**Кэширование**

- Зависимости Composer по хешу `composer.lock`.
- Зависимости npm по хешу `package-lock.json`.
- Слои образов Docker.
- Результат PHPStan между запусками.

Ключ кэша строится по файлу блокировки, а не по ветке: иначе кэш
не переиспользуется между ветками и смысл теряется.

**Версионирование**

- Тег сборки формируется из короткого хеша коммита и номера сборки.
- Тег попадает в образ, в собранный фронтенд и в эндпоинт версии.
- На стартовом экране заглушки видна версия — та же, что в теге.

Последнее делает разбор «а что вообще развёрнуто» вопросом одного взгляда.

## Не входит

- Развёртывание. Конвейер заканчивается публикацией образа.
  Куда он выкладывается — открытый вопрос, отдельный разговор.
- Внешнее ревью как шаг конвейера. Ответ языковой модели
  недетерминирован; гейт сборки на нём ставить нельзя. Ревью — работа
  до коммита.
- Автоматическое применение миграций. Миграции — единственный
  необратимый шаг, всегда с человеческим решением.
- Оповещения о падениях за пределами штатных средств.

## Критерий готовности

1. Коммит, меняющий только фронтенд, не запускает PHPUnit — и это видно
   в журнале конвейера.
2. Коммит, меняющий только API, не запускает typecheck, ESLint, Vitest,
   knip и сборку фронтенда.

   **Исправлено при реализации.** В исходной формулировке стояло
   «не запускает Playwright», что противоречило разделу «Всегда,
   независимо от изменений» этого же документа: e2e перечислен там.
   Одновременно выполнить оба требования нельзя. Разрешено в пользу
   «всегда»: ломает фронтенд именно правка бэкенда, и e2e нужнее всего
   как раз на api-коммите. Критерий переписан на те проверки, которые
   на нём действительно пропускаются.
3. Изменение схемы API без регенерации типов роняет конвейер
   независимо от того, что ещё менялось.
4. Повторный прогон без изменения файлов блокировки использует кэш —
   заметно по времени.
5. Собранный образ помечен тегом; эндпоинт версии и стартовый экран
   показывают его.
6. `make ci-local` воспроизводит тот же набор проверок локально.

## Риски

**Фильтры по путям — источник ложной зелёности.** Изменение в `api`,
ломающее фронтенд, при неверно настроенных фильтрах пройдёт незамеченным.
Отсюда правило «контрактные проверки всегда». Проверять эту гарантию
пунктом 3 критерия — обязательно, а не по желанию.

**Кэш, который никогда не инвалидируется**, хуже отсутствия кэша:
он даёт зелёный конвейер на устаревших зависимостях. Ключ строится
по содержимому файлов блокировки, а не по времени или ветке.

**Экономия минут против сложности конвейера.** На проекте с одним
разработчиком полный прогон занимает единицы минут. Если фильтры
начнут требовать заметной поддержки, дешевле гонять всё.
