# product-research-ozon — этап 1

Статус: в работе. Основание — ADR-050 и этап 1 общего плана.

## Цель и границы

Получить запускаемый в dev Python-сервис с проверяемыми границами доступа,
не обращающийся к MPStats. Symfony остаётся единственным входом пользователя.
Новых зависимостей и брокеров нет: используем закреплённый стек этапа 0.
Production-включение загрузки в этот этап не входит.

Внутренние операции категорий, приёма запуска, прогресса и метаданных снимка
описываются v1-контрактом. До реализации соответствующих этапов они отвечают
503 `not_available`: никакого 202 без сохранённого задания и никакого пустого
справочника вместо ещё не загруженного. PHP проверяет общие примеры контрактов;
пользовательский контроллер и бизнес-модуль Symfony пока не создаются.

## Последовательность

1. **Контракт и Red.** Опубликовать schema.json, общие валидные/невалидные
   примеры и описание HTTP. Написать тесты авторизации, валидации, readiness,
   безопасного журнала и S3 scope до реализации. Зафиксировать Red.
2. **Приложение.** Тонкий FastAPI API, проверяемая конфигурация, отдельные
   токены направлений (>=32 символов, не совпадают), ограниченный JSON body,
   постоянное время сравнения. `/health` — процесс; `/ready` — БД, миграции,
   доступ к S3. Документация API и публичные маршруты отключены.
3. **Инфраструктура.** Свои роль/БД dev+test с pg_hba, отдельный S3-порт,
   ключ собирается из проверенных company/connection/snapshot ID. Объекты
   неизменяемы. Alembic baseline и явные migrate/migrations-check, без
   автоматической миграции при старте. Никаких таблиц будущих заданий.
4. **Контейнер/гейты.** Закреплённый образ, непривилегированный пользователь,
   internal-сеть без публикации порта, worker выключен. Lint, mypy strict,
   архитектурные границы, unit/contract/integration, audit/build/smoke в Make/CI.
5. **Приёмка и доставка.** Чистый rebuild локальной test-инфраструктуры,
   обязательные проверки, независимые 5A/5B при недоступном Claude, разбор
   замечаний, PR, зелёный CI, merge и штатная выкладка монолита. Python
   production-контейнер остаётся вне включения до следующих этапов.

## TDD и критерии приёмки

- [x] Без Bearer, с неверным/обратным/дублирующимся заголовком — 401;
  валидация тела/параметров не раскрывается до авторизации.
- [x] Короткие/совпадающие токены и неверная конфигурация отклоняются без секрета
  в ошибке. Worker по умолчанию не делает работы; включение преждевременно
  явно отклоняется.
- [x] PHP и Python принимают одинаковые примеры и отвергают пропуски,
  неверные UUID/даты/лимиты/лишние поля. Списки ограничены, cursor задан явно.
- [x] Все внутренние операции включают company_id; чужой scope не подставляется
  из глобального состояния. Нет сырья, денежных сумм и секретов в ответах.
- [x] Корректный запрос получает 503 `not_available` по общей схеме ошибки;
  readiness инфраструктуры не обещает доступность будущей загрузки.
- [x] `/ready` возвращает 503 при отказе БД/S3 или неприменённой ревизии;
  `/health` при этом жив. Ошибка зависимости не попадает в ответ/лог.
- [x] Роль сервиса реально подключается только к своим БД, не к app/app_test
  или БД другого сервиса. S3-порт не принимает готовый ключ и отклоняет
  ссылку другой компании до обращения к S3; повторная запись не затирает объект.
- [x] JSON-журнал содержит service/company_id/job_id/trace_id/resource_type,
  outcome/error_class/duration_ms; заголовки, URL/query, произвольные ошибки,
  входные тела и секреты не журналируются, access log отключён.
- [x] Архитектурная проверка обнаруживает запрещённый импорт инфраструктуры
  из чистого кода; runtime не использует SQLAlchemy ORM и БД монолита.
- [x] Baseline upgrade/check/down/upgrade проверены с пустой БД. Миграции
  не запускаются автоматически. Проверка схемы включена в db-rebuild-check.
- [x] Образ запускается non-root, сервис не имеет host ports/Traefik/egress;
  smoke проверяет /health, /ready, 401 и 503 без live API.
