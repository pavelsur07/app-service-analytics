# Stage 3 — Makefile

## Цель

Одна команда на действие. Всё, что делается руками — подъём окружения,
миграции, тесты, линтеры, генерация схемы, запрос ревью — вызывается
из Makefile и оттуда же попадает в раздел «Команды» `CLAUDE.md`.

Смысл не в удобстве набора. Смысл в том, что у человека и у агента
одна команда на действие, а не две разные, расходящиеся со временем.

## Состав целей

**Окружение**

```
init              полный подъём с нуля: down-clear, build, up, install, migrate
up / down         запуск и остановка
down-clear        остановка с удалением томов
build / pull      сборка и обновление образов
ps / logs         состояние и журналы
```

**Backend**

```
api-shell         вход в контейнер php-cli
api-install       composer install
api-migrate       применение миграций
api-migrate-test  применение миграций в тестовой базе
api-console       произвольная консольная команда: make api-console CMD="..."
```

**База**

```
db-wait           ожидание готовности Postgres
db-test-create    создание тестовой базы
db-test-rebuild   полное пересоздание тестовой базы
```

**Тесты**

```
test              все уровни
test-unit         без БД
test-int          с БД
test-func         через HTTP
test-e2e          Playwright
test-cov          покрытие
```

**Проверки**

```
lint              PHP-CS-Fixer в режиме проверки
lint-fix          автоисправление
stan              PHPStan
deptrac           границы модулей
audit             composer audit + npm audit
front-typecheck   tsc --noEmit
front-lint        ESLint
front-knip        неиспользуемый код
```

**Контракт API**

```
api-doc-export    выгрузка OpenAPI в файл
api-types         регенерация TypeScript-типов
api-types-check   проверка, что закоммиченные типы совпадают со схемой
```

**Фронтенд**

```
front-install     установка зависимостей обоих приложений
front-dev         dev-серверы
front-build       production-сборка
```

**Ревью**

```
review-prepare    сборка пакета: диф, правила, релевантные ADR
review-codex      прогон Codex CLI, ответ в var/review/codex.md
review-kimi       прогон Kimi CLI,  ответ в var/review/kimi.md
review            оба сразу
```

**Сводная**

```
ci-local          всё, что гоняет конвейер, одной командой
```

Последняя цель нужна, чтобы красный конвейер можно было воспроизвести
локально, не разбирая, из каких шагов он состоит.

## Что взято из примера

- Определение команды compose с запасным вариантом для старой версии.
- Разделение подготовки тестовой базы и запуска тестов: подготовка
  делается один раз, тесты гоняются многократно.
- Цель полного пересоздания тестовой базы на случай, когда она испорчена.
- Выгрузка OpenAPI через консольную команду, а не по HTTP: не требует
  поднятого веб-сервера и авторизации.
- Проверка типов сравнением заново сгенерированного файла
  с закоммиченным — то, что пойдёт в конвейер.
- Отдельные цели под окружение внешнего инструмента с явным `PATH`,
  когда он работает вне Docker.

## Что из примера не берём

| Из примера | Почему |
|---|---|
| `site-fixtures`, загрузка фикстур | глобальные фикстуры запрещены ADR-005 |
| `check-ui-kit`, `check-uikit-react-mapping` | дизайн-системы в виде HTML+CSS у нас нет |
| Цели под Twig-линт | Twig только для писем |
| Префикс `site-` | у нас два фронтенда и API; префиксы `api-`, `front-`, `db-` |
| Закомментированные строки внутри целей | молчаливо не выполняются и вводят в заблуждение |

## Критерий готовности

1. На чистой машине `git clone` и `make init` дают работающее окружение.
2. Каждая команда из раздела «Команды» `CLAUDE.md` существует в Makefile
   и выполняется.
3. `make ci-local` проходит целиком.
4. `make review` на любом изменении собирает пакет и получает ответы
   от обоих инструментов.
5. `make` без аргументов печатает список целей с описаниями.

Пятый пункт — не украшение: список целей и есть документация Makefile,
и он не устаревает, в отличие от отдельного описания.

## Риски

**Makefile разрастается.** Цель, которая нужна раз в полгода, лучше
не заводить: её всё равно забудут, а список станет нечитаемым.

**Дублирование с composer-скриптами.** Правило: Makefile отвечает
за Docker и оркестрацию, composer-скрипты — за то, что выполняется
внутри контейнера. Цель Makefile вызывает composer-скрипт, а не повторяет
его содержимое.
