# MPStats REST: проверка токена, порядка страниц и CSV

Дата: 31.10.2026. Прямое поручение владельца: использовать API-токен
из MCP-ссылки. Секрет использован в памяти через `X-Mpstats-TOKEN`;
не записан в Git, команды процесса, файлы результатов или этот документ.

## Подтверждённый доступ и параметры

POST `https://mpstats.io/api/analytics/v1/oz/category/items` отвечает HTTP 200.
Токен из ссылки подходит для REST. Параметры категории, дат, FBS и валюты
переданы в query; пагинация, фильтры и сортировка — JSON body.

- Категория: `Аксессуары/Женские аксессуары/Платки и шарфы женские/Хиджабы и тюрбаны женские`.
- Период: 01.01.2026–31.01.2026; FBS=1; currency=RUB.
- Body: пустой filterModel; sortModel — revenue DESC, затем id ASC.
- Первично проверены страницы [2500,3000), [3000,3500), [7500,8000), [8000,8500).
  Затем получены все 102 страницы до total=50 702.

На всех четырёх страницах проверен порядок `(revenue DESC, id ASC)`.
В обеих соседних парах пересечение ID равно нулю, включая нулевую выручку.
Ранее в MCP-паре [2500,3000)/[3000,3500) был воспроизводимый дубль.
Полный последующий обход подтвердил порядок на всех строках и границах
страниц, 50 702 уникальных ID и отсутствие дублей. Набор SKU полностью совпал
с API CSV. Это успешный снимок данного запуска; гарантия неизменяемости
данных источника в общем случае не установлена.

REST отдаёт 62 поля строки, MCP — 51. MCP опускает, в частности, URL,
изображения и часть графиков. Для требования «все исходные поля» использовать
проверенный прямой REST; MCP пригоден для разведки, его ответ не raw REST.

## Полный API CSV

Запрос того же отчёта с type=csv вернул HTTP 202 с состоянием подготовки.
Повтор такого же запроса вернул HTTP 200, progress=100 и путь выгрузки.
Файл получен по возвращённому `/api/analytics/v1/oz/download/...` с тем же
заголовком авторизации. Без заголовка загрузка файла не удалась.
Это API-экспорт; независимого ручного CSV из UI пока нет.

Архив ZIP 2 519 319 байт содержит один CSV 27 947 939 байт, UTF-8 BOM,
разделитель `;`. Проверено:

| Проверка | Результат |
|---|---|
| Строк данных | 50 702, равно total JSON |
| Уникальных SKU | 50 702 |
| Дублей/пустых SKU | 0 / 0 |
| Продажи, шт. | 3 541 442 |
| Выручка, RUB | 5 172 621 135 |
| Колонок CSV | 49, A–AW |
| JSON-страниц | 102 |
| Строк JSON для сравнения | 50 702 |
| Совпадение наборов SKU JSON/CSV | Полное |
| Совпадение сумм sales/revenue JSON/CSV | Полное |

Контрольные суммы вычислены Decimal без float, без фильтрации продаж/остатков.
Сохранены все поля исходных JSON; в данном отчёте их 62. Карта сверяет 49
полей, представленных в CSV, а остальные сохраняются без преобразования.
Параметры startRow/endRow запроса CSV не ограничили выгрузку до 500:
возвращён полный отчёт. Это отдельное поведение асинхронного экспорта,
его нельзя автоматически переносить на JSON-пагинацию.

## Карта колонок и расхождения

[Карта 49 колонок](product-research-ozon-columns.md) заполнена по настоящему
API CSV и проверена на всех 50 702 строках REST. Все поля найдены. После явного
разбора десятичной запятой, дат DD.MM.YYYY и `-` для null оборачиваемости
48 колонок совпадают по всему месяцу.

У `% from revenue` / `percent_from_revenue` есть расхождение на 4 497 строках
полного месяца: например JSON=0.24, CSV=0. Дополнительно проверено: на всех 1 000
строках страниц 2500/3000 JSON-процент равен revenue / сумма revenue страницы
× 100 с округлением до двух знаков. Это наблюдение показывает зависимость
показателя от страницы на проверенной выборке; нельзя использовать его как
готовую долю в месяце. Аналитическая доля рассчитывается поверх полного снимка
отдельным этапом. Исходные значения не меняются ради зелёной сверки.

Исходное требование 41 колонки расходится с текущим API CSV (49). Нужен
ручной экспорт UI для решения, является ли это другой схемой экспорта.

## Сохранённые материалы

Постоянный набор подготовлен в
[`services/product-research-ozon/tests/fixtures/mpstats/ozon/category-items/2026-01/`](../../services/product-research-ozon/tests/fixtures/mpstats/ozon/category-items/2026-01/README.md):
102 побайтовых JSON-ответа в tar.gz, исходный ZIP CSV, manifest с SHA-256,

локальный `var/`; независимое ревью перед merge остаётся обязательным.

Каталог `var/product-research-ozon-stage0/rest/` игнорируется Git:

- `stable-2500.raw`, `stable-3000.raw`, `stable-7500.raw`, `stable-8000.raw`:
  неизменённые JSON-ответы; одноимённые meta.json — статус, размер, SHA-256.
- `month-*.raw`: остальные исходные страницы; вместе с четырьмя stable-файлами
  образуют 102 страницы полного месяца.
- `csv-sample.raw`, `csv-poll-1.raw`: ответ ожидания и готовности экспорта.
- `csv-download.raw`: исходный ZIP;
  SHA-256 `9697a089fa3cb09eaf7c73f1cc1b27f16cee9ad1bfc2a74ead26d2f96ec6d82e`.
- `january-2026-export.csv`: байты CSV из архива без изменения.
- `csv-inspect.json`, `csv-validation.json`, `column-mapping-check.json`:
  первоначальные результаты чтения и выборочной сверки.
- `full-json-check.json`: итог загрузки, счётчики, суммы и SHA-256 всех 102 страниц.
- `full-crosscheck.json`: окончательная сверка всех ID и 49 колонок полного месяца.
- `manifest.json`: размеры и SHA-256 всех файлов, существовавших при завершении.

Ответ подготовки CSV содержит служебный ключ выгрузки. Он и сырьё остаются
локальными; в Git не включались. Сырьё — кандидат в фикстуры до проверки
правил допустимости данных и обеспечения постоянного хранения вне `var/`.
Автоматическая fixture-suite приложения пока не создана. Данные перенесены
в постоянный набор, ссылки выше; содержимое архивов проверено офлайн.
