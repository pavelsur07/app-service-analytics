# Реклама Ozon по SKU в юнит-экономике — план

**Цель:** у каждого SKU в юнит-экономике — расход на рекламу из данных
площадки по этому SKU; `by-day` — отдельная сверка. Решения — ADR-035.

**Вне объёма:** «Оплата за заказ» по SKU (форма отчёта неизвестна,
ADR-035 п. 7); ДРР, показы, клики на экране; реклама по модели;
Wildberries; сверка в журнал/оповещение — только признак на экране.

## Согласовано владельцем 2026-09-28

1. ADR-035: данные Performance входят в расчёт (заменяет ADR-026 п. 3),
   отбор кампаний по факту расхода (заменяет правило ADR-026 п. 4),
   `by-day` — сверка.
2. Новая факт-таблица `ad_sku_expense_fact` и её ключ.
3. Изменение контракта `GET …/unit-economics`, используемого фронтендом.
4. Денежные величины — только `Money` (ADR-004): разбор, суммы,
   остаток, сверка.

Новых внешних зависимостей, межмодульных связей и изменений очереди нет:
всё внутри Ingestion, сообщения и транспорты прежние.

## Пакет 1 — факты рекламы по SKU (backend, Ingestion)

**Домен**
- `OzonAdSkuExpense` (readonly): `campaignId`, `businessDate`,
  `marketplaceSku`, `Money $amount` (отрицательная).
- `OzonAdSkuReportParser` — асинхронный отчёт
  `{campaign_id: {report: {rows}}}`: дата `d.m.Y`, сумма с запятой,
  пропущенное поле = 0.
- `OzonAdSkuDayParser` — `products/sku`: `campaignId` в строке, дата ISO,
  сумма с точкой.
- Разбор суммы в минорные единицы — строгим шаблоном на источник,
  результат — `Money::ofMinor(…, 'RUB')`, валюта — константа коннектора
  Performance. Несовпадение — исключение.
- `OzonAdExpenseParser` — `statistics/expense`: пары «кампания × день»
  с `moneySpent > 0` (для отбора кампаний, п. 4 ADR-035).
- Entity `AdSkuExpenseFact` (`class`, не `final`) + Builder тестов.

**Схема — одна миграция**
- `ad_sku_expense_fact`, PK `(company_id, marketplace_account_id,
  source_row_id)`, `source_row_id = campaign_id|business_date|sku`;
  `amount_minor` — тип `money_minor_amount`, `currency char(3)`;
  `source_received_at`, `raw_document_id`, `row_hash`,
  `first_loaded_at`, `last_updated_at`.
- Индексы `(company_id, business_date)`, `(raw_document_id)`.
- `down()` — `DROP TABLE`.

**Запись** — `DoctrineAdSkuExpenseFactWriter`: пачками, `INSERT …
ON CONFLICT … DO UPDATE … WHERE EXCLUDED.source_received_at >=
текущей`.

**Обработчики**
- `CheckOzonAdSkuReportHandler`: после сохранения `ozon_ad_sku_report`
  — разбор и запись; у отчёта заказов (`CpoOrders`) разбора нет.
- `FetchOzonAdCampaignStatsHandler`:
  - отбор кампаний для `orderSkuReports` и `products/sku` —
    тип `SKU` (архивные включительно) ∩ расход > 0 в загруженном
    `expense` за нужный период; кампании с расходом, отсутствующие
    в списке, — тоже;
  - после сохранения каждого `ozon_ad_sku_day` — разбор и запись.

**Тесты**
- unit: парсеры на фикстурах — `statistics-json-many-2026-08-25.json`
  (725 строк, итог 158 960,62 ₽), `statistics-products-sku-2026-09-23.json`
  (21 строка, 4 654,82 ₽); отказ на чужом разделителе и трёх знаках
  после запятой; пропущенное поле — ноль;
- unit: отбор кампаний — архивная с расходом выбрана, неархивная без
  расхода нет, кампания с расходом вне списка выбрана;
- integration: повтор документа не меняет результат; старый документ,
  записанный после нового, не перезаписывает; две компании — факты
  одной не видны в чтениях другой.

## Пакет 2 — сверка и юнит-экономика (backend)

- `AdSkuReconciliationQuery(companyId, from, to)` — по паре
  «подключение × кампания × день»: сумма 41 из `marketplace_expense_fact`
  (`unit_number = campaign_id`), сумма `ad_sku_expense_fact`, число
  строк SKU. SQL только агрегирует; разница и допуск («копейка на
  строку») — в PHP через `Money::minus`. Итог — число дней периода
  с несошедшейся парой.
- `UnitEconomicsQuery::skus` — третья сторона объединения: реклама
  по SKU за период входит в `FULL OUTER JOIN` (SKU с рекламой без
  продаж попадает в список) и в `margin_minor` для сортировки.
- `UnitEconomicsQuery::cabinetExpenses` — отдельно итог 41 и итог
  рекламы по SKU за период.
- `BuildUnitEconomicsAction`: у SKU `advertisingMinor`, входит
  в `deductions` через `Money::plus`; в кабинете строка 41 заменяется
  остатком `by-day(41) minus реклама по SKU` через `Money::minus`,
  показывается при ненулевом; тест маржи SQL = маржа Money дополняется
  рекламой.
- Ответ API: `advertisingMinor` у SKU; `advertisingUnallocatedMinor`
  и `advertisingUnreconciledDays` в отчёте. `make api-doc-export`,
  `make api-types`.

**Тесты (обязательное покрытие)**
- денежная арифметика: инвариант «реклама по SKU + остаток = итог 41»;
  знак; маржа с рекламой; SKU в двух кампаниях суммируется;
- сверка: расхождение в две копейки на двух строках — сошлось,
  три копейки на двух строках — не сошлось; нет разбивки; нет
  начисления;
- изоляция: реклама компании B не попадает ни в SKU, ни в остаток,
  ни в сверку компании A (существующий functional-тест изоляции
  юнит-экономики дополняется фактами рекламы).

## Пакет 3 — экран (apps/seller)

- Колонка «Реклама» в таблице SKU и строка в разбивке удержаний;
  строка кабинета «Реклама, не разнесённая по товарам».
- Предупреждение при `advertisingUnreconciledDays > 0`: «Реклама
  по товарам не сходится с финансовым отчётом Ozon за N дн.»
- Типы — из сгенерированной схемы; арифметики над деньгами
  в компонентах нет — значения приходят с бэкенда.
- Vitest: форматирование новых полей; разбор ответа по схеме (msw).

## Выкладка и проверка на проде

1. Merge, выкладка, миграция (`doctrine:migrations:migrate`), проверка
   гейта `up-to-date`.
2. Первичное наполнение: `app:ingestion:backfill-ozon-advertising
   <компания> <подключение> <с> <по>` на 366 дней — по новому правилу
   закажет SKU-отчёты и по архивным кампаниям; разбор идёт в обработчиках.
   Очередь отчётов проходит около одного в минуту — часы.
3. Проверка: за 25.08–23.09.2026 сумма `ad_sku_expense_fact` —
   −158 960,62 ₽ (как фикстура), итог 41 — −158 960,57 ₽, остаток
   кабинета — +0,05 ₽; дней с несошедшейся сверкой за август–сентябрь — 0 (кроме
   последних двух суток); за сентябрь 2025 разбивка есть у архивных
   кампаний 12387459 и 17656929.
4. Экран юнит-экономики на проде: маржа SKU уменьшилась на рекламу,
   итог кабинета + SKU не изменился.
