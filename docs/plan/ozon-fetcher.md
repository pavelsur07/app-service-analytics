# Go-сервис `ozon-fetcher` — план

**Ветка этапа 0:** `task/adr-043-go-python-services`, дальше — ветка на этап
**ADR:** ADR-043 (Proposed → принимается на этапе 0)
**Источник кода:** `app-service-finance`, `services/ozon-fetcher`,
коммит `a9eb74206`

## Задача

Запустить в Conwix автономный Go-сервис загрузки Ozon параллельно
загрузке PHP. Сервис набирает raw-ответы Ozon в бакет сырья Conwix под
своим префиксом (ADR-044) и ведёт
журнал в своей БД. Загрузка, разбор и факты в PHP не меняются;
передача raw в PHP — вторая волна, отдельный ADR.

## Решения (согласовано владельцем 24.10.2026)

1. Модель — как в ВашФинДир: свой планировщик, своя логическая БД,
   только raw. Бакет — бакет сырья Conwix под префиксом сервиса
   (ADR-044, решение 25.10.2026 вместо отдельного бакета).
2. Код — перенос из ВашФинДир с адаптацией, дальше две независимые копии.
3. Ключи — внутренний API PHP, сервисный контур (ADR-043 п. 4).
4. Ресурсы первой волны — пересечение: начисления по дням, FBO v3,
   каталог, карточки, кампании, расход и дневная статистика рекламы.
5. Окна — как в ВашФинДир. Raw хранится 90 дней.

## Этапы

Каждый этап — отдельный PR, доводится до merge. Перед этапом — план
этапа: результат, чек-лист, проверка.

**0. ADR и правила**
- Правки правил из ADR-043 «Что меняется в правилах»: CLAUDE.md
  (сервисный контур в §1, стек, модули, миграции, CI, ревью,
  самопроверка, команды), AGENTS.md, `services/AGENTS.md`,
  `services/go.md`, `structure.md`, `patterns.md`, шаблон ревью.
- ADR-043 → Accepted, строка в таблице ADR CLAUDE.md.
- Кода нет.
- *Проверка:* ревью Claude + оба прохода Codex (ADR о секретах
  и изоляции).

**1. Перенос сервиса и БД под Conwix**
- `services/ozon-fetcher` с коммита-источника; коммит-источник —
  в README сервиса. Правила `services/AGENTS.md`, `services/go.md` уже
  есть с этапа 0.
- **Схема — сразу в форме Conwix**, миграции источника не переносятся:
  они forward-only, их несколько, а миграция в истории `master`
  необратима. Вместо них — одна стартовая миграция с рабочим `down`;
  `connection_ref` → `company_id` + `marketplace_account_id` (UUID)
  в схеме и в коде `store` и его потребителей; новые идентификаторы —
  UUIDv7. Генератор UUIDv7 и валидатор JSON Schema (тест клиента выдачи
  ниже) — пункты согласования плана этого этапа.
- **Клиент выдачи подключений в Go — под контракт Conwix** в том же
  этапе: разбор `marketplace_account_id` и обход страниц по курсору,
  тест разбора эталонного ответа по `schema.json`. Правила кэша и отзыва
  — этап 5. Остальной код — побайтово.
- Dev: логическая БД `ozon_fetcher` и роль `svc_ozon_fetcher` на том же
  контейнере postgres (init-скрипт); проверка с пустой базы входит
  в `make db-rebuild-check`; интеграционные тесты `store` идут в CI.
- Прямые зависимости `go.mod` сверяются с таблицей принятого стека
  `services/go.md`: модуль вне таблицы удаляется или выносится
  на согласование до merge.
- Контракты — **сразу в форме Conwix**, не побайтово: опубликованная
  версия неизменна, и правка v1 после merge была бы новой версией.
  `marketplace-connections/v1` — состав полей по ADR-043 п. 4
  (`marketplace_account_id` вместо `connection_ref`, `company_id`,
  `updated_at`, курсор), keyset-пагинация, `CHANGELOG.md` с отличиями
  от ВашФинДир; `service-coverage/v1` — сверить
  идентификаторы и перенести с теми же правками, если они нужны.
- `services/` — триггер высокого риска в `bin/review.py`;
  `structure.md` — `_contracts/` и `ozon-fetcher/`.
- Compose-профиль `services`, цели `make ozon-fetcher-*`
  (build, up, test, vet, lint, migrate), CI-задача и флаг `services`
  в `bin/ci-classify-paths`.
- Планировщик выключен конфигурацией: сервис стартует, `/health`
  и `/ready` отвечают, наружу не ходит.
- *Проверка:* `make ozon-fetcher-test` (`-race`, включая интеграционные
  тесты `store` на чистой базе), `vet`, `lint`, `govulncheck` зелёные;
  `db-rebuild-check` зелёный; дифф с источником — каркас Conwix, схема,
  замена идентификатора подключения и клиент выдачи под контракт Conwix,
  ничего сверх. Ревью Claude
  + оба Codex: схема и весь код загрузки, лимитов и хранилища;
  выключенный планировщик исключением порога не является.

**2. Хранилище raw под Conwix**
- Решение владельца 25.10.2026: отдельный бакет не заводится, сервис
  пишет в бакет сырья Conwix под своим префиксом — ADR-044 (пересматривает
  ADR-043 п. 3).
- Ключ объекта:
  `conwix/svc/ozon-fetcher/v1/companies/{company_id}/accounts/{marketplace_account_id}/{resource_type}/{period_key}/{sha256}.{ext}.gz`;
  проверка сегментов при сборке ключа (отклонение, не исправление);
  `company_id` и подключение — из одной записи.
- Порт хранилища принимает подключение первым параметром после `ctx`
  (`Put`, `Reader.Get`) и отказывает на ключе вне его префикса; URI
  для чтения пересобирается из строки company-scoped запроса
  (замечания ревью этапа 1).
- Тест: объект одной компании не записывается под префикс другой.
- *Проверка:* интеграционный тест на SeaweedFS песочницы.
  Ревью Claude + оба Codex (изоляция).

**3. Ресурсы первой волны и окна**
- Выключить ресурсы вне пересечения (FBS, начисления по отправлениям,
  типы начислений, реализация, взаиморасчёты, асинхронный отчёт рекламы,
  `/v4/product/info/stocks`): код остаётся, планировщик их не ставит.
- FBO v3: `translit: false`, как в PHP.
- Реклама: расход и дневная статистика — по дню.
- Окна планировщика — как в источнике, в конфиге.
- Признак блокировки (ADR-043 п. 5: 403 по подключению из allowlist
  на методе, который этим ключом уже отвечал 200, ключ не менялся) —
  остановка всех задач сервиса до ручного снятия; 403 на методе без
  прежнего 200 — пауза только этого ресурса подключения; тесты на оба
  случая.
- Тесты разбора страниц и курсоров — на фикстурах Conwix
  (`api/tests/Fixtures/Marketplace/ozon`).
- *Проверка:* тесты планировщика (какие задачи ставятся на дату),
  тела запросов сравниваются с теми, что шлёт PHP. Ревью Claude
  + оба Codex (ingestion).
- Сделано 25.10.2026: `planner.FirstWave`; первичная загрузка отправлений
  и рекламы — с M-2 (даты ВашФинДир убраны); начисления и FBO шлют
  `last_id`/`cursor` и на первой странице, FBO — `translit: false`;
  403 отделён от 401: `service_halt` + `-resume-halt`, `resource_pause`
  (сутки); фикстуры читаются из `api/tests/Fixtures` без копий.
  Синтетические `testdata/` остались для механики обхода курсора начислений
  (двухстраничной боевой выгрузки нет) и ресурсов вне первой волны.
  Открыто: ответ Ozon, «прямо говорящий о блокировке», — формы нет ни в одной
  фикстуре; признаком пока служит только 403 по загруженному методу.

**4. Выдача подключений в PHP**
- `GET /api/internal/marketplace-connections`, контракт
  `services/_contracts/marketplace-connections/v1` в форме, принятой
  на этапе 1 (`marketplace_account_id`, keyset-пагинация: лимит 50,
  максимум 200, превышение — 422).
- Отдельный firewall, токен «сервис → PHP», сравнение за постоянное
  время; запрос `ActiveOzonConnectionsForServiceQuery`; узкие слои
  Deptrac на контроллер и запрос; аудит обращения без ключей.
- Nginx: публичные vhost отвечают 404 на `/api/internal/`.
- `warning` на каждый полученный ответ 429 и 403 Ozon (API, метод, подключение)
  у обоих клиентов PHP: Seller (`OzonSellerRateLimitingClient`)
  и Performance (`OzonPerformanceHttp` — обёрткой лимита Seller он
  не покрыт, ADR-028). База для критерия этапа 8; этап 4 выкладывается
  не позже чем за неделю до этапа 7.
- Тесты: без токена, с чужим токеном, снаружи — отказ; ответ проходит
  JSON Schema; ключи не в логах.
- *Проверка:* functional-тесты, Deptrac, PHPStan. Ревью Claude
  + оба Codex (секреты, изоляция).

**5. Сервис получает подключения**
- Клиент выдачи в Go (разбор и обход страниц — с этапа 1): кэш только в памяти
  и только целиком собранным списком; подключение, пропавшее из выдачи,
  сразу теряет ключи и задачи; кэш без подтверждения — не дольше
  `CONNECTIONS_MAX_STALE` (30 минут), затем все задачи стоят; 401 Ozon —
  одно обновление и один повтор, затем пауза кабинета до новых ключей;
  проверка ответа по той же схеме (валидатор — с этапа 1).
- **Allowlist закрыт по умолчанию** (ADR-043 п. 5): пустой или
  отсутствующий `OZON_FETCHER_CONNECTION_ALLOWLIST` — ни одного
  подключения; в источнике пустой список означает «все», семантика
  меняется здесь.
- Тесты на каждое из правил кэша выше и на пустой allowlist.
- Строгий разбор выдачи (`contract_violation` на любое нарушение
  схемы, включая отдельное подключение и дубль) — уже с этапа 1.
- Сквозной прогон в песочнице: PHP-выдача → сервис → мок Ozon → raw
  в SeaweedFS → журнал.
- *Проверка:* интеграционный тест Go на фикстуре ответа PHP; ручной
  прогон в песочнице, `/internal/fetch-status` показывает задачи
  в `done`. Ревью Claude + оба Codex (секреты).

**6. Наблюдаемость**
- `slog`: `company_id`, `marketplace_account_id`, `job_id`, `trace_id`,
  `resource_type`, `outcome`, `error_class`; без ключей, тел и сумм.
  Обязательные поля дописывает общий обработчик журнала
  (`services/AGENTS.md` §8), а не каждый вызов.
- `/internal/fetch-status`, `/internal/coverage` и загрузка лимитов
  при старте (`…AllConnections`, `…AcrossConnections`) — по
  `services/AGENTS.md` §5: списки с лимитом, без `COUNT(*)` по журналу
  попыток (исходы за сутки — счётчиками или агрегатом по задачам);
  перенесённый код этого пока не делает (замечания ревью этапа 1).
- GlitchTip — свой проект, только ERROR.
- `/internal/fetch-status`, `/internal/coverage` под токеном
  «PHP → сервис».
- *Проверка:* тест, что запись лога не содержит ключей и тела.
  Ревью Claude + оба Codex (ключи подключений).

**7. Вывод на прод**
- Человек: пользователь хранилища с правами на префикс
  `conwix/svc/ozon-fetcher/` бакета сырья (поддержку политики по префиксу
  у Timeweb проверить; нет — записать издержку, ADR-044), правило
  жизненного цикла 90 дней на этот префикс, включая неактуальные версии;
  секреты (токены двух направлений,
  пароль роли, ключи бакета, DSN GlitchTip) — в `/opt/conwix/.env`
  вводом через stdin, как `bin/set-raw-storage-env.sh`.
- Образ в ghcr с `master`; выкладка создаёт роль и БД и проверяет
  миграции сервиса — при неприменённых останавливается; агент применяет
  `ozon-fetcher -migrate` отдельным шагом и повторяет выкладку;
  контейнер — при `OZON_FETCHER_ENABLED=true`;
  сети `internal` + `egress`, без роутера Traefik.
- Роль `svc_ozon_fetcher` не подключается к БД Conwix: правило
  `pg_hba` и `REVOKE CONNECT` на боевом инстансе, проверка входом роли
  в БД `app` (в песочнице — с этапа 1, `make ozon-fetcher-db`).
- `OZON_FETCHER_CONNECTION_ALLOWLIST` — одно подключение, с согласия
  владельца кабинета. Пустой список — ни одного подключения (семантика
  меняется при переносе, тест на это — на этапе 5).
- *Проверка на проде:* контейнер `healthy`, задачи в `done`, объекты
  под `conwix/svc/ozon-fetcher/v1/companies/{company_id}/`, в `conwix/raw/`
  сервис не пишет, `/api/internal/` снаружи — 404.
  Ревью Claude + оба Codex (секреты, инфраструктура).

**8. Наблюдение и расширение**
- Каждое подключение в allowlist — с согласия владельца кабинета
  (ADR-043 п. 5: риск ограничения доступа по Client ID).
- Неделя на подключении, критерии — **по этому подключению и отдельно
  по каждому API** (Seller и Performance — разные хосты, ключи и лимиты):
  сумма ответов 429 у PHP (`warning` с этапа 4) и у сервиса (журнал
  попыток) за сутки не больше максимума суток PHP по тому же API
  за неделю до включения плюс 3; отметки загрузки дня ставятся как раньше;
  ошибок `auth`/`invalid_*` в GlitchTip нет.
- Признак блокировки по Client ID (ADR-043 п. 5): у сервиса — он сам
  останавливает все задачи (этап 3); у PHP — агент ежедневно сверяет
  `warning` 403 по подключениям из allowlist и при 403 на методе, по
  которому загрузка шла, без смены ключей ставит
  `OZON_FETCHER_ENABLED=false`.
- Весь период параллельной работы — не дольше трёх месяцев с первого
  включения (ADR-043 п. 5).
- Параллельная работа — не дольше, чем нужно для критериев: каждое
  подключение в allowlist удваивает запросы к Ozon.
- Сверка покрытия: каждый день, загруженный PHP, есть в журнале сервиса.
- Критерий выполнен — следующее подключение добавляется в allowlist
  поимённо, с согласия его владельца, и проходит ту же неделю. Очистка
  списка сервис выключает, а не расширяет. Не выполнен — подключение
  убирается из списка и разбирается.
- *Проверка:* отчёт с цифрами по каждому критерию.

## Не входит

- Передача raw сервиса в PHP и переключение загрузки (вторая волна,
  отдельный ADR).
- Ресурсы только Conwix: остатки по кластерам, возвраты, реклама
  по SKU, CPO, товары кампании.
- Доработка загрузки PHP (воркеры, `sleep()` в лимитере) — отдельная
  задача.
- Python и прогноз поставок — отдельный ADR с модулем прогноза.
- Экран покрытия сервиса в админке.
