# Доработка расширения: две цены, видимые сбои, контроль РРЦ — план задачи

**Цель:** продавец держит цену на витрине Ozon не ниже РРЦ дистрибьютора.
Для этого расширение снимает обе цены витрины, его сбои не проходят молча,
а нарушение РРЦ превращается в оповещение.

**Основание.** Серверный сбор отклонён по итогам спайка
(`docs/plan/storefront-renderer.md`): Ozon не пускает автоматический
браузер ни с каких IP. Источником витринной цены остаётся расширение
(ADR-014), и всё, что его ослабляло, — тихие сбои, истекающий токен,
одна цена из двух, — чинится здесь.

**Согласовано владельцем 2026-10-16**, все пункты таблицы ниже.

## Решения

| № | Вопрос | Решение |
|---|---|---|
| 1 | Порядок | вторая цена → видимость сбоев → РРЦ → автопродление токена → повторы |
| 2 | Куда оповещения | почта продавцу, Symfony Mailer |
| 3 | Порог «цены не приходят» | 2 часа (4 цикла), только если расширение было на связи |
| 4 | Автопродление токена | делать, новым ADR (отступает от ADR-010 «refresh-токена нет») |
| 5 | Разрешение `notifications` | не добавлять; значок на иконке |
| 6 | Эндпоинт событий расширения | делать |
| 7 | Где РРЦ | колонка у отслеживаемого SKU (`tracked_sku`), правит человек |
| 8 | Порог нарушения РРЦ | строго ниже РРЦ, без допуска |
| 9 | Хранение второй цены | новая nullable-колонка в `price_observation`; прежняя цена без изменений |
| 10 | С какой ценой сравнивать РРЦ | с обеими; в оповещении — какая ниже |

## Две цены карточки

Образец живой карточки 2026-10-16 (SKU 308520421, покупатель вошёл в аккаунт):

| Поле `data-state` у `[id^="state-webPrice"]` | Значение | Подпись на карточке | Смысл |
|---|---|---|---|
| `cardPrice` | 1 413 ₽ | «С банками» | **цена с Ozon Картой** |
| `price` | 1 570 ₽ | «С другими банками» | **цена без Ozon Карты** = `offers.price` schema.org |
| `originalPrice` | 3 948 ₽ | зачёркнутая | не снимается |

Сегодня расширение снимает только цену без карты — `offers.price`.
Подпись «С банками» вводит в заблуждение; смысл поля подтвердил владелец.

## Этап 1. Вторая цена

1. **Разбор.** `apps/extension/src/ozon/price.ts` дополнительно читает
   `cardPrice` из `data-state`. Цена без карты по-прежнему берётся из
   schema.org — она устойчивее к редизайну; `price` из того же `data-state`
   с ней сверяется: расхождение значит, что разобран не тот блок, и тогда
   цена с картой не отправляется. Блока нет или поля нет — цена с картой
   пустая, это нормальный случай (на карточке нет скидки по карте).
   Валюта цены с картой — та же, что у schema.org; знак `₽` проверяется.
2. **Приём.** `PriceObservationRequest` принимает необязательное
   `cardPrice {amount, currency}`; валюта обязана совпадать с `displayedPrice`.
   Старое расширение без поля продолжает работать.
3. **Хранение.** Колонка `price_observation.card_price_minor` bigint NULL,
   одна миграция. Валюта — общая колонка строки.
4. **Экран СПП.** Обзор показывает обе цены; СПП считается от цены без карты,
   как сейчас.
5. **Тесты.** Разбор — на фикстуре из образца; приём — functional: поле
   есть, поля нет, валюта не совпала, отрицательная сумма.

## Этап 2. Видимость сбоев

1. Расширение по будильнику раз в цикл обращается к `/api/extension/.../me`:
   `last_seen_at` становится правдой, 401 замечается в фоне.
2. Значок на иконке: «!» при истёкшем подключении или трёх циклах подряд
   без единой снятой цены.
3. Эндпоинт событий расширения: причина неудачи (`markup-missing`,
   `sku-mismatch`, капча, не открылось окно) и короткий фрагмент блока цены.
   Без содержимого страницы целиком.
4. Сторож на сервере: отслеживаемые SKU есть, расширение на связи,
   наблюдений нет 2 часа — письмо продавцу, не чаще раза в сутки.
   Это задание `docs/task/price-capture-failure-signal.md`.
5. Блок «Расширение» в Conwix: когда было на связи, последняя цена,
   срок токена, предупреждение об устаревших ценах.

## Этап 3. Контроль РРЦ

1. `tracked_sku.rrp_minor` NULL + валюта; правка в Conwix, с аудитом
   (это цена, которую задаёт человек).
2. Наблюдение ниже РРЦ по любой из двух цен — письмо продавцу:
   SKU, обе цены, РРЦ, цена продавца из каталога, размер скидки Ozon.
   Не чаще одного письма на SKU за цикл нарушения.
3. Отчёт по дням для дистрибьютора: цена продавца, обе цены витрины, РРЦ.

## Этап 4. Автопродление токена

Новый ADR: за 5 дней до истечения расширение обменивает действующий
токен на новый; старый отзывается. Напоминание в Conwix — запасной путь.

## Этап 5. Повторы

Артикул, пропущенный из-за занятого окна или неудачной загрузки,
получает одну повторную попытку в том же цикле.

## Ревью

Каждый этап — отдельный PR. Схема и приём данных от клиента (этапы 1, 3),
токен (этап 4) — Claude + оба прохода Codex; остальное — Claude.

## Чего план не делает

- Не обходит защиту Ozon и не снимает цены без браузера продавца.
- Не меняет цены в кабинете: оповещение о РРЦ — сигнал человеку.
- Не удаляет остаточную колонку `seller_price_minor` — отдельной правкой.
