# Stage 2 — зависимости и уровни проверок

## Цель

Поставить всё из таблиц библиотек `patterns.md` и убедиться, что каждая
проверка действительно ловит нарушение, а не просто настроена.

## Входит

**Backend**

Зависимости по таблице `patterns.md`: Doctrine ORM и DBAL, `symfony/uid`,
`brick/money`, Pagerfanta с адаптером DBAL, HTTP-клиент, RateLimiter, Lock,
Messenger, Mailer, Nelmio для OpenAPI.

Инструменты: PHPUnit, `dama/doctrine-test-bundle`, PHPStan level 9
с расширениями для Doctrine и строгими правилами, Deptrac, PHP-CS-Fixer.

**Frontend**

TanStack Query и Table, React Router, `openapi-typescript`, React Hook Form
с Zod, `date-fns`, Tailwind, MSW, Vitest, Playwright, knip, ESLint
с правилами границ импортов.

**Уровни тестов — по одному осмысленному примеру на каждый**

| Уровень | Пример |
|---|---|
| unit | арифметика `Money`: аллокация с остатком, сумма частей равна целому |
| integration | запись и чтение через репозиторий с откатом транзакции |
| functional | эндпоинт-заглушка отвечает и соответствует схеме |
| e2e | открытие приложения селлера, виден стартовый экран |

Пример на уровень нужен, чтобы уровень был проверен целиком —
запуск, окружение, откат, отчёт, — а не только описан в конфигурации.

**Первые правила линтеров**

Написать собственные проверки, о которых договаривались:
литеральный массив в ключе кэша, прямой вызов `fetch`, импорт между
фичами, `localStorage` вне разрешённого списка.

## Не входит

- Глобальные фикстуры и `doctrine/data-fixtures` — запрещены ADR-005.
  В примере из чужого Makefile такие цели есть; у нас их не будет,
  подготовка данных идёт через билдеры.
- Билдеры сущностей: сущностей пока нет. Появятся вместе с первой.
- Пороги покрытия тестами.
- Настройка отправки почты и хранилища секретов.

## Критерий готовности

**Прямая проверка:** все прогоны зелёные.

**Обратная проверка — важнее.** Намеренно внести нарушение и убедиться,
что нужная проверка краснеет:

| Нарушение | Что должно упасть |
|---|---|
| Метод репозитория без `companyId` | ревью по чеклисту (правило машинно не проверяется) |
| Литеральный массив в ключе запроса | ESLint |
| Прямой вызов `fetch` в компоненте | ESLint |
| `any` в TypeScript | ESLint |
| Обращение `array[i]` без проверки | `tsc` |
| Импорт из чужого модуля мимо Facade | Deptrac |
| Метод без типа возвращаемого значения | PHPStan |
| Правка схемы OpenAPI без регенерации типов | проверка синхронности |

Проверка, не упавшая на своём нарушении, считается ненастроенной.

## Риски

**PHPStan level 9 на пустом проекте кажется бесплатным** — так и есть,
и в этом весь смысл. Соблазн понизить уровень появится на Stage 3–4,
когда появится реальный код. Понижение уровня — предмет обсуждения,
а не решение внутри задачи.

**Часть правил не проверяется машиной** — прежде всего `companyId`
в репозиториях. Написать линтер под это возможно, но пока сущностей нет,
писать не на чем. Правило остаётся в чеклисте самопроверки;
вернуться к автоматизации, когда появятся первые репозитории.
