**Цель:** получить ожидаемую выручку из цены каждой принятой исходной строки и
её точного нетто-остатка, сохранив независимую доступность прогноза штук.

**Архитектура:** точный внутренний аккумулятор Ingestion сопровождает существующий
обход `AggregateNetForecastAction`. В DTO публикуется `Money` после суммирования
на данном уровне; родитель получает точный аккумулятор, а не округлённые деньги.
Повторного SQL, второго графа источников и межмодульных изменений нет.
Точное значение дня дополнительно сохраняется приватно во внутреннем DTO
для последующей B12-композиции недель/месяцев/накопления без потери копеек.

**Стек:** PHP 8.4, Symfony 7.4 LTS, существующие brick/math и brick/money,
PHPUnit/ParaTest и настоящие DBAL writers в интеграционных тестах.

**Основания:** [общий план B11](../sales-planning-daily-implementation.md),
[ADR-004](../../adr/0004-money.md),
[ADR-049, §4 «Деньги»](../../adr/0049-net-sales-forecast-observations-and-horizon.md),

## Global Constraints

- Цена — `NetForecastPart::trace->amountMinor`, **цена единицы** в minor units,
  не сумма строки. Это подтверждает `BuyoutDailyQuery`: `quantity * amount_minor`.
  `trace->currency` обязательна. Цена уже прочитана из accepted rows того же RR.
- Только точная integer/rational арифметика; float запрещён даже промежуточно.
  Brick-типы не выходят в публичные сигнатуры/DTO; наружу только собственный `Money`.
- `expectedNetRevenue = HalfUp(Σ unitPriceMinor_i × expectedNet_i)`.
  `expectedNet_i = currentD_i − futureReturns_i + retainedOpen_i` уже вычислен B09.
  Известные R и факт повторно не вычитать/прибавлять, среднюю РРЦ не использовать.
- Единственное округление до minor unit на каждом публикуемом scope — **после SUM**.
  Сумма округлённых parts/days/SKU не является источником итога следующего уровня.
  Quantity не переводить в decimal string; его транспорт с тремя знаками — B12.
- Scope company/account, readAt, snapshot и epoch проверяются существующим
  кодом до нулевых/денежных shortcuts. B11 их не заменяет и не ослабляет.
- Пределы сохраняются: 50 SKU × 184 дня, 20 000 groups, 50 000 source keys,
  5 s общего mapping+compute, 96 MiB peak, 48 MiB allocation, 32 MiB output.
- Без схемы/миграций, новых зависимостей, generic Shared-абстракций, SQL-цены,
  Facade/API/UI, storage/snapshot manifests. B12/B13/B15/B16 остаются отдельно.
- Synthetic tests доказывают арифметику и ограничения, но не качество модели.
  Numeric rollout и пригодность исторического backtest этим шагом не разрешаются.

## Решения и границы доступности

Выбран один проход с локальными аккумуляторами: он сохраняет текущие guards и
не удерживает второй граф. Отдельный post-processing action означал бы повторный
обход, отдельный бюджет и сборку DTO; расчёт в SQL повторял бы модель B09.
Оба варианта здесь не нужны. Это решение дизайна, а не новое требование владельца.

1. **Точные деньги — отдельное внутреннее значение `NetForecastRevenue`.**
   Private rational в minor units и private currency; цены сначала проходят
   `Money`. ADR-049 разрешает взвешивание ожидания, это не деление существующей
   суммы расходов между получателями из ADR-004. Общий `Money` не расширять.
2. **Реальная строка проверяет цену даже при expectedNet=0.** Нет цены →
   `money_price_missing`; нет валюты → `money_currency_missing`; неверная строка
   числа/ISO-код → `money_input_invalid`. Это делает «нет цены — нет оценки»
   одинаковым для положительного остатка, allT1 и allR. Нулевая цена валидна.
3. **Пустая полная область — точная аддитивная identity без валюты.** Она не
   портит сумму с ценовыми строками. Сама по себе публикует null и
   `money_currency_missing`, сохраняя quantity=0: валюта не выводится из компании,
   соседнего SKU или RUB. Пустой request по-прежнему не обращается к БД/часам.
   Пустота с source/coverage failure вообще не получает identity.
4. **Неизвестные штуки имеют приоритет:** quantity=null означает money=null
   с исходной `unavailableReason` (защитный fallback `quantity_unavailable`).
   Не публиковать сумму известных строк под именем полного итога. Доступные
   соседние scopes остаются диагностически доступными, как в B09.
5. **Разные валюты не складываются, даже у нулевых ценовых строк.** Domain `plus`
   выбрасывает `InvalidArgumentException`, Application переводит это в
   `money_currency_mismatch` данного scope и его предков. Одновалютные дети
   сохраняются. Ни FX, ни фильтра валюты/плохих строк нет.
6. **Знак цены сохраняется.** Money допускает signed minor amount; основания
   запрещать отрицательную исходную цену в B11 нет. HalfUp на отрицательной
   половине даёт округление от нуля. Сам quantity остаётся неотрицательным.
7. **Переполнение не превращается в float или clipped amount.** Source price
   обязан вмещаться в native int для `Money::ofMinor`; иначе `money_overflow`.
   Арифметика ожидания точная. Итог, не помещающийся в native int после HalfUp,
   публикует null/`money_overflow` только на данном scope. Его точная сумма
   может участвовать в родителе: signed siblings могут вернуть итог в диапазон.
   Ошибка исходной цены/валюты, напротив, делает полный денежный итог недоступным.

Риск решений 3 и 7: денежный итог может быть доступен при пустом либо
непредставимом в native int ребёнке, а округлённые дети могут не сходиться с
итогом на копейку. Это ожидаемое свойство точного scope SUM, не частичная сумма.
B12 должен использовать готовый итог нужного scope, а не складывать DTO детей.

Планируемое API `NetForecastRevenue` (все методы публичны, Brick скрыт):

- `static empty(): self` — валютно-нейтральная identity;
- `static unavailable(string $reason): self` — sticky отказ входного компонента;
- `static fromSource(?string $unitPriceMinor, ?string $currency, NetForecastQuantities $quantities): self`;
- `plus(self $other): self` — exact addition, currency mismatch exception;
- `unavailableReason(): ?string` — входная причина; для самостоятельной empty
  возвращает `money_currency_missing`, но `plus` использует private state и
  отличает empty identity от отказа из-за строки без валюты;
- `storageBytes(): int` — консервативный заряд private numerator/denominator/
  currency/reason с постоянным overhead; без раскрытия Brick/public дробей;
- `toMoney(): ?Money` — null для unavailable/empty, иначе один HalfUp и
  `Money::ofMinor`; native conversion overflow наружу как `OverflowException`.

Source minor string: bounded canonical signed integer, без exponent/decimal/
пробелов; проверять длину до разбора, затем точный native range. Валюту
валидировать имеющимся `Money::ofDecimalString('0', $currency)` и его
`InvalidArgumentException`, затем создавать цену через `Money::ofMinor`.
Так IngestionDomain не импортирует Brick Money currency/exception classes:
`deptrac.php` уже разрешает здесь SharedDomain и BrickMath, без новых связей.

Private `part/group/day/sku` в aggregate получают последний output-параметр
`NetForecastRevenue &$revenue`; caller инициализирует его empty. Каждый уровень
возвращает прежний DTO и передаёт вверх только текущую exact сумму. Публичные
сигнатуры обоих actions остаются прежними. Не удерживать список accumulator
на каждый source. Только `NetForecastDay` сохраняет exact immutable value
для будущих составных периодов; публичные межмодульные/API DTO его не получают.

Private `publishRevenue(NetForecastRevenue $revenue, ?NetForecastQuantities $quantities,
?string $unitReason): array` с shape `array{0: ?Money, 1: ?string}` решает
quantity-priority и local rounding/native overflow. Ошибка публикации ребёнка
не подменяет его exact carry. Sticky входные ошибки и currency mismatch
передаются вверх аккумулятором, детерминированно в уже сортированном порядке.

## Политика ресурсов

Денежный этап находится **внутри существующего aggregate guard**, не после
возвращения результата и не с новым стартом таймера. Общие 5 s включают mapRows,
unit и money arithmetic; SQL statement_timeout и training имеют свои уже
существующие границы. Это не обещание 5 s на весь HTTP request.

Guard проверяется до/после source multiplication, exact addition и публикации.
Money не получает дополнительного heap/time бюджета: действуют прежние
96/48 MiB, запас 8 MiB и actual peak. Аккумуляторы живут только на текущем
стеке обхода (part/group/day/SKU/batch); только day сохраняет собственный
exact carry, остальные дети — Money+reason. Day carry не удерживает source graph.
`plus` упрощает rational на каждом сложении; числитель/знаменатель ограничены
16 384 цифрами, как quantities, с предварительной проверкой operands.
Промежуточные multiplication operands ограничены этим размером; точный отказ
по precision — `money_precision_exceeded`, штуки сохраняются. Проверять guard
и при превращении precision exception в отказ, чтобы не замаскировать общий
таймаут/heap отказ денежной причиной. Таймер кооперативный, не прерывает одну
библиотечную операцию; adversarial denominators проверяются отдельным тестом.

Существующий `charge()` не видит private поля Money через `get_object_vars`.
Добавить явные ветки Money и NetForecastRevenue: compact `minor` int + `currency`
string для Money и `storageBytes()` для private exact carry,
и включить оба новых поля/имена в заряд каждого DTO. Private rational учитывается консервативно по
ограниченным строкам его компонентов, без второго JSON всего графа. При превышении **общего** time/heap/output
сохраняется прежний whole-result `input_budget_exceeded` без частичного графа;
локальная money unavailability не отменяет этот fail-closed контракт.

Обязательное измерение готовности: representative 2 000 groups с полным
календарём, одновременно units+money, на том же контейнерном пути должно
завершиться доступным результатом в пределах **5 s compute / 96 MiB peak**,
а также прежних 48 MiB allocation / 32 MiB output. Записать фактические значения
и условия измерения, а не только прохождение искусственно уменьшенного лимита.
По evidence root B09 units уже занимал около 4.9 s: стоимость денег не бесплатна.
При RED сначала профиль и план минимального исправления по найденному узкому
месту; заранее новый cache/абстракции/оптимизации не добавлять, лимиты не поднимать.

## Согласованная коррекция после измеренного RED ресурсов

Root принял узкую коррекцию ДО production-правок по реальным профилям и
полному локальному прототипу. Начальный source→SQL→map→units+money достигал

Лимиты и guards не увеличивались и не удалялись.

Разрешена ровно проверенная комбинация:
- NetForecastRevenue хранит private сокращённые BigInteger numerator/denominator.
  Для a/b+c/d: g=gcd(b,d), n=a*(d/g)+c*(b/g), h=gcd(n,g), результат
  (n/h)/((b*(d/g))/h). FromSource сначала нормализует через Brick rational;
  publication использует BrickInteger dividedBy(HalfUp). Currency проверяется
  до zero shortcut; bounded precision и512byte overhead сохранены.
- NetForecastQuantities.php — единственное расширение production filemap:
  private exact sum через denominatorGCD/LCM и обычный BrickRational; constructor
  сначала сокращает retained−future, затем прибавляет integer currentD через
  numerator+currentD*denominator без повторногоGCD. Все8public strings,
  public methods, nonnegative/base validation и16384digit checks прежние.
  NetForecastQuantitiesTest.php добавляет literal canonical regressions.
- Aggregate charge использует factor1 для всех строк только по строгой whitelist
  `/\A[A-Za-z0-9_.:+ -]*+\z/`; все остальные строки сохраняют factor6.
  Разрешённые ASCII bytes не экранируются compactJSON и JsonResponse DEFAULT15;
  quotes/slash/backslash/control/Unicode и HEX <>&apostrophe исключены.
  2quotes/128containers/512privatecarry overhead и32MiB cap прежние.
- Runtime outputLimit=min(own,runtime) явно проходит существующий charging path,
  как уже min-ятся время/heap. Меньший runtime outputcap не обходится новыми
  Money/daycarry полями; отказ whole-result без partialMoney.
