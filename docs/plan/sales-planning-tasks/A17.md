# A17 — зрелость каждой SKU-дневной когорты

## План до кода

1. Переиспользовать BuyoutMaturityQuery::maturityCtes и условие доли
   в доставке ADR-029. Обучение p95 читает весь кабинет компании, а не
   только видимые SKU/дни; 30 уникальных наблюдённых закрытий обязательны.
2. Для каждой точки SKU × день рассчитать возраст от конца дня МСК и
   долю is_in_flight. Mature требует возраста строго больше p95 и доли
   <=300 bps; unknown без активного статуса долю не увеличивает.
3. Добавить calculatedAt как необязательный последний аргумент текущего
   запроса, сохраняя прежние вызовы. Это время расчёта текущих данных,
   не обещание восстановленного исторического среза.
4. В readonly Row добавить maturityStatus, inFlightQuantity/inFlightRateBps,
   числитель и знаменатель условного выкупа и known/actual buyout bps.
   Actual доступен только mature; наблюдаемые D/деньги сохраняются у всех.
   Зрелость выкупа не объявляет завершённость возвратов.
5. TDD integration: зрелые точки вокруг дня с активным хвостом; точная
   граница 3%; свежий день без хвоста; недостаток 30 уникальных postings;
   чужая компания/кабинет не даёт обучающую выборку. Синтетические Builder.
6. Выполнить затронутые тесты/backend-гейты и два Codex CLI прохода.

Файлы: SalesCohortMetricsQuery/Row, новый SalesCohortMaturityQueryTest, этот план.
Существующие Buyout Query/отчёты и пороги не меняются. Схема/API прежние.
Начало реализации после завершения A16 review: MetricsQuery — его frozen context.
