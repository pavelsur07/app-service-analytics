**Goal:** превратить gross-ожидание уже размещённых открытых штук в ожидаемые
оставшиеся продажи с учётом возвратов после будущей доставки.
**Architecture:** чистая exact Domain композиция pGross×(1−F(H)); Application
применяет одну явно выбранную пару scoped gross/return оценок. Целый выбор
SKU→account и общий unknown policy связываются в B08; B09 даёт target producer.
**Tech Stack:** PHP8.4, существующий private brick/math0.19; новых зависимостей нет.
**Spec:** docs/adr/0049-net-sales-forecast-observations-and-horizon.md §3–4;
canonical B07 в docs/plan/sales-planning-daily-implementation.md.

## Global Constraints

- `expectedGross=eligibleOpen×pGross(stage)`, `expectedOpenReturns=expectedGross×F(H)`,
  `retainedOpen=expectedGross−expectedOpenReturns`, H=60. Это будущий хвост
  от будущей доставки, не currentDelivered×q(age). Не выдумывать дату будущей
  доставки и не применять возраст открытого заказа к return curve.
- G в gross rate уже D+R. Known R текущего delivered учтён B04/будущим B09;
  в этой операции известный R не подаётся и повторно не вычитается.
- Return curve берётся через B03 `cumulativeAt(ObservedReturnCurve::HORIZON)`:
  полнота/минимум100units30postings исходной return population обязательны.
  Не использовать старый projectedBuyout или D-rate; не смешивать numerator
  и denominator разных rows, SKU или company/account.
- Одна явно выбранная пара: gross и return marketplaceSku одинаковы
  (оба targetSKU либо оба null для своего account), одинаковые company/account,
  реальный RR snapshot, полный context fingerprint/readAt с microseconds.
  B07 не выполняет fallback и не добавляет query; B08 выберет пару целиком.
- CompanyId первым, accountId следующим; все present scoped inputs проверить
  на foreign scope до metadata и zero shortcuts. Foreign scope — exception.
  Null/empty/whitespace/single_statement target snapshot — unavailable.
  Present readAt/context должны совпадать с target, в том числе для trusted0.
- Target evidence — прежний trusted B09 contract, не новый SQL producer.
  Только BEFORE_HANDOVER или AFTER_HANDOVER; nullable/unknown/incomplete/
  contradictory quantities не считаются0. Для положительного target тип используемой gross rate должен отвечать stage.
- Trusted target quantity0 → все exact quantities0 без pGross/F и training.
  Positive target с пригодным genuine pGross0 тоже математически даёт gross0,
  returns0/retained0 без F(H); при этом pGross0 сохраняется, F остаётсяnull,
  неизвестная ставка не превращается0. Foreign/present-context mismatch не
  обходятся этим shortcut. Для positive gross нужен пригодный return F(H).
- Все quantity0≤retained≤gross≤eligible; retained+futureOpenReturns=gross.
  Private BigRational, public numerator/denominator decimalstrings,
  ни float, ни int products/раннего округления/общего framework дробей.
- B02–B06, schema/SQL/writers/конфигурация/Facade/API/UI/очереди/зависимости
  не меняются. B08 fallback, B09 aggregate/targets, B11 money, B12+ API/UI,
  B16/B17 реальная predictive quality/numeric rollout остаются отдельно.

### Exact Domain contract

`final readonly class OpenRetainedQuantities`:

- `public static function fromProbabilities(int $eligibleOpenQuantity,
  GrossProbability $gross, ?ReturnProbability $cumulativeH): self`;
- `public static function zero(): self`;
- public readonly `int $eligibleOpenQuantity` и шесть `string` properties:
  `expectedGrossNumerator`, `expectedGrossDenominator`,
  `expectedOpenReturnsNumerator`, `expectedOpenReturnsDenominator`,
  `retainedOpenNumerator`, `retainedOpenDenominator`;
- private constructor принимает eligible и три `BigRational`; сторонний тип
  не становится public property/parameter/return. Дроби выводятся exact decimal
  integer strings компонентов, denominator > 0. Нормализация допустима,
  округление quantity отсутствует;
- отрицательный eligible отвергается `InvalidArgumentException` до вычислений;
  F=null допустим только если eligible=0 или gross.numerator=0. Тогда все
  quantities равны 0/1, eligible сохраняется. Для положительного gross при
  F=null — `InvalidArgumentException`, а не подстановка F=0;
- вычисления только BigRational: gross=eligible×pGross,
  returns=gross×F(H), retained=gross−returns; int products/float отсутствуют;
- constructor проверяет 0≤returns, 0≤retained≤gross≤eligible и
  retained+returns=gross. `zero()` задаёт eligible=0 и все quantities=0/1.

Ни currentD/currentR, ни возраст открытого заказа, ни дата будущей доставки
не входят в contract. `cumulativeH` — именно F(60) от будущей доставки.

### Exact Application и DTO contracts

`final readonly class ApplyOpenRetentionAction` получает через constructor
private dependencies `BuildPreHandoverGrossRateAction $preRates`,
`BuildPostHandoverGrossRateAction $postRates`, `BuildReturnCurveAction $curves`.

`public function apply(string $companyId, string $accountId,
OpenTargetEvidence $target,
ScopedPreHandoverGrossRate|ScopedPostHandoverGrossRate|null $grossRate,
?ScopedReturnCurve $returnCurve): OpenRetentionAssessment`.

Метод применяет ровно предъявленную оценку. Переданные DTO сохраняются в
результате как исходная диагностика; account/SKU fallback отсутствует. Для
readiness строится только temporary one-row `NetTrainingBatch` из выбранного
source и его исходного context/readAt; существующий stage builder заново
проверяет всю gross row (p95, полноту, budget, counts и sample), а B03 builder —
return row. Это чистое повторное применение существующих правил, без query,
выбора другого SKU или других данных. Приватные helpers остаются в одном action.

Cached `probability`/`curve` не являются достаточным proof. Для положительной
цели нужны непустой source, правильный source.marketplaceSku и успешный rebuild.
Gross cached numerator/denominator должны точно совпадать с rebuilt исходными
компонентами; curve должна совпадать с rebuilt sample/points целиком.
Противоречие отвергается, а не исправляется молча. Расчёт использует проверенные
rebuilt coefficients; original scoped DTO остаются доступны для diagnostics.
Предъявленный unavailableReason или отсутствующий cached coefficient не
превращается в available только потому, что raw source удалось перестроить.

`final readonly class OpenRetentionAssessment` имеет private constructor и
public properties:

- `?OpenRetainedQuantities $quantities`;
- `?GrossProbability $grossProbability`;
- `?ReturnProbability $cumulativeReturnProbability`;
- `?string $basis` (`no_eligible_open`, `sku`, `account` либо null);
- `ScopedPreHandoverGrossRate|ScopedPostHandoverGrossRate|null $grossRate`;
- `?ScopedReturnCurve $returnCurve`;
- `?string $unavailableReason`.

Фабрики:

- `available(OpenRetainedQuantities $quantities,
  ?GrossProbability $grossProbability,
  ?ReturnProbability $cumulativeReturnProbability, string $basis,
  ScopedPreHandoverGrossRate|ScopedPostHandoverGrossRate|null $grossRate,
  ?ScopedReturnCurve $returnCurve): self`;
- `unavailable(string $reason,
  ScopedPreHandoverGrossRate|ScopedPostHandoverGrossRate|null $grossRate = null,
  ?ScopedReturnCurve $returnCurve = null): self`.

Available всегда имеет quantities и null reason. `no_eligible_open` требует
eligible=0, обе probability=null и Domain zero. `sku/account` требуют eligible>0,
grossProbability и grossRate; basis соответствует non-null/null selected SKU.
При pGross>0 обязательны F(H) и returnCurve; при pGross=0 F(H)=null допустим,
оригинальный nullable return input сохраняется, fake F=0 не создаётся.
Фабрика перепроверяет согласованность exact quantities с probabilities через
Domain factory и совместимость переданной выбранной пары; противоречивые
сочетания отвергает `InvalidArgumentException`. Unavailable требует непустой
trim(reason), обнуляет quantities/probabilities/basis до null, сохраняет inputs.
Полная source readiness и target association принадлежат action.

### Детерминированный порядок readiness

1. **Scope до любых metadata/reasons/zero.** Target context.assertScope;
   у каждого присутствующего gross/return DTO явно company/account и затем
   context?.assertScope. Foreign company/account в любом present input —
   `InvalidArgumentException`, даже если target incomplete/0 или DTO unavailable.
2. **Target RR и present context.** Target snapshot null/empty/whitespace/
   `single_statement` → `target_snapshot_missing`. ReadAt каждого present DTO
   сравнивается с target как `format('U.u')`; каждый present context целиком по
   fingerprint, в том числе snapshot, epoch id/version/start/end/release,
   readAt с microseconds и model/coverage policy. Различие →
   `training_context_mismatch`, в том числе для target0 и genuine gross0.
   Выявлено расхождение точности: существующий fingerprint использует для
   epoch.start/end `format('c')` и теряет их microseconds. B07 дополнительно
   сравнивает epoch.start/end через `format('U.u')`, локально, без правки B02–B06;
   readAt уже сравнивается отдельно с полной точностью.
   Отсутствующий context не объявляется совпавшим; нужность проверяется ниже.
3. **Цель.** Target.unavailableReason сохраняется; иначе inputComplete=false →
   `target_input_incomplete`; stage вне BEFORE_HANDOVER/AFTER_HANDOVER →
   `unsupported_target_stage`; eligible=null → `unknown_eligible_open_quantity`.
   Только после этого trusted eligible=0 → Domain.zero, basis=no_eligible_open,
   probabilities=null. Missing training/source/sample/stage type/pair не мешают
   такому доказанному математическому нулю; present scope/context уже проверены.
4. **Positive target: stage и selected identity.** Missing gross →
   `gross_probability_unavailable`; неверный тип gross для stage →
   `gross_stage_mismatch`. Gross selected SKU — targetSKU либо null;
   present return selected SKU обязан совпасть с gross selected SKU. Другая SKU,
   SKU/account смешение или source SKU, отличный от собственного scoped SKU,
   → `selected_scope_mismatch`. Эти present identity проверки предшествуют
   genuine gross0; account означает свой account, а не чужую компанию.
5. **Gross readiness.** Present gross context обязателен →
   `training_context_missing`; usable snapshot уже следует из target fingerprint.
   Scoped unavailableReason передаётся как причина отказа. Source отсутствует →
   `gross_training_row_missing`; missing cached probability →
   `gross_probability_unavailable`. Rebuild единственной выбранной source row
   existing pre/post builder; его reason передаётся без потери. Cached probability
   отличается от rebuilt → `invalid_gross_probability`. Никакой numerator или
   denominator из другой row не участвует.
6. **Genuine gross0.** После всех предыдущих проверок rebuilt pGross.numerator=0
   даёт три exact quantity0, eligible остаётся положительным, basis=sku/account,
   pGross сохраняется, F(H)=null. Missing return input/context/profile/sample
   не мешает: умножаемый на него gross уже доказанно0. Присутствующий foreign,
   mismatched context или selected pair до этого шага уже отказал.
7. **Positive gross: return readiness.** Missing input →
   `return_curve_unavailable`; missing context → `training_context_missing`;
   scoped reason сохраняется; missing source → `return_training_row_missing`;
   source budgetFailure → `input_budget_exceeded`; source.excludedGroups<0 →
   `invalid_return_training_counts`; missing cached curve →
   `return_training_profile_missing`. Rebuild выбранной source через B03;
   missing/неполная/невалидная population даёт его исходный reason.
   Budget и знак excludedGroups проверяет именно B07 boundary: существующий
   BuildReturnCurveAction этих двух проверок не выполняет, его код не меняется.
   Несовпадение cached curve с rebuilt → `invalid_return_curve`.
8. **F(H) и composition.** Только `rebuiltCurve.cumulativeAt(
   ObservedReturnCurve::HORIZON)`, не `remainingAt(age)` и не требования target
   H+L/currentD risk-set. B03 проверяет исходные ≥100 units и ≥30 postings;
   unavailable reason (например `insufficient_sample`) сохраняется. При пригодном
   F(H) вызывается Domain; available basis=sku/account, оба exact source
   coefficients и исходные DTO сохраняются. Выбора другой оценки нет.

Новые причины B07: `gross_stage_mismatch`, `selected_scope_mismatch`,
`invalid_gross_probability`, `return_curve_unavailable`, `invalid_return_curve`,
`invalid_return_training_counts`.
Остальные перечисленные причины используют существующий vocabulary B03–B06;
raw source reasons (`source_history_unavailable`, `maturity_unavailable`,
`insufficient_sample` и прочие) передаются буквально. Nullable/unknown не
превращаются в numeric0. Ветви reason детерминированы указанным порядком.
