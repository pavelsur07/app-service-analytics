## Уточнение recovery до правки helper

Внутренняя проверка перед CLI выявила окно между commit bootstrap и записью
state. План исправления: Builder::build заранее создаёт известные UUID всех
двух компаний, кабинетов, actor и membership; atomic state с этими UUID
записывается до первой ORM persistence. Затем все bootstrap сущности
сохраняются в одной транзакции. Прерывание до commit оставляет state и
полностью отсутствующий bootstrap; cleanup удаляет только этот state без
DELETE по дочерним таблицам. Полностью присутствующий bootstrap очищается
только после проверки каждой company/account/user; частичное присутствие
или несовпадение markers отвергается. SQL Query и измеренные формулы не менять.

Проверка: исходный guard tests, scoped PHPStan/CS, фактический SIGKILL seed
при заблокированной bootstrap INSERT (без test hooks), rollback всех его
UUID и успешный cleanup отсутствующего scope; затем штатный seed/cleanup
и отказ при несовпадении существующих markers. Новых deps и broad cleanup нет.

### Recovery результат
