## Fix round1 — принятая хронология delivered capacity

5A clean; root принял одно замечание5B. Actual writer RED08:

сохранён в `.superpowers/sdd/B10/freeze-before-fix-1.json`.

До production-правки выбран ограниченный set-wise prefix proof только для
новоразблокированных candidate order/SKU: несколько известных origins и
полный ClientReturn всей delivered capacity. Один положительный event
на delivered source и отрицательный event на каждый положительный accepted
ClientReturn delta объединяются UNION ALL. SUM window по группе и времени
проверяет неотрицательную доступную ёмкость на каждом шаге. В одинаковое
время R идёт раньше delivery: совпадение секунды не доказывает порядок.
Нулевой поздний delta не удаляет ранний overrun; cumulative7→20 после
соответствующих deliveries остаётся доказанным нулём.

Known origin берётся из существующего proof. Если рядом с двумя известными
origins есть initial-delivered источник без origin, его первый accepted
delivered captured_at используется только как lower-bound capacity witness
в prefix stream: это не delivery origin модели/возраст. Existing initial-only
allR вне новых candidates не меняется. Не используются MAX-latest-only
heuristic, физическое R-разнесение или неизвестная ёмкость до её witness.
Preceding history/coverage/quantity/unknown/overflow и прежний strict
MIN(origin) delta guard сохраняются. Invalid chronology→contradictory_quantity.

Изменяется SQL shape: добавляются candidate/event/prefix/group proof CTEs
и один groupjoin в reason CASE. Event bound≤50k delivered source keys
+400k accepted revisions (фактически по кандидатам), одна сортировка
O(nlogn), без correlated return×sales. Новых SELECT roundtrips, индексов,
схемы, caps или planner flags нет. До freeze обязательны actual scoped
EXPLAIN ANALYZE BUFFERS с rows/loops/candidates/events на нескольких
размерах и свежий normal B09 representative stage/combined/EXPLAIN через
существующий guarded helper, own synthetic scope cleanup. Старые timings
и hashes не считаются итоговым performance proof. После scoped GREEN —
backend gates и полный make test-int TEST_WORKERS=2.

Actual EXPLAIN10 после первого GREEN показал rows40/200/400 и
WindowAgg loops1, но planner выбрал nested-loop scans новых candidate/
source joins. Это выявленный resource-risk, а не пройденное доказательство
no-quadratic. До итоговых измерений новые joins заменяются UNION ALL
источников с group reduction, candidate tagging оконным BOOL_OR и bounded
prefix. Capacity verdict объединяется UNION ALL с прежним origin-delta
verdict, затем BOOL_AND по группе: новый join в output CASE не нужен.
Сохраняются cardinality bounds, добавляется не более20k candidate markers;
нет per-return scans и новых planner flags. Лог10 остаётся историческим
нефинальным measurement.
