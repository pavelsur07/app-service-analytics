### Результат и границы

Проверить настоящий путь Builders → writers → SQL producer → единый readonly
reader → точный итог. Полные T1 и R дают доказанный ноль; частичные возвраты,
несколько отправлений и неизвестные исходы не умножают количества.
Существующие тесты single-allR, golden70−5+25, scope, snapshot и бюджетов
сохраняются и повторно не дублируются.

Основной файл: `api/tests/Integration/Ingestion/ReadNetForecastActionTest.php`.
При реальном RED допустима минимальная правка
`api/src/Ingestion/Infrastructure/Query/NetForecast/NetTargetProofSql.php`
или reason-CASE в `NetTargetQuery.php` и точечная regression в

production-файлах сначала обосновать evidence в этом плане. Не добавлять

### Простые задачи

1. **Сверить существующее покрытие и написать сценарии до исправлений.**
   Использовать существующие fixture/read helpers, реальные accepted revisions,
   observation clocks и receipts. Для allT1 построить несколько отменённых
   частей до передачи в доставку с однозначным каноническим исходом;
   без обучения ожидать exact0/1, без открытых/доставленных остатков.
   Missing/failed source coverage по-прежнему даёт null.

2. **Проверить полный возврат нескольких отправлений.**
   Разные доказанные delivery origins одного order/SKU, возврат всей
   подтверждённой доставленной ёмкости после доставок: currentD0 и net0/1
   без модели. Ранее initial-delivered single-allR уже покрыт.
   Возможный дефект — guard считает origins>1 неоднозначностью даже при
   отсутствии остатка D; гипотезу сперва подтвердить настоящим RED.
   Если исправление нужно, ограничить его доказанным terminalzero:
   сохранить chain/alias/quantity/chronology/current-coverage proofs,
   запретить невозможный или избыточный R. Положительный остаток D с
   неоднозначным возрастом по-прежнему недоступен; возраст не выдумывать.
   Сохранить существующий запрет R до доказанного первого origin и
   запрет превышения общей доставленной ёмкости.

3. **Проверить частичный R по всему заказу до фильтра дня/SKU.**
   Existing training fixture:35 delivered×40,20 ClientReturn×5;
   F60=100/1400=1/14, для fresh age до10дней F(age)=0, q=1/14.
   Два одинаково датированных delivered parts7+13 и R6 дают currentD14,
   futureR1 и net13. Проверить точные суммы part/group/day/SKU/batch,
   реальные source IDs и единственный return trace.
   Отдельно расширить уже существующий allocation-case через полный reader:
   EARLY3 + CURRENT4, R5, тот же origin, предыдущий business day у EARLY;
   при запросе текущего дня остаётся currentD2, futureR1/7, net13/7.
   Sibling SKU не получает чужой R; известный R не вычитать повторно.

4. **Проверить unknown вместе с известным исходом.**
   При полной source closure построить valid fresh delivered и отдельный
   положительный unknown outcome. Unknown part и полные ancestors дают null
   с причиной, не zero/partial total. Сохранить доступные диагностические
   группы там, где текущий контракт их возвращает; глобальный source-proof
   refusal не заменять частичным расчётом. Выбрать конкретную неизвестность
   из существующих поддержанных fixture-путей, не из подмены trusted DTO.

5. **Проверить и передать на независимое ревью.**
   Записать фактические RED/GREEN, принятые решения и ограничения.
   Scoped integration, затем `make lint stan deptrac structure-check
   test-unit` и полный `make test-int TEST_WORKERS=2` на имеющихся test БД.
   Набор тестов не сокращать, БД/тома не пересоздавать. Если production fix
   меняет только terminalzero CASE без новых популяций/joins/ordering,
   сохранить budget tests и зафиксировать отсутствие изменения SQL shape;
   изменение структуры запроса требует отдельного плана измерения до кода.
   Root выполняет два actual Codex CLI в отдельных сессиях, разбор,
   CI итогового SHA, PR/merge/deploy и проверку результата. Claude пропущен
   по действующему явному решению владельца.
