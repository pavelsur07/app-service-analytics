3. Добавить типизированный lifecycle outcome/result с id/version/status; два небольших Application action по существующим шаблонам. В каждом target загружается company-scoped, expected version проверяется отдельно до status guard. Actor берётся только из доверенного вызова/UI RequestAttributes.
4. Discard draft: одна transaction, Domain transition, IdentityFacade audit точного status before/after и причины/ссылки на источник при auto-discard; saveMetadata ORM optimistic flush. Никакого удаления lines/claims; первый draft без approved source поддерживается, revision discard не трогает source/header/claims.
5. Cancel active approved: единая внешняя repository.transactional; source.cancel + source audit + saveMetadata ПЕРВЫМИ; после source flush читать openDraft(company,lineage), при наличии discard draft + draft audit + ORM saveMetadata; releaseClaims всех дней source в той же transaction. При optimistic race source или draft вся transaction откатывается вместе с ранее сохранёнными header/audit/claims. Lock order совпадает с A08 (approved source первым, draft вторым). Никаких новых production injection hooks/parallel writer.
6. Существующих port методов transactional/openDraft/releaseClaims/saveMetadata достаточно; новые чтения не добавлять без необходимости. Статусы только ORM. Нормативную disposition ADR-047 дождаться у родителя; не объявлять literal ADR-040 override из факта кода.
7. POST cancel/discard с {version}: переиспользовать строгий version JSON parser; actor из RequestAttributes. Typed Response + Nelmio: success id/version/status, 404 чужой/отсутствующий plan, 409 stale version/status, 422 malformed/nonpositive/noninteger version; запрос body actor игнорируется. Не делать непрошеный рефакторинг approve/revision controllers.
8. RED/GREEN integration реальных flows: cancel с открытой revision сохраняет строки/approval metadata, закрывает оба header, освобождает все claims и пишет status/actor audit; новый независимый plan занимает освобождённые дни, старая copy/approval закрыты. Discard первого draft сохраняет rows/history и запрещает правки; discard revision оставляет approved source и claims и позволяет новую revision с max historical+1.

Проверить tenant/stale/status no-write outcomes и optimistic races: source version bump после ORM load; sibling draft version bump после его загрузки, через test-only repository proxy/decorator, делегирующий реальной реализации.
