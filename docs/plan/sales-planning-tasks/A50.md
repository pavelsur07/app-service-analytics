# A50 — выпуск этапа A

## Подробный план до исполнения

Постоянное разрешение на PR/merge/deploy/миграцию — CLAUDE «Merge, миграции
и доступ к серверу»; дополнительного согласования по этапам не требуется.
Предусловия остаются обязательными. Claude пропущен по отдельному указанию
владельца только для текущей фичи; все кодовые пакеты проходят два Codex CLI.

1. После локальных проверок и итогового review A49 завершить интеграцию
   актуального master в ветку задачи; оставить чужой securety_chek.md вне
   коммитов. Сверить review coverage по конечным blob, одну итоговую миграцию
   Version20261027120000, fresh db-rebuild receipt и рабочий down. Опубликовать
   ветку и PR с актуальным поведением, проверками и ограничениями этапа A.
2. Дождаться зелёного обязательного CI точного PR HEAD, проверить отсутствие
   unresolved blocking review/конфликтов. Только затем merge через PR с
   ожидаемым SHA; master локально не checkout, force push запрещён.
3. Отслеживать сборку образа/выкладку точного master commit. Миграционный
   gate должен проверять новый образ. При отказе из-за единственной ожидаемой
   миграции сверить новый IMAGE и состояние через conwix-prod, не печатая env,
   credentials и данные кабинетов. Gate не обходить и не ослаблять.
4. Отдельной осознанной командой применить свою разрешённую миграцию новым
   образом через production compose. Перед этим убедиться в ожидаемом pending
   version и выполнении предусловий; чужие неожиданные pending не применять
   молча. Проверить migrations up-to-date и схему; повторить штатную выкладку.
5. Проверить точную APP_VERSION публичного seller ping и внутреннего admin,
   готовность контейнеров и ошибки после выкладки. Read-only smoke нового
   контракта/ORM/schema с явным company scope; не писать synthetic факты в prod,
   не вызывать реальные marketplace API и не выводить финансовые значения.
   Если пригодного плана нет, записать ограничение числовой prod сверки.
6. Сохранить PR/CI/deploy URLs, commit/tag, applied migration и smoke results
   в этом документе и общем журнале. Этап A не объявляет готовым future-net
   forecast: поля остаются null с причиной до принятия и реализации B.
