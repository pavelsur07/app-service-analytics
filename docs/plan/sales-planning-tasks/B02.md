# B02 — история источников и пригодная обучающая выборка

> Исполнение: уже порученная автономная работа; подшаги выполняются последовательно.
> Перед исполнением плана применить `superpowers:executing-plans`.

**Цель:** сохранить принятые состояния sales/returns и результаты загрузок,
затем выбирать только доказуемо пригодные наблюдения модели ADR-049.

freshness guards или часы фактов. История начинается перспективно; численный
прогноз остаётся закрыт до отдельного допуска B16/B17.

**Стек:** PHP8.4, Symfony7.4, Doctrine DBAL/ORM, PostgreSQL16, существующий
Symfony Clock/PSR Clock; новых пакетов, транспортов и межмодульных связей нет.

## Инварианты

- Legacy `fact_revision=0`; новый capture INSERT получает1; каждый принятый
  UPDATE делает `fact_revision = current.fact_revision + 1` под row lock UPSERT.
- PK истории: `(company_id, marketplace_account_id, source_row_id, fact_revision)`.
  UUIDv7 создаёт PHP до SQL; это идентификатор записи, не источник ordinal.
- Только `RETURNING` принятого mutable состояния заполняет историю. Поля
  `EXCLUDED` могут отличаться после COALESCE/fill-only и для истории не годятся.
- Noop/stale/rejected update не увеличивает counter и не пишет историю.
  Ошибка вставки истории откатывает mutable изменение в том же statement.
  Ledger не использует `ON CONFLICT DO NOTHING`: повтор revision — нарушение,
  которое нельзя скрыть. `MAX(history.revision)+1` запрещён.
- `fact_revision=1` не доказывает первичное наблюдение source. Нужны
  proven first state, явный `LivePolling` origin, `first_loaded_at >= epoch`,
  непрерывная capture version и полный horizon/coverage.
- `H=60`, `L=7`, `Wreturn=90`, `Wgross=90`; training min100 штук/30 postings,
  risk-set min30/10. Gross и return имеют отдельные populations и зрелость.
  До пригодных данных результат недоступен с причиной; legacy/current facts
  не превращаются в исторический dataset.
- Company первым параметром чтения и первым столбцом scoped индексов.
  SQL/date pushdown, обязательные лимиты/keyset; без запросов на каждую строку,
  `SELECT *`, `COUNT(*)` растущих фактов и ослабления baseline/проверок.
- Все runtime-команды только в контейнерах/существующих Makefile-целях.

не сохраняет текст failure. Одинаковый диапазон/at/status дедуплицируется
`ON CONFLICT DO NOTHING`, но current mark исполняется при каждом вызове.

### Proven initial state — явное происхождение, без догадок

PostgreSQL16 не поддерживает `RETURNING OLD/NEW` из PostgreSQL18.
Root разрешил typed origin и явную дополнительную metadata-колонку mutable facts
`capture_initial boolean DEFAULT false`: только INSERT с явно переданным
`FactCaptureOrigin::LivePolling` пишет true, принятый UPDATE и любой
backfill/unknown/replay INSERT false; RETURNING передаёт её в
`capture_is_initial` ledger. Это признак последней принятой операции, не
обещание marketplace onset. Legacy0→1 получает false, backfill INSERT1 false.
История сохраняется при любом origin, false не подавляет accepted capture.
`xmax=0` и один counter без такого provenance не используются.

Сейчас `IngestionBackfill::stamps()` задаёт только транспорт `async_backfill`;
поля messages содержат даты/scope и не различают происхождение. Handler не
получает TransportNamesStamp. Сравнение raw received_at, message date, времени
normalize либо текущего clock не восстанавливает эту информацию.

Поэтому origin передаётся явно:

- Scheduler polling/rescan: `LivePolling`; это фактический текущий HTTP poll,
  но само по себе ещё не доказывает предыдущий статус/delivered transition.
- Первичная история ConnectOzonAccountAction и BackfillOzonReturnsCommand:
  `HistoricalBackfill`; backfillLinks выбирает его без дополнительного аргумента.
- ImportOzonFixtureCommand и ImportOzonReturnsFixtureCommand: `RawReplay`.
- Старое queued message, ручной SyncOzonAccountCommand или любой caller,
  не объявивший origin: `Unknown`, до осознанного уточнения его контракта.

Messages получают optional constructor origin с default Unknown и accessor
`captureOrigin(): FactCaptureOrigin`, возвращающий
`$this->origin ?? FactCaptureOrigin::Unknown`.
Так native unserialize старого сообщения с отсутствующим promoted property
не обращается к неинициализированному свойству. Это проверяется тестом реально
сериализованного старого payload, не только новым constructor default.
Repository `upsertAll` получает optional
`FactCaptureOrigin $origin = FactCaptureOrigin::Unknown`.
Происхождение — технический input, не меняет бизнес-guard принятия строки.
Поле `capture_is_initial` плюс epoch и непрерывность — часть evidence,
не автоматический допуск return onset или training.
Enum применяется только внутри Ingestion. Внешние модули не импортируют его:
они продолжают существующий Facade, который задаёт provenance своего сообщения
внутри Ingestion. Новых разрешений Deptrac не требуется. Queue routing/stamps
не меняются и не используются как эвристика origin.

## Review focus

1. Legacy update0→1 и новый исторический backfill INSERT1 не должны получать onset.
2. Fill-only repair с тем же hash обязан сохранить итоговые связи в истории,
   не меняя first_loaded_at/last_updated_at и monetary/status snapshot.
3. Concurrent insert/update и ABA при одном raw/одной секунде должны иметь
   разные последовательные accepted revisions без lost update.
4. Ошибка ledger/поздней страницы не должна оставлять mutable состояние
   без истории либо историю откатившегося состояния.
5. Successful empty load и failed→success должны оставлять receipts;
   совпавший receipt не должен подавлять актуальное обновление day mark.
