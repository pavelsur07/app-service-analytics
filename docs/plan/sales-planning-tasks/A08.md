# A08 — новая версия утверждённого плана

## Подробный план до выполнения

1. Добавить Domain factory реального draft из approved: новый UUIDv7,
   та же линия/период/кабинет/валюта, следующий номер, новый creator/time,
   nullable metric наследуется, поля утверждения пустые. Builder использует
   этот путь для подготовки наследованных состояний, без Reflection/обхода конструктора.
2. Добавить атомарный сценарий создания/reuse draft с сериализацией через
   approved header, optimistic version и точной пакетной копией дневных строк.
3. Добавить POST revisions и расширить approve: старую approved версию
   перевести в superseded/flush прежде новой approved, заменить claims в одной транзакции.
4. Проверить реальные legacy approved → draft → явный metric → replacement,
   точность копии, новые UUID, исходную цель, rollback конфликтов и tenant isolation.
5. Сгенерировать API-типы; пройти проверки и два отдельных Codex CLI прохода.

Domain factory вынесена вперёд как небольшой фундамент для A05: тест наследованной
метрики обязан создавать реальную Entity через Builder, а не Reflection.
Наличие factory само по себе не означает готовность API/копирования строк/сериализации.

ADR-047 включается в тот же независимый пакет A08. Принятие — после разбора
обоих Codex CLI проходов, старый Accepted ADR не редактируется.
