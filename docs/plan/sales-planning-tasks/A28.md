Готовность: vendor DAMA SkipDatabaseRollback прочитан; глобальный rollback не
ослабляется. До snapshot кода: обычный вызов открывает DBAL transaction и
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ, READ ONLY первым statement.
Все header/baseline/plan/Ingestion SELECT идут на общей connection. finally
commit/rollback освобождают режим. Если внешняя транзакция есть, принимается
только actual SHOW isolation repeatable read/serializable И read_only=on;
READ COMMITTED или read-write отвергается explicit unsupported snapshot (409).
Никакого fallback cross-module SQL или ложного RR, никакого upgrade чужого scope.

Тесты только новые классы #[SkipDatabaseRollback], свои синтетические fixtures
и finally company-scoped cleanup. Реальный concurrent connection update между
SELECT доказывает неподвижный snapshot; SHOW isolation/read_only внутри,
попытка WRITE запрещена PostgreSQL, после вызова connection восстановлен;
внешний низкий isolation не изменяется. Action-путь trust: чужая company404,
account только header, baseline только BaselineQuery, browser не управляет scope.
