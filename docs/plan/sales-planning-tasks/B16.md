и immutable DB publication anchor B15 переиспользуются; live источники

**Стек:** PHP 8.4, Symfony 7.4, Doctrine DBAL/PostgreSQL, установленный
Brick Math, существующие S3 adapter и контейнерные Make targets.

**Приёмка:** [отдельный чек-лист B16](B16-acceptance.md).

Цель — воспроизводимый private dataset и решение о качестве на реально
сохранённых прогнозах и дозревших labels. Синтетические тесты доказывают
арифметику/изоляцию, но не прогнозную точность. Публичный численный gate
остаётся закрыт до реальных B16, B17, B18 и полного HTTP пути <3 секунд.

## 1. Граница и существующий код

- `api/src/Ingestion/Application/Buyout/BacktestBuyoutForecastAction.php`
  делает до62 asOf пересчётов и текущий final query; `BuyoutBacktest` сравнивает
  bps дневных когорт, baseline=`knownBuyoutRateBps`, округляет через division/
  round. Он не читает sealed input/truth и не годится для B16. Не менять его
  методику и не использовать его исторические результаты как net evidence.
- `ReadNetForecastAction::__invoke(companyId, accountId, NetTargetRequest,
  ?NetForecastSeriesRequest): NetForecastBatch` читает текущие sources/training
  под `NetTrainingSnapshot`; pin делается до readAt. Это согласованность одного
  чтения, не durable history. B16 этот сценарий не вызывает.
- `NetForecastGroup` уже различает order/SKU/parts; part содержит sourceRowId,
  компоненты delivered/openPre/openPost, trace, quantities/money/reasons.
  `NetTargetSourceTrace` содержит first/latest IDs и witness IDs/digest;
  это не полный B15 manifest и само по себе не доказывает видимый training set.
- `NetForecastQuantities` хранит точные numerator/denominator strings,
  display=`HalfUp(3)`; `NetForecastRevenue` использует установленный Brick Math,
  суммирование до `HalfUp` в minor units, currency validation, signed prices
  и bounded arithmetic. Display decimal не использовать как исходный прогноз.
- В выпущенном `IngestionFacade` есть `findForwardCapture`,
  `prepareForwardCapture`, `publishForwardCapture`; SalesPlanning orchestration
  — `CaptureSalesPlanForwardAction`, CLI — `app:sales-planning:capture-forward`.
  В Ingestion `app:ingestion:forward-artifact` имеет modes `replay|truth`.
- Существуют `NetForwardArtifactReader::read(companyId, accountId, kind,
  requestId, ?expectedHash, ?requestHash, ?deadline)` и `segments(...)`,
  `PrepareNetForecastCaptureAction`, `PublishNetForecastCaptureAction`,
  `ReplayNetForecastArtifactAction`, `CaptureNetForecastTruthAction`.
  Reader имеет DBAL connection для publication anchor; требование «нет live DB»
  относится к source/training queries в scoring, а не к чтению scoped anchor.
- `NetForwardArtifactKind` имеет только Input/Truth; Entity и БД — `kind(5)`.
  Reader трактует любой non-input как truth и требует input parent. Добавить

## 2. Предрегистрация до просмотра результатов

До первого holdout capture seal `net_quality_protocol_v1`. Root заполняет
реальные company/account, допустимые SKU/scope и временные границы; пустые
поля запрещают запуск. Protocol включает:

1. UUIDv7 protocolId, version/hash, code commit, schema/codec/model версии,
   `observed_retention_h60_v1`, H=60×86400s, L=7×86400s, Wreturn/Wgross=90d,
   training/risk thresholds ADR-049, B15 epoch ID/start, baseline версии;
   валюты, plan/baseline scope и proof, никаких секретов/полных raw payload.
2. Отдельные calibration и final holdout order-cohort интервалы; все SKU и
   postings одного order попадают только в одну часть. Интервалы фиксируются
   до outcomes и не перекрываются. Holdout начинается после freeze; captures
   с actualReadAt до freeze не получают статус prospective holdout.
3. Один явно заданный account, <=50 SKU, <=184 order-calendar days; capture
   schedule раз в день 12:00 `Europe/Moscow`, origin window из полных ISO
   календарных недель Monday00:00–Monday00:00, минимум2 недели. Capture slot
   не подменяет actual winning readAt; пропуск/поздний retry учитывается явно.
4. Наблюдаемые timestamps — UTC; order age — разница local MSK calendar dates
   businessDate и actualReadAt. Delivery age — floor((actualReadAt−observed
   deliveryOrigin)/86400), не MSK date diff. Недели origins — ISO week-year
   от actualReadAt в Europe/Moscow, не неделя заказа или seal/report date.
5. Фиксированные возрастные группы: order1–2/3–5/6–9/10–15, delivery0–6/7–29/
   30–59. Все семь обязательны для полного v1 допуска; не убирать слабую группу
   после просмотра. Вне диапазонов — diagnostic only, не дополняют минимум.
6. Selection/weights/thresholds из §3–6, точные budgets из §7, целевой набор
   валют. Менять их после просмотра labels можно лишь в новой версии с новым
   prospective holdout; старый результат сохраняется как unsuccessful/insufficient.

Фиксировать training membership actual B15 ledger, а не PIT по timestamp.
Полный order из final holdout не используется для подбора гиперпараметров,
baseline formula, scope/thresholds или калибровки. Оценка v1 — prospective
rolling-origin: зафиксированный алгоритм может обучаться на действительно
видимых на T прошлых исходах. Уже известный gross исход той же доставки
допустим в gross training при выполнении ADR-049; это не ещё неизвестный
retained target. Его пересечение с holdout identities показывается отдельным
count. Запретить любую future-retention label/последующую correction из truth
в training/input этого прогноза. Mature return training с origins до T−67d
и ещё открытый target-tail не должны пересекаться; соответствующий overlap
даёт `holdout_target_leakage`, а не тихое исключение строки. Между origins
одного order нет независимости: dedup/weights ниже обязательны. Если старый
holdout order позже дозрел и по правилам вошёл в rolling training другого
прогноза, фиксировать это в overlap diagnostic, не считать полученную оценку
строгой cross-order holdout. Настройка после просмотра его ошибок запрещена.
Строгая отдельная train/holdout population с исключением всех holdout orders
потребовала бы другой capture/training версии; B16 не пересчитывает её задним
числом и не заявляет такую независимость текущему rolling-origin дизайну.

Frozen capture inventory содержит все запланированные slots/request IDs,
успехи, отказы и missing slots. После capture до выбора labels seal selection
artifact с точными input IDs/hashes и выбранными observations. Отсутствующий
slot не восстанавливать удобным более поздним numeric capture. Не брать
первые100 удачных прогнозов. Все попавшие в заданную population кейсы входят
в inventory; превышение cap делает запуск unavailable целиком.

Truth выбирается из отдельного sealed inventory explicit refs с заранее
заданным cutoff и coverage/capture policy B15. Для input берётся самая ранняя
**полностью ready** версия по `(truthReadAtUtc, truthId)` в этом inventory;
готовность проверяется по всем компонентам, не по значению label. При отсутствии
ready сохраняется earliest pending и reason. После выбора dataset закрепляет
точные IDs/hashes. Никаких `latest`, выбора лучшей ошибки или догрузки из DB.
Пропуск обязательного truth capture/inventory receipt — incomplete provenance,
не доказательство, что переданный artifact был самым ранним. Повторный cutoff
даёт новую evaluation version; опубликованный score не переписывается.

## 3. Единица наблюдения, повторения и знаменатели

Case key = `(companyId, accountId, canonical orderNumber, marketplaceSku)`.
Отсутствующий/неоднозначный order identity — ineligible с причиной, sourceRowId
не создаёт фиктивный новый order. Все parts/postings данного order/SKU
агрегируются; одна штука не входит в case дважды. Разные SKU одного order
допустимы как ADR order/SKU cases, но остаются одним leakage cluster; отчёт
дополнительно показывает distinctOrders.

Selection использует только metadata до outcomes/чисел прогноза:

- На case в каждой order-age группе выбрать самое раннее actualReadAt,
  затем lexical canonical inputArtifactId. Нельзя заменить null прогноз
  более поздним numeric в той же группе. Case target — все компоненты на T;
  пока любой компонент pending, агрегат не scoreable.
- Для delivery-age групп единица — delivered часть case на T, с известными
  origin и remaining D(T). На case/group выбрать earliest capture; в нём
  суммировать все delivered components именно этой группы. Mixed origins
  распределяются по собственным delivery ages; неизвестный origin не
  приписывается соседнему. Open часть здесь не входит и оценивается в order
  группах. Baselines и truth получают идентичную component mask.
- Для overall quantity взять один order observation на case — earliest
  среди четырёх order groups, tie как выше, **до** проверки null/ready.
  Этот отдельный overall sample требует >=100 distinct comparable cases.
  Десять captures одного case не считаются десятью cases. Overall нельзя
  получить складыванием order/delivery групп: семьи перекрываются.
- В каждой группе один case имеет вес1; overall тоже weight1/case. Суммы
  по количеству и currency — отдельные diagnostics. Не усреднять проценты
  групп и не считать их независимыми повторениями. P-values/доверительные
  интервалы в v1 не обещаются; если позже нужны — cluster по whole order,
  новая заранее зарегистрированная методика.

На каждой группе и overall публикуются flow counts: scheduled slots,
successful inputs, unique candidates, deduplicated observations, eligible
identities, ready truth, pending/censored/ineligible, method numeric/null,
simple numeric/null, legacy numeric/null, primary comparable и legacy
comparable. Eligibility не зависит от ошибки. Для known candidate row
`methodNullShare = methodNullCount / candidateCount` (включая pending truth);
дополнительно `methodNullAmongReady / readyCount`. Аналогично bases, money,
pending/censored shares. Если denominator0 — null + `empty_population`,
никогда 0%. Missing input slots считаются отдельно, их неизвестное число
кейсов не выдумывается. Причины multi-valued, отдельные reason counts могут
перекрываться; total null count считает observation ровно один раз.

Primary paired set = выбранные observations с verified fully ready truth,
полным одинаковым scope и numeric method+simple baseline. Одинаковый rowId
список и вес используются обеими сторонами MAE/bias/WAPE. Method-only metrics
можно вывести diagnostic, но ими нельзя заменить primary. Legacy сравнивается
на своём пересечении с method/truth; рядом обязательны его counts и отдельные
method metrics именно на этом пересечении, а также тройное пересечение.
Legacy null не уменьшает primary set. Запрещено сравнить MAE по разным population.

## 4. Базы на T и truth

**Принятая база:** выпущенный B15 сохраняет описанную ниже
`simple_mature_return_linear_h60_v1`. Сверить implementation/version и
replay на final code preflight; пересчёт иной базы после truth недопустим.

Root design preflight 2026-10-29 принял описанную ниже версию
`simple_mature_return_linear_h60_v1` и дополнительные availability/money
пороги §6 до получения реальных outcomes. Это выбор методики, **не** sealed
protocol: реальные company/account, окна, валюты и refs ещё не закреплены.

`simple_mature_return_linear_h60_v1`: по тому же доказанному mature training
scope на T сохранить `r = returnedWithinH / grossDelivered`, exact fraction,
0<=r<=1. SKU/account fallback и минимумы100 units/30 postings берутся из
ADR-049 и фиксируются; нет знаменателя/пригодного scope — baseline null.
Собственная baseline sample — только observed deliveries origins в
`[T−67d−90d,T−67d)`, с полным H+L и видимыми в том же RR receipts/revisions.
Denominator — сумма исходных gross delivered units этой population, numerator —
admissible положительные ClientReturn increments строго в `[origin,origin+60d)`.
Source membership/fields/counts/исключения baseline сохраняются отдельно, даже
если совпадают с моделью; endpoint rate не берётся из будущего truth или
legacy net D. Monotonicity/source coverage/allocation exclusions ADR-049 §3
действуют полностью, R>G не clipping. Сначала SKU с100 units/30 postings,
затем только свой account с теми же минимумами; обе attempts и причины
сохраняются. Baseline не использует эмпирические возрастные risk-set/bin
вероятности: это заранее заявленное отличие простой модели; её eligibility
не копируется из numeric/null результата основной модели.
Для delivered D(T) с возрастом a<H простой additional-return fraction
`r*(H-a)/H`, baseline retained=`D(T)*(1-r*(H-a)/H)`; при a>=H baseline=D(T).
Для open quantity использовать сохранённую на T gross вероятность соответствующей
pre/post части, умноженную на `(1-r)`; terminal part=0. Суммировать retained D
и retained open, unknown часть делает полный baseline null. KnownR уже исключён
из D(T), второй раз его не вычитать. Это простая линейная модель оставшегося
tail, не эмпирическая age curve; общая gross оценка делает сравнение retention
осмысленным. Сохранить fractions/selected scope/version и независимый baseline
replay. Если root выбирает другую простую формулу, изменить protocol/version
до captures; B16 не угадывает её из агрегата.
Доставленная часть age>=H и terminal0 не требуют r; при нулевом remaining D
не требовать неиспользуемую ставку. При положительном open обязательна пригодная
gross вероятность этой части, при положительном D с a<H — известный origin
и пригодный r. Отсутствие source/coverage, unknown outcome/origin, insufficient
sample, invalid allocation дают собственный baseline null reason; отсутствие
price/currency делает только baseline money null. Все required parts готовы —
baseline quantity доступен, даже если основная модель null по своему risk-set.

Старый `projectedBuyout` сохраняется B15 с его исходной методикой, units/scope
и null reasons. Не умножать его на retention и не объявлять gross.
Если legacy доступен только на дневном scope и не имеет доказанной order/SKU
декомпозиции, per-case legacy=`scope_not_comparable`. Разрешена дополнительная
таблица на точно совпадающем sealed day/SKU scope с готовностью всех компонентов;
она не заменяет100 order/SKU cases и primary baseline gate.
Совпадение scope ещё не означает совпадение estimand: старый buyout может
предсказывать иной outcome/horizon. В таком случае помечать
`target_not_comparable`; сохранённое число показывать только как legacy
diagnostic с описанием методики, не как равноценную ошибку retained-H target.
Не превращать legacy в gross/net догадкой. Legacy paired score допустим лишь
при явно доказанном совпадении target, units, component mask и truth horizon;
иначе comparison unavailable является честным результатом обязательной проверки.

Truth только из B15: D(T) минус новые admissible returns remaining units
в открытом delivery H; knownR и после-H события не вычитать повторно.
Open→delivery d готово после d+67d и coverage; terminal без delivery —
terminalObservation+7d; unknown/open остаётся censored. Пример T→deliveryT+20
→returnT+75 готов не раньшеT+87, не T+67. Mature D(T) сохраняется rolling base.
Timestamp, p95, now или epoch age не являются доказательством label readiness.
Later corrections помечают artifact invalidated отдельным событием/report,
не меняют старые bytes; до разрешения invalidation выпуск закрыт.

## 5. Точные метрики и деньги

Все значения имеют canonical decimal integer strings. Quantity rational
`{numerator,denominator}` с denominator>0, reduced; прогноз/truth>=0 и в
границах соответствующих ordered/remaining units. Ошибка `e=forecast−truth`
signed. Ноль=`0/1`; `-0`, leading zeros, exponent, NaN/float запрещены.
Использовать уже установленный `Brick\Math\BigRational/BigInteger` внутри
evaluator; наружу readonly DTO строк. Cap16384 digits для каждого
операнда и промежуточного exact результата, preflight multiplication size;
overflow => evaluation unavailable, не truncate/floating fallback.

При весах w=1 и N>0: `MAE=Σ|e|/N`, `signedBias=Σe/N`,
`absoluteBias=|Σe/N|`, `WAPE=Σ|e|/Σtruth` при Σtruth>0.
Отдельно хранить exact sums/counts, numerator/denominator всех метрик.
Нулевые индивидуальные truth допустимы и остаются в MAE/bias/WAPE numerator;
если весь denominator0, WAPE=null/`zero_truth_denominator`, group insufficient
для release. Negative quantity truth/prediction — invariant violation, не
абсолютное значение/обрезка до нуля. Comparisons выполняются exact arithmetic;
display decimals=6 digits HalfUp, WAPE процентов — отдельное display, не gate.

Money на том же paired subset, но только с полным price/currency T для каждого
компонента обеих моделей и truth. Сохранить exact `Σquantity*unitMinorPriceT`,
затем один HalfUp на scope для published-minor comparison, как B11.
Не складывать предварительно округлённые части. Отчёт по **каждой валюте**:
N, money-null reasons/share, exact и rounded minor MAE, signed/absolute bias,
WAPE-money=`Σ|moneyError|/Σ|truthMoney|` при ненулевом denominator.
Никаких FX и общей денежной MAE разных валют. Zero price валиден, но вся
нулевая money population — insufficient для денежной проверки. Signed price
разрешён текущим `NetForecastRevenue`: сохранить знак, negative money не
является negative quantity; абсолютный denominator исключает взаимопогашение.
HalfUp отрицательных половин также проверяется; не использовать signed sum
как money WAPE denominator. Errors могут быть любого знака.
Later price correction — отдельная diagnostic; не менять price T.
MoneyUnavailable не портит quantity sample, но блокирует утверждение качества
денег там, где валюте не хватает данных. Нет полного money — нет ложного итога.

## 6. Предъявляемое решение и заранее фиксированные пороги

Report хранит `protocolRef`, `selectionRef`, dataset/report schema+hash,
input/truth refs, code commit, exact counts/метрики/разницы с bases, reasons,
`mechanicalValidation`, `predictiveValidation`, `performanceValidation`,
`b17Status`, `b18Status`, `numericRolloutAllowed=false`.
Evaluator сам feature flag не пишет. CLI возвращает только report ID/hash,
status и сводные counts; dataset/order identifiers не печатаются в публичный лог.

Порог v1 до first numeric release:

- Ни одного нарушения tenant/account/as_of/source provenance, quantity bounds,
  money scope/rounding/currency. Повреждённый hash/version/missing evidence —
  INVALID_EVIDENCE, а не исключённая удачная строка. Source-null по правилам
  не является violation, но остаётся missingness.
- >=100 distinct **primary comparable overall** order/SKU cases, >=30 distinct
  primary comparable cases в каждой из семи обязательных групп; actualReadAt
  overall и каждой группы охватывают >=2 ISO weeks. Ни одна группа не пустая,
  не вся нулевая по truth и не искусственно достроенная fixtures.
- Overall и каждая обязательная группа: method MAE<=simple MAE,
  method WAPE<=simple WAPE, method absoluteBias<=simple absoluteBias.
  Tolerance=0, equality проходит. Signed bias публикуется даже при равенстве
  absolute bias. Baseline metric0 требует method metric0.
- Принятый в design preflight порог availability: на ready identities
  method-null-share<=simple-null-share; требование фиксируется заранее,
  обе доли на одном denominator. Абсолютный maximum null% ADR не задаёт;
  его не изобретать после outcomes. Всегда показывать candidate null share
  и pending share, даже при успешном paired score.
- Принятый в design preflight money gate: каждая заранее заявленная currency имеет >=30
  comparable distinct overall cases и ненулевой Σ|truthMoney|; rounded-minor
  MAE и absoluteBias метода не хуже simple, tolerance0. Exact money metrics
  публикуются рядом. Зафиксировать это уточнение в sealed protocol до
  регистрации captures; per-age currency slices с N<30 показываются insufficient,
  не заявляется доказанное качество каждого такого slice. Если scope требует
  такой claim, заранее добавить его в mandatory strata, не после результатов.
- Legacy comparison обязателен как таблица с availability/scope diagnostics;
  legacy лучше/хуже не заменяет simple baseline gate. Нет совместимого legacy
  scope — ограничение отражено явно, не fabricated comparison.

Decision priority: `INVALID_EVIDENCE` при integrity/invariant/protocol failure;
иначе `INSUFFICIENT_DATA` при недоборе/нулевом denominator/pending required
strata; иначе `QUALITY_FAILED` при любом threshold failure; иначе
`QUALITY_PASSED`. Если недостаточность и известная регрессия одновременно,
основной insufficient плюс все failed metrics. `QUALITY_PASSED` означает
измерение на данном sealed holdout, не разрешение rollout.
Mechanical tests=`passed|failed|not_run` с проверяемыми ссылками; их passed
не меняет predictive state. До реальных B17+CI/reviews, B18 release evidence
и full-HTTP<3s performance gate итог rollout всегда BLOCKED. <3s не следует
из 5s SQL timeout, private CLI runtime или быстрого unit test.

## 7. Приватное хранение и контракты реализации

Использовать реально принятые B15 artifact port, bounded reader/publisher
и DB publication anchor; конкретные signatures сверить после B15. B15 prefix:
`conwix/monolith/net-forecast/v1/companies/{company}/accounts/{account}/`.
Узкое необходимое расширение закрытого artifact kind enum: `quality-protocol`,
`quality-inventory`, `quality-selection`, `quality-dataset`, `quality-report`;
request UUID identities и attempt-scoped content-hashed roots/chunks. Это **будущее изменение B15 port
key/codec allowlist**, не использование `MarketplaceRawDocument` и не новый
bucket. Root проверяет IAM/privacy/retention и inventory/deletion
ownership для этих kinds до кода. Если B15 не допускает extension, согласовать
его там, не писать другой raw adapter или новую DB молча.

Protocol и selection seal отдельно; scored dataset сначала, report последним
с datasetRef. Unique first-winner DB publication после закрытия RR, hash полных envelope bytes,
canonical payload hash и chunk hashes, version/scope verification, first-wins
retry semantics B15. Same requestId с другим requestHash отвергается;
при race читать и полностью проверять winner. Never overwrite/copy latest.
Provider игнорирует conditional PUT: fixed-root S3 CAS не использовать.
Root timestamp один не доказывает pre-registration: protocol должен быть
связан с capture request/manifest при capture, не добавлен после outcomes.
`quality-inventory` имеет закрытый subtype `capture|truth`, фиксированный
cutoff, schedule/slot receipts и bounded refs; оба inventory seal до selection/
scoring соответственно. `NetQualityCaptureInventory`/`NetQualityTruthInventory`
ниже — verified readonly DTO reader с собственным inventoryRef, а не непроверенный
список caller. Scoped reader не делает discover/list; caller передаёт exact refs.

Новые Application contracts (ещё не существуют). Пути ниже —
`api/src/Ingestion/Application/NetForecast/`; новые DTO readonly.
`NetQualityArtifactRef` содержит `NetForwardArtifactKind $kind`, canonical
UUIDv7 `string $requestId`, `string $sha256`; scope всегда отдельными первыми
параметрами, не внешним S3 URI. `NetQualitySelectionRequest` содержит
`requestId`, protocol ref и verified capture-inventory ref.

```php
FreezeNetQualityProtocolAction::__invoke(
    string $companyId, string $accountId, NetQualityProtocol $protocol
): NetQualityArtifactRef;
SealNetQualityInventoryAction::__invoke(
    string $companyId, string $accountId, NetQualityInventoryRequest $request
): NetQualityArtifactRef; // subtype + protocolRef + slots + bounded explicit refs
SelectNetQualityObservationsAction::__invoke(
    string $companyId, string $accountId, NetQualitySelectionRequest $request
): NetQualityArtifactRef;
EvaluateNetForecastQualityAction::__invoke(
    string $companyId, string $accountId, NetQualityArtifactRef $selection,
    NetQualityTruthInventory $truths, string $evaluationId

NetQualityDecision::decide(NetQualityDecisionInput $input): NetQualityDecisionResult;
```

Все DTO readonly, строгие schemas; ref содержит kind, UUID, expected sha256,
не внешний object key. Protocol/inventory carries request identity и hash;
Company/account — первые параметры всех scoped операций. Reader сверяет caller
scope и embedded scope каждого input/truth/link, не доверяет ref без проверки.
Калькулятор чистый: нет Connection, Clock, source queries или IngestionFacade
live reads. Evaluator CLI находится в Ingestion; Facade меняется только для
привязки существующего plan-linked capture к protocol, не ради scoring.

Строгий DAG родительских ссылок: protocol→null; inventory→protocol;
selection→capture inventory; dataset→selection; report→dataset. Дополнительные
protocol/truth-inventory refs лежат в typed metadata и проверяются evaluator.
Legacy input→null и truth→input остаются совместимыми; optional protocol ref
input проверяется отдельно. Глубина verified traversal<=6, циклы/неверный kind
и любые лишние связи отвергаются. Запланированные input IDs протокола — слоты,
не обязательные к чтению artifacts при freeze. Это устраняет текущий reader
`else => truth` без ослабления старой parent-проверки.

Операционные bounds v1, требующие resource preflight: <=200 input refs и <=200 truth refs
на evaluation; одна inventory page<=200 descriptors; <=20000 candidate
case-observations; один JSON root/chunk<=1MiB, <=128 output chunks/128MiB;
sum bytes прочитанных input/truth objects<=512MiB, deadline120s, PHP peak96MiB,
additional allocation48MiB, private spool<=130MiB. Один artifact всё ещё
подчиняется более строгим B15 caps. Decode depth/row/string/digit caps проверять
до роста graph; stream по bounded chunks, spool target rows, не materialize
все input training ledgers. Проверять размер перед decode, oversized row =>
unavailable. Нет successful truncated sample. Повторение одного ref кешировать
только bounded; budgets считаются по реально прочитанным bytes, requests и rows.
Непроверенный timing/RSS не обещать. Для большего holdout заранее seal bounded
shard refs и deterministic combination; в v1 такого режима нет, превышение
cap требует нового protocol до наблюдения outcomes. Доказать совместимость caps
профилем до основного capture; перечисленные значения не являются замерами.

B15 `findBatch` принимает<=50 identities:200 refs обрабатываются bounded
пачками по50, не расширением repository limit. `NetForwardArtifactReader::read`
уже проверяет chunks, а следующий `segments()` читает их повторно; truth-read
также проверяет input parent. Общий `NetQualityBudget` передаётся опциональным
последним аргументом reader `read`/`segments` и через recursive parent calls;
все реальные root/chunk GET и повторные проверки расходуют512MiB. Обход
проверки hash ради лимита запрещён. Guard проверяет declared size до GET/decode,
actual bytes после чтения и deadline на каждом шаге. Без budget прежний B15
контракт остаётся тем же. B15 capture/replay/spool сохраняют собственный30s
лимит; общий120s evaluator его не увеличивает. Созданный output spool живёт
не более30s и общего остатка; timeout не создаёт новый успешный partial report.

В будущем CLI `app:ingestion:net-forecast-quality` mode — positional argument;
для всех modes обязательны options `--company`, `--account`, `--operation`
(UUIDv7). Scope не читается из ambient tenant/session. Остальные options:

| Mode | Обязательный ввод | Выход |
|---|---|---|
| `freeze` | `--request-file`, `--request-hash`: bounded private protocol JSON с protocolId=operation | protocolRef/hash |
| `seal-inventory` | Те же options: inventory JSON, requestId=operation, subtype, protocolRef, cutoff, slots/refs | inventoryRef/hash |
| `select` | Те же options: selection request JSON, requestId=operation, protocol и capture-inventory refs/hashes | selectionRef/hash |
| `evaluate` | `--selection`, `--selection-hash`, `--truth-inventory`, `--truth-inventory-hash`; operation=evaluationId | datasetRef/reportRef/hashes, decision/counts |

`--request-file` — явный приватный локальный файл<=1MiB, не URL; проверить
size/hash до decode. Объём refs/slots остаётся в caps §7. Option combinations
неверного mode и неполные пары отклоняются до artifact IO. Нет `--as-of`,
`--latest`, arbitrary S3 key, all-tenants mode или inline order data в argv.
CLI exit0 означает полный verified dataset/report даже при QUALITY_FAILED
или INSUFFICIENT_DATA; automation читает decision, не выводит quality из exit0.

ложного complete report; INVALID_EVIDENCE сохраняется, если integrity-safe
diagnostic report удалось опубликовать, но никогда не считается quality PASS.

## 9. Проверки, ревью и календарная готовность

Команды ниже **ещё не выполнялись**. После implementation GO только существующие
контейнерные цели: `make lint stan deptrac structure-check`,
`make test-unit test-int test-func TEST_WORKERS=2`, `make api-types-check`.
Targeted PHPUnit через существующий container runner; не выдумывать Make filter.
Из-за widening kind обязателен `make db-rebuild-check TEST_WORKERS=2`;
root сначала подтверждает LOCAL dev/test compose hosts/volumes и освобождает
exclusive DEV. Внешние production/test DSN в этом прогоне недопустимы.
API/TS не меняются; если реально изменятся — источник контракта,
`make api-doc-export api-types`, `make api-types-check`, нужные front gates.
Обязательный CI всего branch diff, включая audit/e2e; `make ci-local` —
существующий сводный runner, без бессмысленного повторения уже зелёного CI.

По [исключению владельца](../sales-planning-review-rule.md) только два
настоящих независимых Codex CLI: root собирает точный package через
`make review-prepare` с verified base/high risk/ADR0049 и relevant context,
затем `make review-codex REVIEW_PACKAGE=<exact>` и
`make review-defects REVIEW_PACKAGE=<exact>`. `make review` вызывает Claude,
его здесь не использовать. [Формат пакета](../../review-package-template.md):
не включать чужие изменения/секреты; сохранить полные ответы/metadata/hash,
triage и число уникальных принятых замечаний каждого дополнительного прохода,
после исправлений повторить затронутые проверки/ревью. Неполный review/CI
блокирует merge. Design-only Markdown не является code review и не заменяет B17.
