# A16 — полнота загрузки заказов по дням

## План до кода

1. Добавить Query и readonly DTO покрытия окна до 184 календарных дней:
   одна точка на каждый день, общая для SKU одного кабинета.
2. Полным считать только день с явным completed_at без failed_at для
   OzonPostingFboList. Отсутствие фактов при таком признаке означает настоящий
   ноль заказов. Наличие raw без успешной отметки или failed-прогон означает
   partial; отсутствие любых свидетельств — missing. Raw сохраняется до
   завершения страниц и сам по себе полного дня не доказывает.
3. Не изменять существующие отчёты/DayLoadSql: их legacy fallback по raw
   остаётся прежним. Новый performance-контракт использует консервативную
   полноту. Это полнота заказов, а не хвоста возвратов или статусов.
4. Сначала integration RED: complete-zero/missing/partial, отказ после
   прежнего успеха и восстановление успешным повтором, company/account/type
   и границы дат, верхняя граница 184, невалидное окно.
5. Реализовать SQL generate_series + tenant-scoped join по естественным
   ключам и EXISTS raw, без чтения/подсчёта фактов и запросов в цикле.
   Query возвращает QueryBuilder, каждый список имеет явный лимит <=184.
6. Выполнить integration и backend-гейты; два Codex CLI прохода отдельно.
   Подключение в публичный Facade и запрет полного итога при partial — A20.

Файлы: SalesCohortCoverageQuery/Row, SalesCohortCoverageQueryTest, этот план.
Схема, API и зависимости модулей не меняются. Нового источника площадки нет.
