# A20 — публичный пакет когорт

Готовность: прочитаны brief A20–A23, ADR-046/029/031/032/033, аудит источников,
текущие Metrics/Coverage Query и Facade. Основа A01–A19 существует; SalesPlanning,
схема и чужие изменения не затрагиваются. ADR-046 уже разрешает контракт.

Решение: readonly Request (SKU ≤50, календарные даты, accumulationFrom≤from≤to,
весь сезон ≤184 дней), enum day/week/month; Batch содержит ≤50 SKU, каждый ≤184
Point с clipped bucketFrom/To. Batch ordersCoverage описывает весь
accumulationFrom..to (готовая оценка последней cumulative-точки); пустой пакет
ordersCoverage=not_assessed и не запрашивает БД. Point имеет period/cumulative качество и nullable
Components. Только complete разрешает Components: иначе объект целиком NULL,
диагностические неполные суммы не публикуются. Это исключает неполные числа,
маскирующиеся под итог. При complete отсутствие SKU — настоящий ноль. Деньги
Money только при явной валюте; неизвестная цена/чужая валюта обнуляет доступность
денег, не количества. Возвратное покрытие всегда not_assessed; net forecast NULL
с причиной net_forecast_not_available. calculatedAt — текущий ClockInterface,
не обещание исторической реконструкции mutable inputs.

План: сначала интеграционный RED на форму/нули/качество; затем DTO и Facade,
SeriesQuery (Infrastructure принимает примитивы). SQL переиспользует Metrics и
Coverage Query как CTE, dense SKU×days, суммирует точные numeric-компоненты и
накапливает от accumulationFrom до clip видимого окна. Периодная зрелость —
возраст от последнего дня и доля всего агрегата, не AND зрелости дней. Мета
p95 отдельным постоянным запросом; запросов ≤2 независимо от SKU. Конечные
прогнозы вычисляются общими SQL helpers Buyout. PHP только отображает DTO.

Проверки: focused integration RED/GREEN, далее A21–23, make lint stan deptrac
structure-check и затронутые/full backend suites в контейнерах TEST_WORKERS=2.
Ревью и Git — у parent, без миграции/сбросов/зависимостей.
