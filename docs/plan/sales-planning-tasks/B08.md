## Global Constraints

- Whole estimate SKU→свой account→null. Для каждой попытки брать gross и
  return row одного выбранного SKU (оба targetSKU) либо оба account(null).
  Если SKU gross пригоден, но его return непригоден, account попытка заново
  выбирает оба account компонента. Не смешивать SKU gross с account F(H).
- Использовать действующие stage builders и B07 apply для каждой пары.
  До передачи pGross включаетT1, после исключаетT1 и требует dedicated
  conditional100units30postings. Return F60 и точные количества уже реализованы.
  Не вводить новые вероятности/priors/возрастные поправки/округление.
- Не более двух попыток, без чтений SQL/IO/loop queries и без cross-company,
  cross-account или глобального fallback. Сохранить каждый исходный scoped
  DTO, его sample/diagnostics/unavailability/budget и результат B07.
- CompanyId первым, accountId следующим. Target, batch, present batch context
  scope проверяются до metadata/zero. Foreign scope → exception.
- Настоящий непустой RR target snapshot; same batch.readAt/target.readAt U.u,
  и present full context fingerprint плюс epoch.start/end U.u (nullend отдельно).
  Existing fingerprint сам теряет epoch micros, поэтому нового кода он один
  не защищает; B07 local precision guard сохранить. B02–B07 не менять.
- Поддерживаются только BEFORE_HANDOVER/AFTER_HANDOVER. Unknown/null quantity,
  incomplete или contradictory target →unavailable с исходной причиной,
  без попыток обучения. Missing source не означает0.
- Trusted target quantity0 →B07 apply с null training, knownzero resolution,
  без attempts; present scope/context и target stage уже проверены.
  Missing batch context или unavailable training не мешают knownzero,
  но present batch context mismatch мешает. Positive target требует batch context.
- Genuine pGross0 с пригодной gross source может вернуть knownretained0/FHnull
  на SKU без account fallback и без ненужной return sample. Unknown gross
  не получает0; это правило уже исполняет B07, не копировать его math/readiness.
- Непригодная SKU/account оценка сохраняет обе причины; итог quantity=null,
  reason='open_retention_unavailable', никаких частичных numeric totals.
  Source/target failures и null coefficients не превращать в numeric0.
- B04 delivered-risk fallback уже действует и не меняется. Nonzero unknown
  и отсутствие компонента делают полный итог недоступным в B09; здесь один
  open component, без SQL/агрегации факта/producer/денег/API/UI/rollout.
- Никаких schema/SQL/writers/конфигурации/Facade/API/очередей/новых dependencies;
  source/coefficient правила B02–B07 остаются без изменений.

### Выбор конструкции и граница B07

Выбран прямой Application orchestrator с четырьмя concrete зависимостями.
Новые Domain formulas, wrappers над вероятностями, интерфейсы и SQL не нужны.
Независимый fallback каждого коэффициента отвергнут: он смешивает populations
и даёт неверный результат. Дублирование B07 formulas/readiness source отвергнуто:
только B07 решает пригодность пары, включая настоящий gross0 и cumulative F60.
Общие target/batch guards нового orchestrator обязательны до любой попытки.

`AssessOpenRetentionAction` — `final readonly class`, constructor:

```php
__construct(
    BuildPreHandoverGrossRateAction $preRates,
    BuildPostHandoverGrossRateAction $postRates,
    BuildReturnCurveAction $curves,
    ApplyOpenRetentionAction $apply,
)
assess(string $companyId, string $accountId,
    OpenTargetEvidence $target, NetTrainingBatch $batch): OpenRetentionResolution
```

После общей readiness максимум две итерации `[$target->marketplaceSku, null]`.
На каждой выбирается только builder своей стадии и return builder с тем же
`$sku`, исходным `$batch`, company/account. В B07 передаются именно оба
полученных scoped DTO. Все DTO сохраняются по object identity; source rows,
samples, excluded groups/days, reasons, budgetFailure и ageProfile не копируются,
не переписываются и не теряются. Даже при missing row scoped DTO остаётся
в assessment; `OpenRetentionAttempt.marketplaceSku` фиксирует chosen scope.
Обе исходные причины доступны через `assessment.grossRate.unavailableReason`
и `assessment.returnCurve.unavailableReason`, а итоговый reason B07 — через
`assessment.unavailableReason`; один не заменяет остальные.

Если B07 вернул quantities, сразу выбрать эту assessment. Иначе сохранить
неуспешную попытку и перейти к своему account(null), заново построив **оба**
компонента. После двух отказов selected=null, reason строго
`open_retention_unavailable`. Перенос SKU gross в account attempt запрещён.
Чужие SKU rows и другие scopes не являются кандидатами; глобального fallback нет.
Return builder на попытке вызывается для сохранения diagnostics; его unavailable
не запрещает B07 выбрать настоящий пригодный gross0. Дополнительная выборка
возвратов для доказательства нулевого результата не требуется, IO здесь нет.

### Порядок readiness target/batch и причины

Порядок фиксирован; metadata и zero не могут скрыть foreign scope:

1. `target.context.assertScope(companyId, accountId)`; сверить поля company/account
   самого batch; затем `batch.context?->assertScope(...)`. Любой foreign present
   scope бросает `InvalidArgumentException`, даже если target0, snapshot невалиден,
   target/batch содержит private unavailableReason или nested context foreign.
2. Target snapshot не null, не пуст/whitespace и не `single_statement`.
   Иначе resolution unavailable `target_snapshot_missing`, attempts=[].
3. `batch.readAt.format('U.u') === target.context.readAt.format('U.u')`.
   При present batch.context обязателен тот же полный fingerprint **и**
   `epoch.start.format('U.u')`, `epoch.end?->format('U.u')`; null end сравнивается
   отдельно с null, не с датой. Иначе `training_context_mismatch`, attempts=[].
   Fingerprint покрывает company/account/readAt, epoch id/version/start/end/release,
   snapshot, model/coverage policy, но существующий start/end через `format('c')`
   теряет micros. Поэтому новый private sameContext дополняет fingerprint точно
   как B07; B02–B07 и существующий fingerprint не меняются.
   Present context.readAt, не совпадающий с batch.readAt, также отсекается:
   сравнения с target одновременно доказывают согласованность всех трёх clocks.
4. Если target имеет unavailableReason, incomplete input, неподдержанную stage,
   null quantity либо quantity0 — вызвать B07 `apply(..., null, null)`.
   Это единый источник причины target и результата trusted0. Если unavailable,
   вернуть его точный reason без attempts; если available — knownZero factory.
   Не распознавать readiness по строке `gross_probability_unavailable`: такая
   строка может быть исходной причиной target и не разрешает обучение.
5. Только для полного, непротиворечивого, положительного target с одной из
   `before_handover`/`after_handover` нужен present batch.context. Его отсутствие
   даёт `training_context_missing`, attempts=[]. Batch.unavailableReason здесь
   не превращать в target reason: при present context обе attempts пройдут
   builders/B07 и сохранят исходный batch reason в scoped diagnostics.
6. Построить и применить целые пары. Остальные training readiness, p95,
   conditional sample, F60, budgets и counts остаются B03/B05/B06/B07.

Target reasons пункта 4, с приоритетом самого B07:
`target.unavailableReason` → `target_input_incomplete` →
`unsupported_target_stage` → `unknown_eligible_open_quantity`.
Невалидный stage0, contradictory0 и incomplete0 не knownZero.
Отрицательная quantity/пустые order/SKU/stage/reason уже запрещены конструктором
OpenTargetEvidence; producer reconciliation остаётся будущим B09.

Known target0 после scope/context/target guards допускает missing batch.context,
missing rows, training unavailable и budgets: B07 получает null/null и возвращает
`no_eligible_open`, eligible0 и точные нулевые quantities, probabilities=null.
Present context mismatch и readAt±1 microsecond мешают даже target0.
Genuine gross0 имеет positive eligible quantity, basis sku/account, валидный
gross source/probability0, F(H)=null и retained0; это обычная attempt, не knownZero.
Missing/unknown gross не получает probability0. Эту логику исполняет только B07.

Причины attempts не нормализуются: сохраняются, например,
`insufficient_sample`, `maturity_unavailable`, `gross_training_row_missing`,
`gross_training_row_ambiguous`, `return_training_row_missing`,
`return_training_row_ambiguous`, `return_training_profile_missing`,
`input_budget_exceeded`, `gross_training_counts_missing`, coverage/history reasons.
Итог с двумя отказами не содержит quantities/частичной numeric суммы; никаких
`?? 0`, default probability0 либо fallback на пустой source.

### Точные DTO/factories/invariants

`OpenRetentionAttempt` — `final readonly class`:

```php
__construct(public ?string $marketplaceSku,
    public OpenRetentionAssessment $assessment)
```

Nonnull chosen SKU непустой после trim. Каждый present grossRate/returnCurve
обязан иметь marketplaceSku строго равный chosen SKU; каждый present source row
имеет тот же SKU. При двух present scoped DTO company/account и readAt U.u
совпадают; каждый present nested context соответствует своему outer company/account
и readAt U.u; два present contexts совпадают по fingerprint+epoch micros.
Нарушение — `InvalidArgumentException`, включая unavailable assessment.
Отсутствие source/DTO само по себе не ошибка: chosen scope всё равно сохранён.
Available assessment с basis sku/account обязана соответствовать chosen SKU;
`no_eligible_open` не является training attempt и отвергается здесь.
Никакого IO, обучения, вычисления или исправления assessment.

`OpenRetentionResolution` — `final readonly class`, private constructor:

```php
public ?OpenRetentionAssessment $selected;
/** @var list<OpenRetentionAttempt> */ public array $attempts;
public ?string $unavailableReason;

static knownZero(OpenRetentionAssessment $selected): self;
/** @param list<OpenRetentionAttempt> $attempts */
static available(OpenRetentionAssessment $selected, array $attempts): self;
/** @param list<OpenRetentionAttempt> $attempts */
static unavailable(string $reason, array $attempts = []): self;
```

- `knownZero`: selected.quantities nonnull, selected.reason=null,
  basis=`no_eligible_open`, eligible quantity0, grossRate/returnCurve=null;
  attempts=[], resolution.reason=null. Exact zero/probabilities already
  guaranteed by existing B07/assessment/quantities factories; math не повторять.
- `available`: selected.quantities nonnull, selected.reason=null, basis sku/account;
  attempts list длины1..2. selected — **тот же объект**, что assessment последней
  попытки; все предыдущие assessment unavailable. reason=null.
- Любой непустой attempts list начинается с nonnull SKU; если есть вторая,
  её SKU=null. Больше двух, sparse array, повтор scope или account-first запрещены.
  Все элементы — OpenRetentionAttempt, checks без IO.
- `unavailable`: trim(reason) непуст; selected=null; 0..2 attempts с тем же
  порядком, каждая без quantities и с nonempty reason. При nonempty attempts
  reason строго `open_retention_unavailable`, и попыток ровно2: успешный SKU
  завершает цикл, отказ SKU обязан дойти до своего account. При attempts=[]
  сохраняется точная preflight причина.
- Противоречивый результат/пустая причина/подмена selected равным clone/лишняя
  попытка после успеха/нулевой training attempt — `InvalidArgumentException`.
  Ни одна factory не вычисляет вероятности или quantities.
