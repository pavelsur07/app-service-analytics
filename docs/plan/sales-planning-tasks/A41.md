# A41 — типы и хранение календаря

## План до кода

1. Ввести пять значений SalesPlanCalendarKind по ADR046: season_start,
   season_end, replenishment, sales, replenishment_stop. Границы сезона
   вычисляются из шапки и не принимаются как сохраняемые записи.
2. Ввести readonly PlannedCalendarEvent: nullable SKU, kind, календарные
   from/to. sales допускает интервал, включая один день; два подсорта —
   точки с равными датами. Нормализация date-only не зависит от часов/DST.
   Диапазон внутри сезона, SKU непустой <=64 при ненулевом scope.
3. Добавить ORM Entity SalesPlanCalendarEntry с UUIDv7 приложения,
   company/plan UUID, SKU, kind и датами; фабрика/изменение только draft.
   Копия в новую версию получает новый UUID. Builder обязателен.
4. Добавить company-first порт и ORM-репозиторий для человеческой записи:
   ограниченная коллекция до500 для изменения, persist/remove в общем EM,
   без самостоятельного commit за пределами внешней транзакции плана.
   Это агрегат команды, не Entity-список для отображения.
5. Схему добавить в единственную pending Version20261027120000, down
   удаляет таблицу. Индексы company/plan/date/id для keyset и company/plan/SKU
   для удаления scope. CHECK ограничивает сохраняемые виды тремя значениями.
6. TDD Domain: точки/интервалы, границы периода, вычисляемые виды нельзя
   сохранить, read-only approved, календарные даты, UUID/копия и принадлежность.
   Интеграционные записи после согласованного локального rebuild A43.
