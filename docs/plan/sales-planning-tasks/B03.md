# B03 — кривая возвратов и остаточный риск

## Подробный план до реализации

Статус: подготовка следующей задачи; код начинается после принятия B02 и
его окончательных typed inputs. ADR-049/B02-posting-risk уже задают H60,
границы, populations и минимальные выборки; здесь они не переоткрываются.

Результат — количественная return curve F(a) и остаточный риск q(a) для
0<=a<H. Никаких денежных расчётов, API/Facade или численного rollout в этой
задаче. SKU→account выбор целой оценки относится к B04, aged target H+L — B05.

1. Сверить final B02 inputs: G, monotone R_before_a на61boundary, exact initial
   distinct sample postings и atRiskPostingsLowerBound, source/context quality.
   Составить minimal Domain inputs/value objects без зависимости Domain от
   Infrastructure rows; mapping в Application допускается по существующим слоям.
2. Написать meaningful unit tests математики и readiness: q должен быть
   conditional remaining risk, а не общей долей возвратов; source unavailable,
   small sample/risk-set и inconsistent counts не дают коэффициент.
3. Реализовать exact fractions с integer numerator/denominator:

   `F(a)=R_a/G`, `F(H)=R_H/G`,

   `q(a)=(R_H-R_a)/(G-R_a)`.

   Последняя форма алгебраически эквивалентна ADR, избегает floating point
   и промежуточных произведений. Не округлять quantity перед будущими B05/B11.
   Не добавлять пакеты, общие абстракции вне модели или неиспользуемые DTO.
4. Проверить полные sample guards100units/30initial postings, risk-set
   30remaining units/10proved posting lower bound. Недостаточный proof не
   заменяется q0. Коэффициент сохраняет целые выбранные numerator/denominator
   и scope/context diagnostics для B04; источники fallback здесь не смешивать.
5. Прогнать affected unit tests и backend static gates; actual2Codex CLI,
   triage и повтор изменённых частей. B03 сам не проходит B16 quality gate.

## Поведенческие случаи

- G100, R_a20, R_H30: q=10/80, а не30/100; age0 даёт R_H/G.
- F не убывает по возрасту; q при достаточном risk-set не возрастает и в0..1.
- R_H=G допустим при положительном risk-set: q1; all returned/zero risk
  не допускает деления на0 или fake ready coefficient.
- G0, negative/nonmonotone R, R>G, missing boundary, inconsistent posting
  profile и unsupported H/context отклоняются явно, не clipping.
- Ровно пороговые100/30 и30/10 допускаются; меньше любого порога — unavailable.
- q0 возможен по достаточной пригодной выборке с R_H=R_a, а не при её отсутствии.
