## Общие ограничения

- H=60,61boundary points0..60; возраст для remaining risk0<=a<60.
- `F(a)=R_a/G`, `F(H)=R_H/G`, `q(a)=(R_H-R_a)/(G-R_a)`.
- Дробь сохраняет исходные целые числитель/знаменатель; float, округление,
  произведения для cross-multiplication и промежуточные decimal не нужны.
- Initial sample minimum100units/30distinct postings, age risk minimum
  30remaining units/10proved postings lower bound. Пороги включительные.
- Current B02 readonly RR batch имеет точный scope/context. Не смешивать
  числители/denominators разных rows, SKU/account или capture contexts.
- B04 выберет whole estimate SKU→account; fallback в B03 не реализуется.
- B05/B11 относятся к target-age/money; historical manifestB15 и real quality
  B16/B17 здесь не объявляются готовыми. API/численный rollout остаются закрыты.
- Пользователь требует подробный plan/readiness ДО кода и автономное исполнение.
  Root owns Git/globaldocs/ADR/реальные CLI review/CI/merge/prod, implementer
  owns только B03 source/tests/этот MD, без subagents и Git операций.

## Фокус проверки рисков

- Conditional q остаётся10/80 при G100/R_a20/R_H30, не превращается в30/100.
- Source unavailable/insufficient sample не подставляет0 или готовую оценку.
- Nonmonotone/missing/duplicate ages, negative/R>G, inconsistent at-risk
  quantities/posting bounds и unsupported risk method не дают коэффициент.
- G=R_a не делит на0; при достаточной выборке R_H=G даёт q1, R_H=R_a — q0.
- Mapping сохраняет company/account/row/context и отказывает чужому batch/scope;
  чтений БД и неявного account fallback не появляется.

  `__construct(int $numerator, int $denominator)`; только exact исходные
  компоненты, `0<=numerator<=denominator`, denominator>0, без сокращения.

  `__construct(int $age, int $returnedQuantity, int $atRiskQuantity,

  immutable mutually exclusive `?ReturnProbability $probability` и

- `api/src/Ingestion/Domain/ValueObject/ObservedReturnCurve.php`:
  `__construct(int $sampleQuantity, int $samplePostings, array $points)`;
  `cumulativeAt(int $age): ReturnProbabilityAssessment` (0..60),

  `observed_retention_h60_v1`. Points — list из61 ordered unique ages0..60;
  R0=0, R не убывает и <=G, riskQty=G-R, risk lower bound не возрастает,
  <=original distinct postings и riskQty; age0 bound=original postings.
  При positive quantity bound>=1; при zero quantity bound=0. G/P согласованы:
  0/0 либо G>=P>=1. Невозможные counts/profile — InvalidArgumentException.
  G0, G<100 либо P<30 дают `insufficient_sample`; remaining также требует
  riskQty>=30 и lowerBound>=10 (`insufficient_risk_set`). Ни один unavailable
  не содержит probability. Дроби F=R/G и q=(R60-Ra)/(G-Ra), без произведений.
- `api/src/Ingestion/Application/NetForecast/BuildReturnCurveAction.php`:
  `build(string $companyId, string $accountId, NetTrainingBatch $batch,
  ?string $marketplaceSku = null): ScopedReturnCurve`. null явно выбирает
  account row; SKU выбирает ровно эту row; отсутствующая/duplicate выбранная
  row недоступна. Fallback не вызывается. Batch/context scope mismatch
  отвергается InvalidArgumentException до отдачи foreign metadata; несовпадение
  readAt контекста/батча — `training_context_mismatch`.
- `api/src/Ingestion/Application/NetForecast/ScopedReturnCurve.php`:
  readonly company/account/readAt/context/marketplaceSku/source/curve/reason;
  source сохраняет всю выбранную B02 row (counts/exclusions/budget/method),
  context — fingerprint/capture epoch/snapshot/model/coverage; curve model
  фиксируется отдельно constant в Domain. Available curve может иметь
  insufficient sample assessment; adapter не выдаёт готовый коэффициент.
- `api/tests/Unit/Ingestion/ObservedReturnCurveTest.php` и
  `api/tests/Unit/Ingestion/BuildReturnCurveActionTest.php`: чистые fixtures
  без БД/сетевых doubles; mathematical invariants, inclusive thresholds,
