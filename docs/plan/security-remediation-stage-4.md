# Этап 4. Исправленная зависимость и обязательный аудит расширения

## Задача и результат

Удалить GHSA-mrhx-c7xc-m3w5 из установленного дерева extension и сделать
его аудит блокирующей частью `make audit`/CI, включая dev-зависимости.

## Изменения и границы

- `apps/extension/package-lock.json`: минимальное совместимое обновление
  транзитивной Zod до исправленной версии не ниже 4.6.6.
- `Makefile`: добавить `node-extension npm audit`, сохранить отказ при
  ошибке Composer или любого npm audit, не ослаблять пороги.
- Поведенческий shell-тест в `bin/`: подставной docker фиксирует вызовы и
  моделирует ненулевой код аудита расширения; проверяется выполнение
  настоящей Make-цели и её код возврата, не текст Makefile.
- Проверить шесть lock-файлов: root и ui имеют самостоятельные dev-деревья;
  их аудит включить через контейнеры с уже существующими монтированиями.
  Если ui требует установки собственного дерева — использовать существующий
  workspace/Make-процесс; новую runtime-зависимость не добавлять.
