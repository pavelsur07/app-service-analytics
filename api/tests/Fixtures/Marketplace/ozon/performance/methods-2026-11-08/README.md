# Ozon Performance: сравнение методов 08.11.2026

Кабинет: ООО «Вумджой», первый клиент. Основание — прямое поручение владельца
проверить методы чтения и цепочку генерации отчётов с предоставленными реквизитами.
Период снятия: 05:35:18–05:39:00 UTC. Выполнены 60 запросов данных/отчётов
(57 × 200, 1 × 400, 2 × 404), отдельно три получения access token.
После завершения каждой короткой сессии токен удалялся из памяти; реквизиты
и ответы авторизации не включены в набор. Управление рекламой не выполнялось.

## Устройство набора

`manifest.json` описывает каждый запрос: method/path с query, тело без секретов,
время фиксации ответа, HTTP-статус, длительность HTTP в секундах строкой,
тип содержимого, размер, SHA-256 тела и заголовков. `captured_at` — завершение
нашего запроса, не watermark данных Ozon. Адрес API: `https://api-performance.ozon.ru`.

Тела сохранены побайтово. JSON/CSV-расширение выбрано по Content-Type.
Заголовки сохранены отдельно в `<file>.headers`: только Date, Content-Type,
Content-Disposition и, при наличии, Retry-After/заголовки квот; CRLF преобразован
в LF. Cookies, авторизация и остальные заголовки не сохраняются в наборе.
manifest и README созданы локально, а не получены от Ozon.

| Группа файлов | Что проверено |
|---|---|
| `campaign-list` | Состав: 101 кампания, 10 работающих SKU/CPC и одна работающая SEARCH_PROMO |
| `product-{csv,json}-<day>` | Синхронная статистика CPC за явный день, 65 строк |
| `daily-json-<day>`, `daily-csv-*` | Синхронная дневная статистика; 10 строк за каждый исследованный день |
| `expense-json-<day>`, `expense-csv-*` | Сегодня пусто, вчера 10 строк; CSV сегодня содержит только заголовок |
| `sku-json-<day>` | Все 10 работающих CPC в одном запросе; 15 строк сегодня и 16 вчера |
| `media-*` | CSV/JSON доступны, в данном периоде данных нет |
| `report-{csv,json}-{submit,status-*,download}` | Полная цепочка отчёта по одной CPC-кампании за сегодня |
| `cpo-{products,orders}-*` | Полная цепочка отчётов CPO за вчера; оба скачанных результата без строк |
| `all-sku-{products,orders}-submit` | Оба запроса вернули 404 «Кампания не найдена» |
| `phrases-*` | Полная цепочка отчёта поисковых запросов за вчера, непустые данные |
| `attribution-submit` | 400 «Неподдерживаемый тип рекламной кампании» для выбранной CPC |
| `report-list*` | До и после успешной генерации — `items: [], total: "0"` |
| `product-json-{filter,zero,intraday,from-utc,date-precedence}` | Фильтр, явная нулевая строка архивной кампании, варианты периода |
| `*-repeat`, `series-*` | Повторные чтения и три серии SKU → product → daily → SKU |

CSV скачанного подробного отчёта содержит BOM, строку описания, строку заголовков,
строки данных и итоговую строку. Проверка одинаковой ширины всех строк файла
не подходит этому формату. Синхронный агрегированный CSV имеет обычный заголовок.

## Проверки автора и ограничения

- JSON разобраны; CSV декодированы через UTF-8-sig и CSV-reader с разделителем `;`.
- Побайтовое сравнение тел с исходниками, размеры curl и SHA-256 проверены.
- Ключи JSON, заголовки и текстовые значения просмотрены; секретов, ПДн покупателей
  и реквизитов контрагентов не обнаружено. Ответы CPO не содержали строк заказов.
- Денежные сравнения выполнены через Decimal, без float. Данные не изменялись.
- Запросы последовательные; это исследование API, не нагрузочный тест и не тесты приложения.
- В трёх сериях SKU до/после совпал, product совпал с daily, но три кампании имели
  разницу между этими группами. Причина различий и максимальная задержка не доказаны.
- Полнота всех методов Performance API не подтверждена из-за недоступной основной
  спецификации; отсутствие подходящих кампаний ограничивает проверку некоторых типов.
