# Ozon Performance: фикстуры для «Контроля затрат»

Сняты 08.11.2026, около 05:07 UTC (08:07 Europe/Moscow), из кабинета
ООО «Вумджой», первого клиента проекта. Основание: пользователь предоставил
временные реквизиты для проверки и после обсуждения ограничения живых запросов
прямо поручил сохранить ответы Ozon как фикстуры. Это разрешение относится
к текущему чтению и сохранению ответов, не к управлению рекламой.

Выполнены авторизация и шесть запросов данных. Запуск, остановка, изменение
бюджета, ставок и товаров не выполнялись. Асинхронные отчёты не заказывались.
Рабочий код коннектора и его allowlist не изменены.

|---|---|---|

Точные пути, параметры, тела запросов, время завершения запросов, размеры и
SHA-256 ответов находятся в `manifest.json`. Базовый адрес:
`https://api-performance.ozon.ru`. `captured_at` — время фиксации ответа,
а не watermark актуальности данных Ozon.

Ответы сохранены побайтово. Расширение агрегированной статистики исправлено
на `.csv` по полученному Content-Type; содержимое не преобразовывалось.
Файлы `.headers` содержат только полученный Content-Type без CRLF; остальные
заголовки исключены. Ответ авторизации и реквизиты не являются фикстурами.
`manifest.json` и этот README созданы локально, это не ответы Ozon.

## Наблюдения и границы выводов

- Access token выдан с `expires_in = 1800` (30 минут). Это срок access token,
  не срок предоставленного пользователем Client Secret. Токен не сохранён.
- Агрегированный метод вернул `text/csv; charset=utf-8`, а не JSON. Денежные
  значения используют десятичную запятую. Период ответа без параметров не
  подтверждён: использовать его как расход за сегодня пока нельзя.
- В `daily` поле `moneySpent` — строка с запятой, в `products/sku` поле
  `expense` — строка с точкой. Для выбранной кампании в обоих ответах за
  сегодня наблюдалась одинаковая сумма; один замер не доказывает синхронность.
- Пустой ответ `expense` при непустом `daily` показывает, почему нельзя
  считать пустую выдачу нулевым расходом. Причина различия не установлена.
- Наличие `dailyBudget` в списке кампаний не доказывает поддержку его записи
  или жёсткого суточного ограничения для текущего типа кампании.
- 101 запись общего списка и 65 строк CPC-статистики относятся к разным
  представлениям; полное покрытие всех типов кампаний агрегированным методом
  не доказано.
- Один последовательный прогон не измеряет SLA свежести, квоты, время остановки
  или устойчивость при нагрузке. Методы записи не проверялись.

## Проверки

- Все шесть ответов имеют HTTP 200; JSON разобран, CSV проверен на одинаковое
  число колонок, SHA-256 записаны в manifest.
- `cmp` подтвердил идентичность сохранённых тел первоначальным ответам.
- Проверены схемы полей, текстовые названия кампаний и CSV: токенов, cookies,
  реквизитов авторизации, данных покупателей/контрагентов не обнаружено.
  Сохранены реальные товарные и рекламные данные первого клиента согласно
  CLAUDE.md §9, без изменения денежных значений и идентификаторов.
- Это набор данных для будущих тестов. Runtime и существующие тесты не менялись;
  результаты запуска тестов не заявляются.

Независимое ревью набора выполняется отдельно по правилам проекта; наличие
фикстур само по себе не подтверждает готовность стратегии управления рекламой.
